# 自然语言入口与资料概览

本轮增加可选的 `ENABLE_NATURAL_ROUTING=1`，精简研究Compose默认开启，普通主应用默认关闭。统一聊天支持下列受限自然语言，不要求用户记住指令前缀；原 `/herb`、`/research`、`/pubmed` 指令保留，显式选择优先。

| 问法 | 处理方式 |
|---|---|
| 你能做什么／系统有什么功能／可以查什么 | 固定能力说明及当前工具开关 |
| 支持多少药材／收录了多少药材／药材有多少种 | 只读查询本地ETCM有效来源记录与独立药典索引，不把记录数说成去重药材种数 |
| 有哪些功效分类／有多少种功效 | 按指定ETCM数据版本统计原始分类字段值、缺失数和每个值的记录数；最多展示20种 |
| 黄芪有什么作用／黄芪的功效有哪些 | 药典字段查询，仍核验名称、炮制范围、字段和来源 |
| 用量呢／它的药用部位／出处呢 | 按本会话已保存的当前工具焦点解析；没有焦点时明确询问药名 |
| 黄芪／查一下黄芪 | 完全匹配已校验药典索引名称后选择条目，并询问要查哪个字段；不做别名猜测 |
| 在PubMed检索 Astragalus membranaceus[Title/Abstract] | 保留检索式，调用已开启的PubMed工具 |
| 找黄芪相关文献 | 识别文献方向，要求明确英文/拉丁名或检索式；不自动建立未核验的跨库映射 |
| 什么是归经 | 识别概念问题，说明当前尚无有来源的通用术语解释库；不把药材条目当作概念定义 |

## 页面组织

本轮页面先加入“功能说明、数据概览、药典查询、现代文献”轻量导航入口；点击填入可修改的示例，发送后展示结果。仍是统一聊天界面，尚未交付独立功能页签或多窗口。这样可以先验证自然语言与数据工具是否有用，再按真实操作量拆分工作区。

后续建议一个主界面下设置三个工作区：数据概览、药材与药典、现代文献。同一任务共享明确的对象选择；新建任务隔离会话。不要仅靠不同窗口推断上下文或授权，不同来源之间仍须对象核验。

## 统计口径与来源

ETCM按当前 `TCM_DATASET_VERSION`（未指定则最新导入版本）在同一SQLite只读事务统计，仅纳入 `state=valid`。原始功效分类字段有值记录、缺失记录、不同原始值数分开；不拆分逗号、不翻译、不合并同义类别，不能视为已审核的标准功效分类。

药典只从已校验来源的冻结研究索引读取条目数、字段块数与索引SHA。ETCM与药典数量分列，不相加。各来源独立报告不可用/未启用/版本未导入，没有数据时不沿用写死的旧数量；部分来源可用时为partial，两者均不可用为503。

分类标签以 `textContent` 展示，不执行HTML；原始标签不写入聊天消息或历史。刷新后保留统计摘要，需要再次提问获取实时分类列表。能力说明和概览不清除本会话工具焦点，不会替其他会话选药材。

## 路由边界

本轮是确定性意图路由与上下文补全，不是任意中文语义理解、模型自主规划或text-to-SQL。API接纳检查与主图使用同一路由函数；主图再结合自己的持久会话焦点决定追问归属。模型、Tavily和PubMed不会参与数量/分类/帮助问题；文献请求才按开关调用NCBI。

不能识别或同时涉及多个来源时应进一步明确任务，不生成疗效结论。停用工具和来源失效仍保留原503/来源核验；不将自然语言改进作为临床质量批准。

后续优先收集真实失败问法，建立覆盖能力、统计、字段、概念、文献和跨源歧义的小型意图评测集。只有对照证明规则覆盖不足，再增加可选模型意图分类：仅输出允许的工具/参数，校验后执行；低确定度询问，模型不生成SQL，不参与来源事实补造。通用概念解释需要另行补充可引用术语资料。
