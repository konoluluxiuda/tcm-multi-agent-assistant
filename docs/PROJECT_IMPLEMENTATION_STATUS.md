## 后续按完整交付包推进

### 跨来源研究与检索质量闭环（J02 + J03分阶段完成）

当前交付及未完成边界见[本轮说明](CROSS_SOURCE_REPORT_MILESTONE.md)。下列完整目标不能全部视为已完成。

业务：给定明确药材与问题，文本分支检索药典，结构化分支查询ETCM，返回各自来源及能/不能支持的结论。实体无法确认时保留来源候选，不将同名自动合并或把关联写成药效。

一次交付包含：复用现有数据的检索服务、dense/词法融合与候选重排、统一证据结构、两个有职责边界的子图并行、超时/空结果降级、接入现有后台进度与报告页面、固定任务集及方案对照。不能只新增类或测试脚本就结束此里程碑。

验收：同一数据快照和冻结开发/保留问题，分别报告检索命中/排名（只有完整相关性标注才报Recall）、引用支持与任务完成、耗时；展示至少一个跨来源任务、一个歧义任务和一个分支失败任务。模型外发仍按授权范围执行；不为演示而默认发送真实资料。

### 随后：生产存储与可恢复执行（J04剩余 + J07）

一次交付包含：PostgreSQL部署/迁移/回滚、run/step/checkpoint持久化、恢复后的未知工具调用策略、跨进程租约、API/页面续跑、强杀/升级/并发演练。复用本轮API语义与事件顺序，不重新设计一套交互。当前本地队列无需重写即可继续服务，PostgreSQL收益需由恢复/并发实测说明。

### 最后：跨会话记忆与工具互操作（J05 + J06）

交付账号/项目命名空间、明确可查看/更新/删除的长期记忆、本地语义召回，以及同一套工具通过MCP被本应用和第二客户端调用。先确定真实使用场景，避免为简历安装框架而没有调用链。
