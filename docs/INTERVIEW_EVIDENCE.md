# 大模型应用项目：贡献、证据与面试追问

更新：2026-10-31。主投大模型应用开发。项目源自开源Multi-Agent-Medical-Assistant；本人贡献应描述为基于开源项目的改造及新增工程，不能称从零独立研发整个框架。当前讲解主线见[三分钟演示](PROJECT_DEMO.md)，状态见[统一大纲](TCM_PROJECT_ROADMAP.md)。所有表达先由本人复现并确认理解。

## 简历表述草稿

**中草药资料核对工作台｜Python、FastAPI、LangGraph、SQLite、DeepSeek，选配Qdrant/Langfuse**

- 将ETCM结构化JSON与药典提取文本构建为版本化资料发布，登记来源/规则指纹并保留证据锚点，支持字段核对、缺项与差异报告及可追溯XLSX交付。
- 分离自然语言Goal理解和工具执行，使用Pydantic校验对象、字段、否定要求与父版本；复用持久状态图、队列和请求回执，处理幂等提交、未知派发、owner隔离、租约及revision冲突。
- 构建原生tool calling观察循环，以状态限制合法工具/参数，保留最多三组工具历史和最新snapshot；对重复动作、越界证据和预算耗尽显式停止，宿主负责文件生成与逐格验证。
- 设计分层数据/检索/RAG及执行对照，保留失败记录；根据同目标下单次理解与多轮执行的交付和token开销，选择确定性执行作为常规路径，多轮模型仅显式开启。

熟悉哪两三条就选哪几条；不能把使用过的所有可选组件堆成必经技术栈。不填写未测的QPS、P95、临床准确率、付费成本下降或独立用户任务成功率。PostgreSQL与MCP是其他已实现的可选报告能力，不代表本工作台已分布式部署或由模型自主选择MCP。

## 90秒讲解稿

“我在开源医疗助手上做了一个数据库加文档的资料核对工作台。用户把两味药的功效、注意事项整理成表，之后还会追加字段，要求旧内容和出处保留。难点不是把模型接到网页，而是结构化JSON、PDF提取文本和名称候选可能不一致，还存在缺失和饮片作用域，不能直接拼成一个确定的医学结论。

我把目标理解与执行分开：模型可用一次原生工具调用提出Goal，宿主检查对象、字段和父版本，再进入同一个LangGraph持久任务。常规字段读取和表格生成走确定性策略；另有native模型每次看观察再选动作，两者共用工具、预算和交付校验。文件按版本保存，先验证再交付，旧v1不覆盖。

我没有默认认定Agent一定更好。八道新业务题，单次模型理解加固定执行完成七题，本地语法只完成一题；预选多轮两题均未交付，一题漏药名未执行，一题说没有合格记录却提交了三条不合格记录。随后我统一入口、收紧新建/续改Schema及可交付集合，让模型理解自然表达、程序检查参数。合成烟测中，原生循环已能三步交付正确空表；真实旧失败不重写，多轮继续实验。样本由作者编写，不把它说成生产准确率。”

## 常见追问

**为什么用Agent，不能写一个脚本吗？** 字段完整性、集合运算和文件生成确实可编程，所以常规流程使用fixed。模型在当前实验里的收益主要是理解某些自然表达；native循环验证观察后选动作、约束与交付，但尚未证明它对这些机械任务必要。若需求不需要策略调整，不强行加入循环。

**Tool calling具体在哪里？** Goal模型通过 `propose_research_goal` 提案；执行模型通过list/inspect/search/read/ask/deliver六类动作选择下一步。它们是独立模型阶段，有独立开关和计数。程序校验动作，交付由宿主完成；不是模型任意执行Python/SQL。

**CoT/ReAct用了什么？** native执行具有动作—观察—再行动的循环，并使用原生tool_calls。可审计的是目的、参数、工具返回和状态，不保存隐藏CoT，也不拿思维链长度作为可靠性证据。

**上下文太长怎么办？** 保留目标和最新snapshot，最多三组工具调用/返回；历史保存句柄和状态，旧原文不反复携带，回读最多三段且每段800字。调用前有上下文字节及请求正文预算，超限裁剪旧工具对或停止；没有证明它必然提升语义正确率。

**模型失败后怎么处理？** 无法理解或目标校验失败，不入队；错误动作被拒绝、无进展/预算耗尽停止；未知派发不自动重发；RAG生成失败返回已检索原文。父版和旧文件仍可读，失败不能被自动改标成功。

**同一份表两个人同时改怎么办？** 写入核对owner、父版revision和来源版本，过期写入冲突；子版本不覆盖父文件。会话隔离、租约和文件锁是具体机制，尚无任意多人协作文档合并。

**记忆、RAG、MCP有什么区别？** 会话/项目记忆保存用户工作状态；RAG读取来源事实；MCP让有限只读工具可被标准客户端复用。它们不是一项功能，也不会因为安装过就全部参与这次表格任务。工作区revision本身也不是语义记忆。

**最能讲清楚的失败是什么？** 三个例子：Schema合法但模型加了五个不需要的属性；旧循环已读完却重复列目录；向量方法没有超过词法基线。分别用宿主约束、状态工具/历史和保留简单默认方案处理。原始结果保留，不能把离线回放包装成新增模型成功。

**还欠缺什么？** 开放问句和复杂未识别要求覆盖、跨库身份/提取人工签核、独立问题真值及生产规模。现有证据更充分地证明有界单机工程和小样本调用，尚无全库Recall、广泛用户收益、分布式或临床效果结论。
