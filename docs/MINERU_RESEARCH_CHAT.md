# 独立研究聊天入口

2026-10-18完成研究对话页面与持久会话闭环。打开 <http://127.0.0.1:7869/chat>，可从原证据研究台的链接进入。

后续已将共享工具接入[主Agent显式/research分支](AGENT_RESEARCH_TOOL.md)；下文保留独立入口这一阶段的能力和验证范围，两种入口不共享会话。

本轮使用**确定性工具路由**：识别明确追问、调用只读研究检索、根据状态展示固定说明与证据卡。没有调用聊天模型，没有新增LangGraph工作流，也没有把药典导入主聊天或ETCM数据库。它提供后续Agent集成可复用的工具对话层，不宣称已经实现自由问答、临床推理或复杂多步研究。

## 使用方式

1. 输入“甘草的功效”，查看未审核的原文/AI修订及原PDF证据。
2. 输入“它的用量”，从本会话保存的药材焦点重新检索，不从旧回答文字推断药名。
3. 输入“出处呢”，重新执行上次成功查询并展示证据；不会编造页码。
4. 刷新页面或重启服务后继续追问。重新加载只恢复近期消息与焦点，证据在下一次提问时按当前数据重新查询。
5. 点击“清除本会话”，删除已存消息与焦点并更换会话凭证。

只有明确同名候选查询成功才选定焦点；也可先只输入已收录药名，再补充字段。炮制范围未解析、引用未展开、未知名称或多条目歧义均不会继续沿用上一味药。只选定药名而尚未查询字段时问“出处呢”，会提示补充字段并保留药名。

本页只支持当前药名/字段规则与“它、这味药、刚才那味药、刚才的药材”开头的明确追问；不识别任意省略或泛指。对比、个体用药、复杂诊疗问题不属于该入口当前能力。字段改述、繁体/拼音覆盖仍有限。

## 来源与未完成状态

复用[检索保护](MINERU_RETRIEVAL_GUARDS.md)，原文、研究修订、字段与标题证据采用两个页面共享的DOM渲染函数，全部文本用文本节点展示。

- “酒大黄的用量”提示炮制范围未解析，只给母条目标题核对入口，不用大黄字段代答。
- “炙甘草的用量”显示未完成状态及“同甘草”的相邻原文证据，不自动复制剂量。
- 查询失败后再问“它的用量”会要求明确药名，不回退到此前甘草等旧焦点。
- 焦点绑定索引、视图与检索/保护代码SHA；重启后版本不同，追问返回`context_stale`，需要明确药名重新查询。

## 持久化与隔离

复用`ConversationStore`的已完成轮次JSON快照、签名Cookie、散列会话键、乐观修订、删除墓碑和过期机制。新增序列化字典读写接口，使研究页面不依赖模型或LangChain包；主聊天原消息编码接口仍可使用，未更改存储Schema版本。

研究会话另存 `var/mineru_research_chat/conversations.sqlite3`，以独立类型标记拒绝复用已有主聊天会话库；索引和PDF不能用作会话库。研究Cookie名为`research_session`，带HttpOnly、SameSite=Strict及默认30天期限。它不与主聊天的`session_id`共享身份或历史；尚无账号登录和跨设备同步。

默认只保留最近20条消息，闲置30天过期。只保存用户问题、固定状态说明、药材名称与上次成功问题等小型槽位，不保存工具返回的药典原文、图片或完整证据卡。保留范围针对会话库，不自动删除用户另存的截图、数据库备份或验证文件。

服务写入前再次检查来源快照，并仅在检索完成后按修订号提交整轮。存储或来源失败不降级为临时记忆；同一会话冲突返回409，删除/过期旧凭证返回410。单进程线程锁与数据库CAS共同保护完成状态；不支持节点级崩溃续跑或多工作进程容量承诺。

## API

| 路径 | 行为 |
|---|---|
| `GET /chat` | 独立研究对话页面 |
| `GET /api/research/conversation` | 初始化签名会话或恢复消息、焦点及revision |
| `POST /api/research/chat` | JSON仅接受question和revision；服务器决定上下文并调用检索 |
| `DELETE /api/research/conversation` | 删除已存会话并轮换凭证 |

客户端先GET恢复会话，再携带同一Cookie与返回的revision提交问题。请求体不接受自报history/context/agent状态，问题长度1–500字符；非法/重复JSON字段拒绝。写接口校验本机Host及Origin，未设置CORS。`POST /api/search`仍不支持，现在返回404；既有GET检索和原页接口保持原用途。
