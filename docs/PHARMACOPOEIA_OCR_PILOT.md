# 中国药典小样本 OCR 试验

2026-10-16。使用用户提供的两份PDF，以及现有ETCM SQLite中的四味药材，先验证可提取性、阅读顺序、关键片段和来源追踪；不接入正式聊天或知识库。

## 样本与定位

|---|---|---|---|---|
| YiZhiHuangHua | 一枝黄花 | 434页文件第24页；另对照全本第51页 | 3 | 跨左右栏，同页不同扫描质量 |
| DingGongTeng | 丁公藤 | 434页文件第24—25页 | 3—4 | 跨栏、跨页；含注意项 |
| DaFuPi | 大腹皮 | 全本第76页 | 28 | 从全本补434页文件缺失位置，跨栏 |
| ShanMaiDong | 山麦冬 | 全本第77页 | 29 | 从全本补页，跨栏，多个来源植物 |

四条ETCM来源ID已写入 [试验清单](../eval/pharmacopoeia_ocr_sample_v1.json)。中文对应和区域划分由AI看图提出，仍待人类审核；没有更新ETCM中文别名或自动合并实体。

两份文件均无文本层。434页文件在印刷27页后直接跳到30页；全本PDF第76、77页可提供28、29页。本轮使用这两页作为较低清晰度样本，不代表已证明全本没有其他缺页或已确认下载件真实性。

## 方法

- 使用本地CPU RapidOCR 1.4.4及包内PP-OCRv4模型，不调用聊天模型、嵌入或付费OCR服务。[工具来源](https://pypi.org/project/rapidocr-onnxruntime/1.4.4/)
- 240dpi渲染5个实际PDF页，按中线分为左右栏，共10次分栏识别；另对高分辨率文件第24页做一次整页基线。
- 根据试验前划定的药材区域组合跨栏/跨页文本。**这是人工指定区域的小样本，不是自动条目分割。**
- 先记录21个关键片段，再运行OCR。比较只做Unicode NFKC及去空白，标点差异仍判为不匹配；没有用ETCM或模型改写识别结果。
- 每段证据保留文件SHA、PDF页号、印刷页号、栏位、PDF坐标和OCR行置信度。完整OCR与预览只在忽略的 `var/pharmacopoeia_ocr_sample/` 中保存。

## 结果及实际失败

四味药的预录片段命中分别为5/5、6/6、5/5、5/5，共 **21/21**。原结构化药材 [30条冻结验收](../audits/pharmacopoeia_ocr_sample/golden.json) 仍全部通过，ETCM库SHA保持不变。范围包含药名、拉丁药材名、药用部位短语、性味归经、数字单位，以及丁公藤的一项注意片段。

这不是全文字符准确率。OCR准确率与业务任务完成率都保持null，来源内容和对应关系仍待人类核验。

- **整页会串栏：** 基线输出85行，按行中心统计左右栏交替79次。若直接拼接返回顺序，会混合两栏。分栏后使用左栏→右栏阅读顺序，并按药材区域截取；仍不能直接推广到任意版式。
- **关键片段之外有错误：** 大腹皮拼音 `Dafupi` 被识别为 `dnpa`，该行置信度约0.585；山麦冬的 `spicata` 被识别为 `spicala`，整行置信度约0.962；`短葶` 被识别为 `短亭`，置信度约0.953。高置信度不能代替校对。这三项为后验诊断，未混入原21项预录检查来改变分母。
- **本样本未证明高分辨率版本的整体优势：** 印刷第3页的两种扫描各命中同样的5个关键片段；仅凭此不能报告OCR准确率提升。
- **药材拉丁名与植物学名不能混为一列：** 例如药典的拉丁药材标题与ETCM的来源植物学名属于不同概念。本轮只对照各自原文，不做字符串覆盖。

本次11次识别的实测耗时合计约52.86秒，不含安装、人工划区和全部文件指纹检查，也不是端到端用户时延或吞吐评测。精确模型与依赖版本、模型SHA、逐片段结果见 [审计报告](../audits/pharmacopoeia_ocr_sample/report.json)。

## 使用范围与下一步

当前结果可作为带原图坐标的待复核OCR草稿，不能自动写回已有药材字段，也没有证明完整条目抽取或RAG问答正确。保留原PDF和原始OCR，不通过模型补字来掩盖错误。

下一步先实现有明确边界的“来源、性味归经、功能主治、注意”等字段候选抽取，核对跨页归属，并将拼音/学名不一致项隔离为待审核。确认这一层可靠后，再接入检索和聊天引用；不用先全量OCR两千多页。

## 复现与环境

OCR是单独的可选环境，不加入主应用依赖或Docker镜像。验证使用Python3.12和 [独立锁定依赖](../requirements-ocr-pilot.txt)：

```bash
python3.12 -m venv /tmp/tcm-ocr-pilot
/tmp/tcm-ocr-pilot/bin/python -m pip install -r requirements-ocr-pilot.txt
/tmp/tcm-ocr-pilot/bin/python -m scripts.pilot_pharmacopoeia_ocr --out var/pharmacopoeia_ocr_sample/repeat
```

保持原PDF位于清单所写路径。脚本在识别前后验证文件SHA，源文件改变即不能沿用同一试验。模型在本地，识别阶段禁用Python socket连接与ONNX遥测；不加载 `.env` 或调用主应用配置。

实际安装过程保留的限制：最初Python3.13不能安装该OCR包；系统Python3.12缺少ensurepip，因此使用现有pip的 `--python` 参数向临时3.12环境安装。没有升级主项目或系统Python。

原PDF、完整OCR、页面图像与初次探测结果留在本地。仓库只保存脚本、依赖、少量参考片段和统计/坐标，不包含完整药典正文。测试与源码检查不替代人工签核或科研、临床内容核验。
