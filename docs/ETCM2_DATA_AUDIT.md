# ETCM2.0 本地快照：首轮数据审计

日期：2026-10-10。源目录：`/home/zry/workspace/HDCTI/dataset/ETCM2.0`。

## 1. 结论与实施决定

这批数据值得用于验证**药材结构化查询与来源展示**，但不能直接当作完整、干净的中草药知识库。药材基础字段可以解析；中文名映射、字段语义、记录去重和关系身份校验仍是必要工作。当前结果只证明数据接入的可行性，不证明已有 Agent 的中草药回答效果，也不证明复杂多 Agent 编排带来收益。

首批实现：药材基础信息 Schema → loader → SQLite repository → 拼音/ID 查询 → 原字段和来源定位 → 人工核对测试集。先用少量记录验证再导入通过校验的药材基础信息；中文入口需单独建立可核验的名称映射。不对整个 169 GiB 快照直接向量化，不把异常靶点用于可信关系查询。

本次仅读取原始目录，输出审计与设计文件；没有修改原始 JSON，没有调用模型/嵌入 API，没有业务入库，也没有改动容器或发布镜像。

GiB = 2³⁰ 字节，按文件逻辑大小计算，不是磁盘实际占用。文件数不等于唯一实体数。抽样采用固定随机种子 42、每组随机 24 个文件，加最小/最大/中位大小文件并去重；这是工程筛查，不能据此推算全量错误率。

全部文件记录相对路径、大小、mtime；仅检查内容的 2,390 份文件计算 SHA-256。检查 JSON 解析、响应状态、基础字段、缺失、HTML、名称/内容重复、关联表行数和抓取汇总。关联表字段目录仅取各表前 3 行，不代表逐行 Schema 或关系外键已经验证。

## 3. 实际结构与药材字段覆盖

源文件是接口响应，包含 `code/msg/data/name/page_title` 等字段；`data` 中按 section 存放基础信息、关联表与图表。药材基础信息为 `base_information.value` 的键值数组。成分样本则通过 `base_information.children` 嵌套多层属性；外层 `value=""` 不代表基础信息缺失，需要不同解析分支。

2,076 份药材文件均能解析为对象、`code=1`，且能提取基础信息。下表是源字段非空覆盖，**不是内容正确率或证据充分率**。

| 药材基础字段 | 非空文件数 / 2,076 | 比例 |
|---|---:|---:|
| 拼音、拉丁名、英文名（各自） | 2,076 | 100% |
| Family | 2,068 | 99.6% |
| Habitat | 1,988 | 95.8% |
| Medicinal Part | 1,931 | 93.0% |
| Indications | 1,843 | 88.8% |
| Flavor | 1,775 | 85.5% |
| Property | 1,766 | 85.1% |
| Database Cross References | 1,621 | 78.1% |
| Meridian Tropism | 1,438 | 69.3% |
| Herb classification based on efficacy | 609 | 29.3% |
| PubMed | 65 | 3.1% |

关键限制：

- 药材基础信息没有独立中文名称和别名字段；不能声称整个数据集没有中文文本，也不能凭拼音自动生成已确认的中文药名。
- 拉丁名与英文名全部带 HTML 标签，部分两者值相同。保留原值，使用 HTML 解析器另取展示文本，不能直接据此合并实体。
- `Indications` 混有疾病/症状名称与传统功效描述，初期保存原字段，不强行统一成“已验证适应证”。
- 65 份药材记录包含 PubMed 字段，不代表这些记录的每项属性均有论文支持。其余记录也不能因此直接断言没有研究。
- `HuaYeEZhangChai.json` 仅有 4 个基础字段，必须支持稀疏记录和缺失状态。

详细设计见 [字段映射草案](ETCM2_FIELD_MAPPING.md)。

## 4. 已发现的质量问题

### 4.1 靶点身份错配与整份响应重复：暂缓关联入库

260 份靶点文件均为可解析、`code=1` 且有基础信息的响应，但存在 **5 组完全相同的文件内容，共涉及 30 份文件**，按 SHA-256 计算仅有 235 个不同文件内容。235 也不等于已经验证的实体数。

例如 `5-hydroxytryptamine_receptor_1B.json` 和 `5-hydroxytryptamine_receptor_1E.json` 内容相同，内部 `name=PLCG2`，基础字段为 phosphodiesterase gamma-2、Gene Symbol 为 PLCG2、UniProt 为 P16885。还有 gamma-1/gamma-2 文件存入 CYP24A1 的案例。文件标识与内部身份明显不一致；仅检查 JSON 或接口成功码无法发现问题。规范化标点后共有 28 份靶点文件触发文件名/内部名称不一致警告，完整列表见机器报告。原因尚未查明，不能直接断定是哪段抓取代码导致。

处置：将重复组及文件名/内部名称不一致项加入待复核清单，检查抓取时的请求参数、响应与文件写入对应关系；确认后重新抓取或更正映射。不能简单按文件名建靶点主键，也不能只做哈希去重就宣布修复。

### 4.2 抓取不完整

`etcm_targets/Aromatase.json` 的传统方剂关联抓取汇总为 `expected=45118`、`actual=2060`、`status=partial`，并记录 HTTP 502。这里引用的是源文件自报汇总，不能假定其与表内容的统计口径完全一致。

药材抓取汇总中出现 2,949 次 `skipped` 状态（计数单位为汇总项，不是文件）；药材疾病关联表最大行数为 20。当前证据不足以证明这些关联表全量完整，也不足以把每个 20 行表判为截断；后续应复核分页和抓取策略。`expected=actual` 或 `status=ok` 也不是科学内容核验。

### 4.3 成分错误响应

27 份成分抽样中，26 份为成功响应并有嵌套基础信息；`etcm_ingredients/2,2'.json` 返回 `code=2`，消息为 `No Data for 2,2'!`，不能作为正常成分导入。该样本包含最小文件，不能用 1/27 估计全量失败率。

### 4.4 药材重复名称与文件名问题

`HuaShi .json` 与 `HuaShi_.json` 的拼音经去空格/大小写归一化后均为 `huashi`；基础字段相同，完整文件内容不同。保留两份来源并复核，暂不自动合并成同一药材实体。另有两个药材文件名出现异常编码字符，需用内部身份与名称核对。

文件名比对只作异常候选检测；标点归一化、同义名、命名规则差异都可能影响判断，不能将所有警告直接认定为数据错误。

## 5. 关联数据为什么先不整体向量化

药材文件中的关联表累计行数如下，包含跨药材重复，**不是去重实体数或核验后的关系数**：

| 关联表 | 出现文件数 | 累计源行数 |
|---|---:|---:|
| 成分 | 1,898 | 67,342 |
| 靶点 | 1,849 | 126,775 |
| 疾病 | 801 | 14,176 |
| 中成药 | 898 | 70,007 |
| 传统方剂 | 654 | 303,566 |

快照还包含图表、网络和富集结果。直接将响应作为长文档嵌入会重复索引大量表格/派生数据，并掩盖身份错配与来源层级。初期只提取药材基础字段；关联表后续拆成独立来源记录，在身份、关系含义和证据类型验证后再开放查询。
