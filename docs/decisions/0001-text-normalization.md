# ADR-0001：来源展示与查询的空白规范

日期：2026-10-14。状态：采用现有实现作为当前产品规范；AI 复核分歧已分类，人工科学审核仍待完成。

## 问题与证据

独立 AI 复核发现四条记录的拉丁/英文名存在八项字面差异：源 HTML 的 `&nbsp;` 解码为不换行空格 `U+00A0`，现有展示值保留它；盲推文本额外折叠为普通空格 `U+0020`。另有五项普通字段首尾空白差异。原值、定位和查询结果没有相应冲突，见 [原始复核](../../audits/tcm_ai_review/report.md)。

两个可选方案：展示时统一全部空白，或者保留内部空白、仅在查询匹配时折叠。当前采用后者，保持已交付的来源展示与冻结 v1 一致，不为消除审核差异变更知识数据。

## 当前规范

- `raw_value` 保留来源原值，不改 HTML、空格、大小写或数组位置；JSON Pointer 继续定位原字段。
- 拉丁/英文名展示通过 HTML 文本提取、实体解码、首尾 trim；内部 NBSP 保留，不额外折叠为普通空格。
- 普通字符串展示去首尾空白；不在内部自动改写传统术语或药材名称。
- 名称精确匹配与字段子串筛选使用 Unicode 空白折叠和 casefold；NBSP 与普通空格在匹配时等价。这是查询归一化，不是科学实体合并。
- 列表的首尾 trim、去重及缺失状态仍沿用现有 loader 契约；原始列表保留在来源对象。字段存在但为空时保留其来源位置。

对应实现为 [tcm/herbs.py](../../tcm/herbs.py) 的 `text_value`、`search_key` 和字段处理；本次没有修改该代码、原 JSON、SQLite 或冻结 v1。

## 审核结果怎样记录

保留原盲推与八个 literal mismatch，不把审计退出码从 1 人为改成 0。另存 [产品规范裁定](../../audits/tcm_ai_review/adjudication.json)，将这些差异标为 `accepted_contract_difference`，依据是上述展示契约，不是人类签核。五项 trim 差异也明确记录。错误字段、错误指针或源漂移仍是错误，不能套用这一分类。

后续如希望统一展示空白，需另建规范版本、迁移与候选集，保留 v1 和修订理由；不能覆盖原标准答案来得到通过率。该决定不处理中文别名、术语词表或药材基原身份。

2026-10-15 实测：8 项展示值与两种空格查询返回的来源集合一致，展示值保留。两项查询返回歧义候选，不能假设每个名称唯一；首次检查中“全部应唯一”的假设已纠正。见 [验证记录](../../audits/tcm_ai_review/normalization_validation.json)。这不改变原 AI 审计的八项字面差异记录。
