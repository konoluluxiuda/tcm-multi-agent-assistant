# 报告入口：结构化字段请求与展示优先级

2026-10-25。本轮修复上一轮自然问法诊断定位的报告入口问题。适用范围是“本地研究 → 药典+ETCM报告”的文本分支，以及调用同一文本分支的两药报告；不是整个聊天意图路由升级，也不是新增自主LLM规划。

## 实现

新增 `tcm/report_request.py`。请求对象保存用户原句、已选药材、识别的字段、优先字段、解析来源和检索用问句。沿用 `mineru_retrieval.INTENTS` 字段词表，避免复制药典字段定义。通过完整句式匹配支持保存/用途的部分口语改述；只在整个问句符合限定语法时生成规范字段查询，不把未知复合药名截成父药材。

`cross_source_report.text_search` 先校验所选药材与原句中的对象一致，再解释请求，再执行原有字段/炮制范围校验、词法/向量检索和可选重排。明确的“先列/先看/优先展示/重点是”只有唯一字段时影响展示；否定的“不要先看”等不设置优先项。展示层稳定排序，不修改原文、证据和模型分数，也不把优先排序冒充重排模型提升。

重排返回最多6项后，结果组织层可从原融合候选中补回被截断但被用户优先要求的字段；最多仍返回6项。对已识别字段记录 `missing_requested_fields`；有候选但选中结果未覆盖全部字段时标为 `partial_evidence`，不标完整。保留原有限定和缺失/歧义状态。

本轮没有启用外部模型 fallback。现有 `intent_planner.py` 是聊天意图路由，缺少报告的优先序和完整要求契约，不能直接把其输出当作本轮报告请求。当前解释器仍是有限规则，未知开放问法、否定多项需求、复杂条件仍需后续统一Schema与模型适配；原句保留不等于其全部语义都已被理解。

## 已验证的问法

在本地研究选择“药典+ETCM报告”，药材填“当归”：

- `当归买回来放在哪里保存？` → 贮藏字段。
- `整理当归的资料，想知道它主要用来做什么。` → 功能与主治字段。
- `当归的功效和贮藏都需要，不过请先列保存要求。` → 两个字段，贮藏在前。

完整句式匹配之外的炮制品、药品复合名、多对象和额外指令继续走原校验，不直接改写；问题长度预算在规范化前验证。合成测试还覆盖购入后怎样存放、查阅资料想了解用途、否定优先要求及字段缺失。
