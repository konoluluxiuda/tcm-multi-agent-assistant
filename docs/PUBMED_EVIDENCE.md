# PubMed来源关系、保守查重与文献库升级

现有 `/pubmed` 与CLI现在会显示来源关系和身份提示。仍只读取官方返回的元数据/摘要，不获取全文、不进行临床质量评分、不让模型补充结论。功能开关与指令沿用[聊天手册](PUBMED_CHAT.md)。

## 能判断什么

关系来自 `MedlineCitation/CommentsCorrectionsList`，逐项保存原 `RefType`、关联PMID/版本、来源和备注。未知关系类型保留原值，缺失/异常PMID不补造链接。以下方向不能混用：

| 当前记录的关系 | 本系统提示 |
|---|---|
| RetractionIn | 当前论文已关联撤稿通知 |
| RetractionOf | 当前记录是撤稿通知，不把通知本身误标为被撤稿论文 |
| ErratumIn / ErratumFor | 当前论文有更正 / 当前记录是更正通知 |
| ExpressionOfConcernIn / ExpressionOfConcernFor | 当前论文有关注声明 / 当前记录是声明通知 |
| CorrectedandRepublishedIn / From | 原文关联更正重发 / 当前为更正重发版本 |
| RetractedandRepublishedIn / From | 原文关联撤稿重发 / 当前为重发版本，不因此把新版本直接标成已撤稿 |
| UpdateIn / UpdateOf | 有更新版本 / 当前为更新版本 |

同时识别来源出版类型中的撤稿、通知、重复发表等标注。没有命中规则仅表示**本次返回元数据未见已识别提示**，不是“文章没有问题”。关系不额外联网展开，不保证通知内容已经阅读或第三方撤稿数据库已核对。依据：[NLM关系政策](https://www.nlm.nih.gov/bsd/policy/errata.html)、[PubMed XML关系字段](https://dtd.nlm.nih.gov/ncbi/pubmed/doc/out/230101/el-CommentsCorrections.html)。

研究类型只映射明确的PubMed出版类型，如综述、Meta分析、随机对照试验、观察研究、病例报告、方案或预印本；未识别则显示未分类。MeSH中的Humans/Animals仅作为对象索引显示，缺失不推断人/动物/体外研究，不根据标题或摘要猜类型；`aheadofprint`也不自动当成预印本。所有记录仍为 `quality_appraised=false`。类型字段的含义见[NLM说明](https://www.nlm.nih.gov/mesh/pubtypes.html)。

## 查重和版本边界

- PMID仍是唯一目录键，同PMID的新观察更新目录，但批次快照保持不变；来源提供的PMID版本单独保留，版本变化列为提示。
- 仅对本批次和本地台账中已见记录做DOI匹配，不做全球查重。去除doi.org包装或doi前缀、外侧空白，并仅折叠ASCII A–Z；保留Unicode差异和结尾标点，不做NFKC、模糊标题匹配或百分号解码。DOI等价规则依据[DOI Handbook](https://www.doi.org/doi-handbook/html/)。
- 格式识别是受限规则（`10.`加4–9位ASCII数字及非空后缀），不是完整DOI有效性验证。不满足规则时保留原值、不给匹配键；不能据此宣称DOI不存在。
- 不同PMID具有同一DOI时显示候选列表，**不删除、不自动合并，也不直接计为独立研究**。原始论文、通知和重发版本可能关联同一研究，单靠DOI不足以裁定。
- 同一返回记录中多个可识别DOI相互冲突时，保存全部候选，标记冲突并禁用该记录的DOI匹配。`ELocationID ValidYN=N`明确标为无效的DOI及其等价变体也不用于查重，仍保留原值和提示。相同PMID的DOI或PMID版本相较目录变化时保留提示，历史批次提供旧值。
- 出版类型“重复发表”是来源标注，与本系统“同DOI待核对”分开保存。没有做跨数据库实体合并、作者/标题模糊匹配、系统综述级最终判重或人工审核。

新记录保存版本化 `assessment` 和 `identity` 字段；检索批次冻结当时结果。旧批次回放不联网、不重算、不修改哈希，缺失新版关系标记时页面明确提示重新检索。已存旧批次并不因代码升级就自动完成撤稿核查。

## SQLite文献库v1→v2

本轮只升级独立文献库，**会话库仍为v1**。新文献库直接初始化为v2；已有合法v1库在首次开启工具或CLI访问时自动迁移，包括仅回放旧批次的访问。默认关闭的PubMed分支不会初始化或升级文献库。

1. `BEGIN IMMEDIATE`阻止其他写入，先验证库用途和版本。
2. 用独立只读连接在线备份已提交的v1库，放在数据库同级 `migration_backups/`，私有目录0700、文件0600，校验完整性并fsync。备份失败则不执行DDL。
3. 同一事务增加 `articles.doi_key`，每批128条回填目录匹配键，建立普通索引 `articles_doi_key`，最后将 `user_version`设为2。
4. 任一步失败回滚列、索引、回填和版本；已验证的升级前备份保留。再次打开v2不重复升级，不触碰旧批次JSON或会话引用哈希。

查重查询使用 `WHERE doi_key=?`，实际 `EXPLAIN QUERY PLAN`验证命中索引。这里只证明查询路径，不代表完成容量、并发或生产性能测量。文章表原DOI和快照均保留原值，`store_kind=pubmed_literature_v1`继续作为数据库家族标记，结构版本以 `user_version`为准。

升级前备份包含文献检索式和摘要，属于私有运维数据，不含会话签名密钥。它不使用[会话备份包](MEMORY_BACKUP.md)的格式或自动失效逻辑；本机操作规程为确认新版本可用后手动清理，通常最多保留7天，当前没有清理调度器。数据库路径建议始终位于被忽略的 `var/`。

结构升级失败会自动回滚事务；已经成功升级后**没有自动降级命令**。需要运行旧代码时，先停止相关写入，将已关闭的升级前v1文件复制至新私有路径，核对数据后使用旧版本和新路径；不要覆盖运行中的v2库，注意升级后新增批次不在旧备份中。本轮只在隔离副本执行了实际升级，没有升级正在使用的原文献库或切换镜像。
