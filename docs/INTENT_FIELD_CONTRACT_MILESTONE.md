# 模型意图与本地字段查询契约

2026-10-26。本轮复用现有DeepSeek/LangChain原生Tool Calling适配，补齐字段查询的优先级和原始问句信息，不引入新框架、不新增资料外发。只完成合成响应的离线验收，未执行真实提供方请求。

## 改了什么

`QueryIntent` 增加：

- `priority_field`：仅单药research可填写，必须属于本次fields。
- `priority_evidence`：必须逐字出现在当前问句中，和优先字段一起填写；缺失或凭空生成则拒绝模型输出。
- `unresolved_requirements`：最多4项，每项最多200字符；非空时只允许clarify，不允许继续查询后把未完成要求省略。

模型仍只接收当前问句和静态工具定义，最多1次调用、10秒超时、0次自动重试。资料、用户历史和本地工具结果不进入这次模型请求。字段、对象与动作继续经过严格Schema、字面对象和炮制品范围校验；外部模型不能生成SQL或自行选择任意工具。

`mapped` 把经过校验的字段和优先项转成既有本地药典工具可消费的查询，并保留原句、字段和优先级。`ResearchRuntime` 在响应的 `intent_request` 中保留这些信息；本地 `ResearchTool` 检索、组织字段并保留出处。后续“出处呢”使用已执行的规范查询本地重读，不重新调用模型。原句在本次响应中保留，不承诺另建跨会话原始请求档案。

未识别任务是否真的完整、排序语句是否语义正确，不能仅靠Schema和逐字证据判断。模型可能漏报未知要求；本轮校验不能证明任意长句被完整理解。原有规则命中时仍直接走本地路径，本轮没有为所有规则结果增加第二次模型检查。多药compare不支持新增priority字段，不能误套单药语义。

## 实际链路验收

测试通过真实FastAPI `/chat`、生产路由与LangGraph节点，用假SDK只替换模型响应，并使用本地合成药典索引：

> 示例叶炭能派什么用场、每回取多少，后一项放最前

该句未被现有规则识别；合成模型提案为“功能与主治、用法与用量，优先用法与用量”。实际API返回两项合成资料，用量在前；原句被保留，出处追问返回相同字段与证据。断言模型只收到一次当前问句，未收到合成字段正文；追问禁止模型调用。

其他测试包括：虚构排序证据、未请求的优先字段、未解决要求仍尝试查询、非法动作组合、超时不重试、炮制品对象保护，以及已有聊天/药典工具行为。

**本轮4个相关测试模块、34项测试通过。** 它验证接口、校验、路由与本地执行，不验证真实模型自然语言识别质量。上一轮115模块984项全仓回归属于上一轮，本轮没有把该数字改写为新全仓结果。

## 使用与后续

默认本地预览仍关闭意图模型，已有7883进程未更新。部署代码更新后，配置 `ENABLE_INTENT_PLANNER=1` 才会对规则未识别的当前问句启用既有模型适配；预览脚本对应 `--with-intent-model`。不需要重新构建药典或ETCM索引。

本轮没有启用真实模型预览、没有执行远程调用，也没有Git提交、push或Docker更新。离线验收记录与文件指纹在 `audits/intent_field_contract_v1/`。

下一步应在冻结的、未参与规则设计的合成问句上验证真实模型输出，并记录错误动作、遗漏字段、错误优先级与澄清比例。每题最多一次，不自动扩大既有授权，不以假模型测试通过代替真实模型有效性。真实资料继续留在本地。

回滚只涉及意图Schema/映射、运行响应附加元数据与测试，不修改数据库。没有这些可选字段的旧模型输出仍可校验；现有自然规则与显式命令不依赖新增字段。
