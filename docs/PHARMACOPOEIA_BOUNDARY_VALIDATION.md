# 药材章节30页冻结规则验证

本轮从九页开发试验推进到新的30页验证。目标是检查现有自动条目切分能否扩展，识别真实漏切和跨药串接；本轮不修改被冻结的抽取规则，也不执行全章导入。

## 页面与参考如何建立

使用较清晰的434页扫描件，取三个连续区间：物理30–39页、200–209页、420–429页，分别覆盖药材章节前、中、后段。样页均为双栏；印刷页码直接读图登记为9–18、181–190、401–410。三组之间是试验主动留出的物理间隔，不等于源文件缺页。

选择排除了此前开发/基准使用的页面，是有目的的工程抽样，不是随机样本，不能代表全书通过率。[页面计划](../eval/pharmacopoeia_boundary_validation_v1.json)固定来源SHA、页面、版式和章节；两份PDF仍保留原有身份，本轮仅对434页来源做新OCR。

识别前保存抽取器、字段规则、OCR适配器和批处理脚本的源码SHA，并在私有目录保存源码快照。解析规则在整个验证期间不改动。每页240dpi渲染、RapidOCR本地推理、逐页缓存与校验，保留失败记录，不调用付费模型。

先直接读图登记44处条目标题，包含炮姜、制何首乌等有完整标题的炮制品；体外培育牛黄附属原料标准不计为独立药材。**视觉参考由同一个AI助手建立，未经人工或独立专家签核，不等同于人工金标准。**

初版缩略图纵坐标窗口估计过窄：对物理32页原图再次核对时发现偏差。原v1参考和冻结记录保留；在OCR已经开始、但尚未查看任何OCR结果时，将参考v2改成页/栏对应，只有同栏出现两个标题时才分上下窗口。标题文字、样页与抽取规则未改变。此修订的时间边界明确记录，不声称v2在OCR启动前已冻结。

主评估使用[参考v2](../eval/pharmacopoeia_boundary_visual_v2.json)及[冻结记录v2](../audits/pharmacopoeia_boundary_validation/freeze_v2.json)，测量的是粗略页栏标题对应，不是精确像素级起止位置准确率。初始[参考v1](../eval/pharmacopoeia_boundary_visual_v1.json)保留用于追溯，不能混作最终位置标注。

## 评估与故障处理

评估器先校验冻结源码、PDF、计划、参考、推理配方、页面缓存文件SHA和两套渲染图SHA，再从原OCR重建条目，与落盘结果逐项比较。不接受部分成功批次，也不允许改候选正文后仍使用旧摘要作为通过证据。

标题匹配要求页、栏和窗口唯一对应；多个候选或多个参考相互重叠时记录歧义，不强行计为正确。页栏位置对应和名称文字相同分开报告，因此有对应不代表OCR名称准确。

如果一个原图可见标题没有成为新条目，却原样出现在前一候选内部，报告标记跨药串接并输出需要隔离的候选ID。没有原样名称证据的漏切仍记录，不能凭推测宣称已定位其归属。检查三组之间是否错误接续、同一条目是否跨页、哪些条目需要补充后续页面。

`report.json`把工程输入完整性与边界验证状态分开。出现漏切、额外标题、歧义或跨组串接时，评估命令退出码为2，并保留失败报告；不能因OCR完成而把业务验证记为通过。名称差异单列，不能自动改字或进行实体映射。全文字符准确率、字段范围准确率与临床正确性保持为空。

## 复现

```bash
# 首次新识别；默认缓存目录与旧九页试验独立。
/tmp/tcm-ocr-sample-20261016/bin/python -m scripts.batch_pharmacopoeia_pdf \
  --plan eval/pharmacopoeia_boundary_validation_v1.json \
  --out var/pharmacopoeia_boundary_validation_v1/batch

# 完成后验证；输出路径必须尚不存在。
python -m scripts.eval_pharmacopoeia_boundaries \
  --out var/pharmacopoeia_boundary_validation_v1/recheck.json
```

评估还需要在忽略目录保留本轮的100dpi视觉参考图 `visual/high-N.png`，不能只下载脱敏审计就伪称完成了私有数据复现。抽取结果和页面图均不进入公开仓库或Docker镜像。查看脱敏结果：[审计目录](../audits/pharmacopoeia_boundary_validation/)。

本轮新建评估器的六项测试覆盖名称错误不冒充字符准确、漏切污染隔离、一个窗口多候选、负例页误切、无标题续文、跨分组串接，以及印刷页码不连续。工程回归不代替真实PDF的边界结果。

## 实际结果与判断

| 检查 | 实际结果 |
|---|---|
| 原生OCR | 30/30页完成，303.358秒；Python网络尝试0，未复用开发OCR |
| 标题参考与检测 | AI视觉参考44处；自动检出36处，页栏对应36处，其中2处名称有差异 |
| 漏切/额外切分/歧义 | 8 / 0 / 0，相对本轮粗略AI参考，不称全书准确率 |
| 接续 | 23个候选跨页；跨三个试验分组串接0；3个末尾候选未闭合 |
| 漏切污染 | 主评估用原样中文标题证据确认5个已有候选被串入下一标题；事后诊断连同错字/漏字情况共定位7个被污染的已有候选 |
| 复核清单 | 8个漏切事件、2个名称差异；合并涉及9个不同候选，未导入索引 |
| 缓存重跑 | 命中30页、0新增OCR，条目结果SHA不变 |
| 工程验证 | 192/192离线回归、0跳过；篡改OCR缓存副本被拒绝，未生成评估输出 |

主命令真实退出码为 **2**：工程输入完整性通过，但边界验证有失败。这里没有把“33个候选止于下一检测标题”当作33个正确条目，因为漏切会让这个“下一标题”已经隔了一味药。

失败分为三类：

1. **OCR漏掉来源首行（3处）**：干漆、土贝母、僵蚕。重新从PDF裁剪原图已确认来源首行存在，原OCR没有保留下来；当前切分器因找不到“本品为”而不切开。土贝母标题还有“土→士”的识别错误。
2. **来源句式覆盖不足（3处）**：体外培育牛黄的“本品以……”，藏菖蒲、翼首草的“本品系……”，均未被当前“本品为/本品由”规则接受。
3. **中文标题漏字（2处）**：薤白仅识别为“白”、藁本仅识别为“本”，触发当前至少两个汉字的限制。不能自动用预期名称填回缺字。

另外，三七识别为“三冏七”、槲寄生识别为“寄生”；它们被检测为新条目，但不能用这个名称直接进行药材映射。原文和OCR均保留，不自动改字。

[主报告](../audits/pharmacopoeia_boundary_validation/report.json)、[事后异常清单](../audits/pharmacopoeia_boundary_validation/exception_queue.json)、[来源漏行原图检查](../audits/pharmacopoeia_boundary_validation/origin_omission_image_check.json)分开保存。事后清单的7个污染候选与主报告的5个证据确认候选采用不同确认条件，不能悄悄改成同一组统计。

下一步应先修复“条目边界必须依赖完整来源段”和“中文标题漏字导致吞并”的问题：即使来源或名字未识别完整，也应将可靠的标题组合作为待核实边界，隔离身份/来源未知的条目；再对少量异常标题和来源区域尝试局部重识别。**本轮30页从此成为已知失败回归集**，修复后的独立验证需另取未参与开发的新页面。不能修完这30页再声称它们是独立留出集。

当前不启动完整章节提取。药典批量链路仍未接入正式聊天/ETCM，字段范围和专业词准确性尚未评估；人工批准仍为0。原两份PDF和ETCM数据库SHA均未改变。
