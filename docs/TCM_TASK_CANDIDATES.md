# 60 条任务候选：审核与后续评测

日期：2026-10-15。状态：AI 设计草案，尚未人工审定或执行任务评测。

## 与原有 30 题的关系

[新候选](../eval/tcm_task_candidates_v1.json) 用于准备业务任务评测；[原有 30 题](../eval/tcm_golden_v1.json) 继续作为冻结工程验收集，文件与签核状态不变。新候选全部标为 `designed`，真实使用问题 `observed` 数为 0。设计者是同平台独立 AI，不声称外部模型或人类专家已签核。

候选配额：详情 15、筛选 10、比较 10、边界 10、稀疏数据/文献范围 10、多步任务 5。每题保存问题、操作入口、预期、来源锚点、限制、分组和审核状态；原数据不从被测查询输出反推。

中文题干是给使用者/审核者的任务说明，当前执行依赖明确的页面操作或 API 参数，并不表示中文聊天入口已接入。`planned_chat` 题必须标为 unsupported；人工在页面修改筛选或查看来源，不意味着系统具有会话追问能力。

## 验证什么，以及不验证什么

[候选校验器](../scripts/validate_tcm_task_candidates.py) 校验 60 题配额、dev20/test40、声明分组与泄漏锚点、支持范围标记、来源文件 SHA、JSON Pointer 原值以及全量快照指纹。

```bash
python -m scripts.validate_tcm_task_candidates \
  --source /home/zry/workspace/HDCTI/dataset/ETCM2.0 \
  --out /tmp/tcm-task-candidate-validation.json
```

不传 `--source` 只检查结构与声明分组，报告来源检查 `not_run`。CI 使用合成源验证校验器的错误分支，并检查仓库候选的格式，不要求私有全快照。校验器不执行候选任务，不判断标准答案是否完整、科学正确或足以满足用户目标；通过不能写成“60/60 任务成功”。

任务需人工复核问题是否明确、预期是否与问题一致、是否遗漏可接受答案及证据是否充分。缺 PMID 不等于没有研究；有 PMID 也不能证明每项传统属性。无答案与工具失败需分开判定。中文能力未实现时，即使接口正确返回限制，也不能当作中文药材查询目标已经完成；降级行为正确率应另报。

## 分组与泄漏边界

dev20/test40 是候选分组，不是已经完成的独立测试实验。相同 group 与声明的实体/条件组合锚点不能跨组；筛选条件可能共享词语，结果集合可能重叠。校验器只检查显式锚点，不能证明没有所有形式的语义泄漏。

这些候选及源数据已供设计者和开发者查看，不属于隐藏评测。人工审定后再冻结正式版本；后续开发只用开发集调参，保留测试集避免反复挑选答案。若已据测试失败改进系统，要记录其开发暴露状态，另补未见题评估泛化。

## 后续落地顺序

1. 复核每题的来源与预期，记录人类审核人、日期、争议及修订理由；AI 状态不能冒充人工签核。
2. 将设计题与实际使用记录分别统计，收集 observed 问题，补足当前缺少的真实工作需求。
3. 对已支持的页面/API 任务建立执行器和人工操作评审；未支持聊天题单列能力缺口，不静默删掉。
4. 保存逐题实际结果、证据、状态、耗时与失败类别；调用模型时再记录 token/成本，未知成本不填 0。
5. 在同一人工审定版本和运行条件下比较方案，才报告任务完成率或改进幅度。

本轮采取的空白规范见 [ADR-0001](decisions/0001-text-normalization.md)。原 AI 审核八项字面分歧仍保留；产品契约裁定不是人工科学审核。
