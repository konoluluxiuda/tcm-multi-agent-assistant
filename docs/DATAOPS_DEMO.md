## 直接输入整理要求

用上述`--dataops-synthetic`启动后，在`/dataops`顶部输入要求，点击“开始整理”：

- `整理白术和黄芪的功效、注意事项，保留出处并生成表格`
- `整理药用部位包含Root的前20条记录，补充功效和注意`
- 无真实资料的合成服务可问：`整理Alpha和Gamma的功效、注意，保留出处`。

从结果或历史打开任务后，输入`增加贮藏，保留旧字段`，点击“修改当前结果”；对象集合沿用该结果。可写`重查有问题的记录`；不更换对象，不覆盖旧v1。候选不唯一时仍只询问实际药典候选。

本轮是有界本地语法，默认附带ETCM药用部位/拉丁名；未指定药典字段时取功能主治和注意。未知名称、否定/复杂条件、推荐预测等未覆盖要求会显示原句中的具体未识别内容，任务不入队，不自动删掉要求执行剩余部分。仅给筛选条件、未指定条数时默认取前20条，页面会说明。一次最多50条、4个药典字段；换对象或筛选条件请新建任务。它不接通外部模型，也不代表真实A已通过。无需额外核对请求清单。

完整记录见[问句入口验收](../audits/dataops_question_v1/README.md)。更新代码后需重启服务；旧检查点与源码校验不兼容时请新建任务，历史产物仍可回看。聊天首页`/`也已接入明确的表格整理要求及字段续改：可直接输入第一条示例，结果卡内查看进度、选择实际候选和下载；刷新会话可恢复。再问“增加贮藏，保留旧字段”会修改当前整理任务。`/dataops`继续提供独立工作台；普通问答和显式`/research`等指令沿用原路线。见[聊天接入验收](../audits/dataops_chat_v1/README.md)。

## Docker引擎恢复后的本地命令

D3当时引擎不可用，以下为历史命令，未用于最新镜像验收。当前引擎和本地镜像已可用，以[当前运行说明](RESEARCH_SELECTION_AGENT.md)及新验收回执为准。构建不包含原始资料、.env或本地运行记录：

```bash
docker build -f Dockerfile.research \
  --build-arg SOURCE_REVISION="$(git rev-parse HEAD)" \
  --build-arg SOURCE_TREE_SHA256="$(python -m scripts.dataops_source_manifest --hash-only)" \
  -t tcm-dataops:d3-local .
RESEARCH_IMAGE=tcm-dataops:d3-local RESEARCH_PORT=7908 \
  docker compose -f compose.research.yaml -f compose.dataops.yaml up -d
```

首次使用需已有ETCM目录、药典索引及`ETCM_RUNTIME_DIR`对应独立侧库快照；相对默认路径指向当前已有目录。端口映射为宿主7908→容器8000，访问宿主7908。7908已有本地预览时先停止该预览，或改用空闲端口。

状态使用`research-memory`卷；重建容器后核对历史v1/v2、人工等待续跑、取消及owner隔离。不要通过`down -v`清除卷来模拟恢复。只在镜像实际运行验收通过后记录镜像ID；本轮无远程push。
