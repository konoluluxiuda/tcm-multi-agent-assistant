## 当前实现

用户在聊天中显式勾选“AI整理回答”后，LangGraph依次执行模型规划、工具检索、模型整理和引用/原文摘录检查。Pydantic限制计划及回答格式；每题最多2次模型调用、2个本地查询和1个文献查询。本地片段最多6条、每条800字，文献最多3条、每条摘要1200字。模型调用超时30秒、自动重试0次。记录阶段耗时、调用次数和provider返回的token用量；未配置可靠单价，费用为null。

计数和能力概览继续使用现有确定性查询。新模式复用FastAPI聊天接口和SQLite会话保存，不引入新数据库、Agent角色或页面。当前会话保存最终展示的短句摘录、来源ID和标题，刷新后可恢复回答文本；不另外持久化完整检索结果对象或AI来源展开卡片。新模式只发送当前问题及本轮有界工具结果，不发送会话历史。

当前校验同时检查ID存在、来源组一致、每个引用均绑定原文短句，以及短句逐字存在于指定来源的text/title。药典陈述由服务器改为展示已核对摘录，去掉模型自由改写；文献仍可改写，**摘录存在不等于改写被语义支持**。两类资料分组，不自动认定对象一致，不将标题或摘要标成已读全文。无证据、澄清、模型失败、错误引用、错误摘录和部分工具失败均有显式状态。

## 数据发送范围

最初用户明确要求“先只用合成资料测试，不发送药典片段”，前述合成阶段仅向已配置的`api.deepseek.com`、`deepseek-flash`发送设计问题与内存生成的“示例草”和虚构文章，没有发送真实片段。后续用户明确批准下文5题的有限药典片段测试；授权不扩展到整个网页、ETCM、真实文献、历史或整份PDF。

网页通过`ENABLE_EVIDENCE_ASSISTANT=1`启用，`EVIDENCE_ASSISTANT_DATA_MODE`默认为`synthetic`，界面和回答均标注合成资料。CLI也默认使用合成资料。本次5题在独立受限脚本运行，没有修改`.env`或网页默认模式；不要因单次测试获批就全局改为`local_sources`或任意使用`--local-sources`。

## 来源短句约束：已实现，真实模型新格式待验证

针对D01/D05，回答Schema新增`supports`，每项包含`evidence_id`、`field`（text/title）及最多160字的逐字摘录；每条陈述最多4项。程序要求支持项与引用ID集合一致，并逐项在对应来源字段中查找原文；改写、拼接、编造的摘录均不能通过。错误返回`invalid_support`并以HTTP 502展示失败，不自动重试，也不把未经检查的草稿作为回答返回。

仅检查摘录存在无法拦截“正确摘录＋错误推断”，因此药典回答采用更窄的输出范围：模型仍规划和选择片段，服务器只展示核对后的原文短句，删除该条自由改写，并合并重复摘录。未核验的自由改写也不会保存在会话。此阶段牺牲药典自由总结能力，优先避免自行建立功效/主治配对或补入分类；不能再把这个入口描述为已验证的自由生成综述。
