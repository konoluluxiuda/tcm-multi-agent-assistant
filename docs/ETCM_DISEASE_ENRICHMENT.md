# ETCM疾病富集来源查询

日期：2026-10-20。对应ENG-04：利用现有药材JSON关联表，提供可追溯的疾病富集记录查询；不新增全量疾病文件导入、疾病翻译或医疗推荐。

## 使用

在7875聊天中输入“白术有哪些疾病富集记录”“白术的富集疾病”，或显式指令`/relations 疾病富集 BaiZhu`。中文候选需要选择ETCM来源，不把药典与ETCM对象自动认定为一致。选定后每页20条，分页使用固定来源ID；可问“出处呢”、刷新恢复、手动收藏，并复用JSON备份及Markdown证据笔记。

疾病名称保留来源原文，不自动翻译或合并；原始行中Global category、Anatomical category等字段保留在“原始行与JSON出处”。每条来源行保留JSON位置、抓取状态、原始名称和分组信息；重复行不按名称删去。结果数量是来源行数，不是去重疾病种数。

**富集关联不是适应证或治疗推荐，不证明药材可治疗所列疾病。** 本轮不验证疾病身份、统计显著性、富集算法或临床质量。不把“白术能治疗哪些病”等临床问句纳入此关系语法；这不代表其他现有模型入口已完成全局医疗安全验收。

## 数据范围与完整性

数据来自已导入2076份药材JSON的disease关联表，复用`var/etcm_enrichment_v1/data/enrichment.sqlite3`。未读取/导入全量`etcm_diseases`文件，也未将疾病文件候选自动合并为事实；源文件、基础库和派生库均保持只读。

疾病表抓取状态单独从已校验来源SHA的药材文档取得，即使本页零行仍能展示：

- 来源明确记录skipped/partial等状态时原样展示，不改成complete。
- 来源没有提供状态时提示“无法判断抓取完整性”。
- 零行只表示当前来源未记录可展示的行；不能推断没有疾病关联。

实际白术来源现有20行，原始抓取标记为skipped，因此这20行不是已确认的全量结果。黄芪、甘草当前目录也各有20行，但没有据此开展完整性或疾病相关性评议。没有根据分类、行数或“富集”字样补造P值、临床证据等级或作用机制。

## 复用工程约束

新增关系种类disease，复用原有参数化只读查询、名称候选选择、来源ID/文件SHA/数据版本检查、页码1–1000与来源绑定焦点。缺库或来源不匹配停止，不切换模型。页面与Markdown保留“非适应证”边界和疾病表抓取状态，导出仍只含收藏页，不遍历全部结果。

收藏备份v1允许disease关系种类；已有类型的备份继续兼容。含疾病类型的文件需要本轮或更新源码读取，旧程序会拒绝其未知类型，不应删掉类型校验来强行导入。没有新增账户、MCP、Neo4j、嵌入或外部模型调用。
