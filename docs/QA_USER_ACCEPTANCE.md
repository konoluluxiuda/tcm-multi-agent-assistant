## 问题与交付标准

每个场景使用新浏览器会话，同场景多轮保持原会话。10 场景共 13 轮文字输入，翻页和刷新不另算问题。按原句提交，不临时补关键词。

| ID | 原始输入（多轮按顺序） | 必须满足的交付 |
|---|---|---|
| U01 | 请把菊花的药性、药味放在一起告诉我。 | 菊花的 ETCM `properties`、`flavors` 均覆盖；不因两个字段重复成两张药材卡 |
| U02 | 薄荷的归经和药典用法与用量，我都想看。 | 薄荷；ETCM `meridians` 与药典“用法与用量”，不得只给一项或询问已明确来源 |
| U03 | 桔梗与陈皮分别属于什么科，药用部位又是什么？ | 两个对象各有 ETCM `family`、`medicinal_part`，不串值、不漏药 |
| U04 | 山药的性味与归经只查《中国药典》，不补其他来源。 | 仅药典“性味与归经”；不混入 ETCM 默认值，保留合并字段语义 |
| U05 | 只从ETCM查独活的用法与用量。 | 说明指定来源不支持该字段，不静默换药典或输出用量；能力边界题 |
| U06 | ① 我想查陈皮的资料。<br>② 先给我药味和药用部位。<br>③ 再补上药典的贮藏。 | ① 询问字段并保留陈皮；② 陈皮 ETCM `flavors`、`medicinal_part`；③ 陈皮药典“贮藏”；②③不重新索要药名 |
| U07 | ① 请查桔梗的归经。<br>② 换成菊花，仍然查归经。 | 分别查桔梗和菊花的 ETCM `meridians`，不沿用旧对象、不覆盖旧答案 |
| U08 | 列出薄荷的成分，先看第一页。 | 薄荷成分关系第一页、有页范围；有下一页时点击，核对对象和分页位置；不把当前页当全量 |
| U09 | 请查月砂草QX73的药用部位。 | 先确认人为名称不在目录中；应提示未找到，不猜其他药名或生成字段值 |
| U10 | 这个药应该怎么保存？ | 全新会话没有对象，应询问药名；不读取其他会话对象、不猜药名 |

业务为 U01–U04、U06–U08，共 7 场景；边界为 U05、U09、U10，共 3 场景。U06 首轮澄清是业务步骤，不另计边界通过。

执行前根据冻结来源人工建立对象与字段参考，记录来源标识、版本、原文位置及有值/缺失/歧义；不用被测答案反推标准，不凭模型知识编写药学标准值。缺字段时忠实展示缺失可通过“如实交付”，但不计“字段有值完成”。真实名称歧义按参考判断，不能把任意澄清当正确。U09 若意外存在精确记录，标注题目前提不成立、停止该题，不能运行后悄悄换名。

## 执行步骤

1. 新建未用过的私有目录，例如 `var/qa_user_acceptance_20261106_01/`，存在则换后缀。保存本文副本及 SHA256、Git 提交、工作区差异、运行源码与来源指纹、入口、非敏感开关、起止时间；不复制密钥或 Cookie 入报告。
2. A 组可用于排障，不是 B 组的必经前置；本次按用户授权直接在核对后的 7896 执行 B 组。串行提问，每场景新会话，不清除原用户会话。每句只提交一次；失败保留，同批不修改代码、词表、Prompt、题目或验收标准。
3. 每轮记录 Network 的 `POST /chat` 响应、`X-Request-ID`、提交至答案渲染完耗时、结构化结果及截图。同会话按[诊断说明](REQUEST_DIAGNOSTICS.md)读取已有轨迹，不重提问题取日志。
4. U06、U07 完成后刷新并回看早期答案，核对原轮次内容与出处，刷新不产生新查询 POST；U02 打开药典原页或证据定位。U08 检查分页；无下一页据实记录，不伪造翻页通过。
5. 对照事前来源参考评分，定位理解、名称绑定、来源/字段、工具读取、答案保存或展示阶段。前置轮失败，不人工注入正确对象救后续轮，保留实际对话观察并注明依赖影响；服务不可用则停止，剩余题记未执行。
6. 汇总所执行组别。B 组本次授权已经执行完毕，不因剩余预算继续调用；A 失败也不自动启用模型。若以后另行开展复测，使用新目录，不覆盖首轮结果。原文、截图和诊断留在 `var/`，公开摘要只放去敏结论及必要指纹。

这是手工方案，未新增自动评测器或全局预算拦截器。

## 评分与交付

每轮核对对象、字段、来源、值与证据、终态、展示；场景所有必需轮次及操作都满足才通过。HTTP 200、模型说完成或生成文件不等于业务成功。判定使用确定性检查与人工来源核对，不以模型自评替代。

分别记录“完成且有值”“完成并如实报告缺失”“必要澄清/边界处理”“不必要澄清”“错误”“未执行”，业务与边界分开汇总。延迟给每轮原始值与中位数，不声称生产 P95。理解请求、结果复核请求、输入/输出 token、未知用量分列；刷新/证据读取单列。

目标为 7 个业务满足合同、3 个边界处理正确。错对象、静默换源、编造值和跨会话泄漏是阻断问题；多余澄清或展示/恢复失败记待修项，不扩大功能来凑通过率。无法核定证据的项记待核验，不能宣布完整通过。即便全过，也只完成本批走查。
