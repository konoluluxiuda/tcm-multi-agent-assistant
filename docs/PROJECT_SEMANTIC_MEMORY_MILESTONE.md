# 本地语义项目记忆：召回、核对与报告应用

2026-10-26。本轮在显式项目记忆上接入本地语义候选检索、普通聊天入口和确认后的报告应用。保存的数据仍是用户明确填写的研究背景，不自动抽取全部聊天记录，不把历史模型回答作为药学事实。

## 如何使用

打开 http://127.0.0.1:7887/ ，在“本地研究 → 研究项目记忆”保存：

- 项目名：补血活血药比较
- 药材：当归、川芎
- 关注问题：功效及贮藏

之后可以直接在聊天输入“继续上次那组补血活血药的比较”，也可在“查找研究背景”输入自由描述。系统展示最多3个相关项目；点击“继续这个项目”填入报告，然后生成报告。

“继续上次的研究，这次只看贮藏”保留药材但使用本次问题；“继续上次的研究，这次看白术的贮藏”使用本次明确药材。候选不会自动执行研究，也不会自动改写保存的项目。药材目录无法核对、过期或删除的候选不能自动应用。不能可靠理解的新要求原样保留给报告入口，不静默退回旧关注问题。

普通明确查询仍走现有路由；“刚才那味药”“它的出处”等短期追问不被项目检索抢占。聊天自动进入记忆检索仍使用有界的历史指代识别，不宣称任意问法都能自动识别。独立的项目检索框没有这层触发词限制。

## 实际调用链

`/chat`中的研究背景指代，或`POST /api/research/projects/recall`
→ 签名Cookie映射owner
→ SQLite只读取该owner最多20个项目
→ 本地子进程验证已下载的BGE模型文件哈希
→ BGE-small-zh-v1.5 ONNX编码
→ 请求内Qdrant内存集合余弦检索
→ 中文二元字符重合排名与向量排名RRF融合
→ 相似度开发阈值0.50过滤
→ 再次读取SQLite核对存在性/revision
→ 最多3个候选
→ 用户选择时`/{id}/apply`再次检查owner/revision
→ 本次明确要求优先
→ 现有后台报告重新读取药典/ETCM及出处。

余弦分数不是置信概率。当前数据规模小，每次仅编码该用户的项目，不建立常驻向量服务，也不保留磁盘向量缓存。删除或更新不会留下可复用的旧向量；检索期间更新/删除则丢弃旧候选。用户选择时再校验，防止旧页面应用旧版本。

每进程最多2个本地编码子进程；等候空位最多1秒，子进程超时25秒。模型缺失、编码超长、worker超时或返回错误绑定时提示不可用，仍可手动选项目，不转调DeepSeek。子进程环境不传聊天API密钥。此限制不是多主机全局限流。

## 实现文件

- `tcm/project_semantic.py`：本地召回、权威版本核对、当前问题覆盖及短期追问边界。
- `scripts/project_memory_dense.py`：本地ONNX/Qdrant工作进程；复用`LocalEncoder`和锁定模型。
- `tcm/project_memory_api.py`：recall/apply契约及owner/同源校验。
- `app.py`：聊天指代入口，不调用外部聊天模型。
- `tcm/research_runs.js`、`templates/index.html`：搜索框、聊天候选、安全文本展示及报告预填。
- `scripts/preview_local_tasks.py`：显式`--semantic-memory`开关，默认关闭。

## 开发对照与真实边界

固定题目在`eval/project_semantic_v1.json`，4个手写项目、6个相关问题（其中1题有两个合理候选）、2个无关问题。运行前冻结，属于开发集，未由独立用户提供或人工医学签核。

| 方案 | 首位命中（6题） | 平均Recall@3 | 无关题不返回候选 | 返回候选中相关比例 |
|---|---:|---:|---:|---:|
| 无记忆 | 0/6 | 0 | 2/2 | 不适用 |
| 二元字符匹配 | 6/6 | 1.0 | 2/2 | 7/10 |
| 本地向量 | 6/6 | 1.0 | 2/2 | 7/10 |
| 向量＋词面RRF | 6/6 | 1.0 | 2/2 | 7/10 |

**没有证明语义方案优于词面匹配。** 无记忆不返回候选是定义，不是业务准确率为零。虽然正确候选首位命中，仍有3个次要候选不相关，因此本轮不自动套用第一条记忆，不将阈值视为校准后的置信界限。下一轮应使用未参与开发的问题检验同义改述与歧义，并对比简单方案；没有收益时可保留更简单实现。

本机8次检索包含模型加载约0.71–1.12秒，中位数约0.77秒；不是压力测试或p95服务承诺。每次重新编码降低索引一致性复杂度，但项目数量增加后需要重新评估开销。

真实浏览器已验证：保存项目后刷新，在聊天中检索，选择后以本次“贮藏”覆盖保存的“功效”，实际报告取得贮藏出处；编辑后旧候选拒绝应用、删除后不再返回、其他浏览器身份无记忆、普通概览聊天仍可用。本轮外部模型调用0次。

## 启动与回滚

```bash
/tmp/tcm-ci-mail-env/bin/python -m scripts.preview_local_tasks \
  --port 7887 --state var/project_semantic_v1/preview_state \
  --diseases var/disease_catalog_v1/build/diseases.sqlite3 \
  --dense-python /tmp/tcm-dense-20261019/bin/python --semantic-memory
```

本机本地推理环境已有qdrant-client 1.13.3、ONNX Runtime和tokenizers。模型使用现有固定BGE导出，脚本不下载模型。其他机器按现有本地dense环境准备依赖及模型后再启用。

服务配置为`PROJECT_MEMORY_PYTHON`、`PROJECT_MEMORY_MODEL`；去掉开关或清空两者即可关闭自动聊天语义入口，保留项目CRUD。`--dense-python`同时启用已有报告dense能力，非仅记忆开关；回滚到原预览参数可恢复原报告配置。
