## 1. 新结果说明了什么

用户走查进一步支持了实际资料上的查询、跨来源报告、表格和连续修订能够交付。当前路径包括直接查询、声明式计划、本地模型替身，不能把这些结果统称为真实LLM自主推理成功，也不能据此计算真实模型准确率。

“为什么需要模型”应分成三个可检验问题：

1. 对没有预设完整语法的表达，模型是否更准确地形成受约束目标，减少无意义改问？
2. 对执行后才出现的资料异常，模型是否能在现有证据和工具权限内增加安全、有效的交付？
3. 这些增益是否值得增加的请求、等待、费用及失败面？

不主张证明某类任务只能由LLM完成。固定流程已能胜任的任务继续作为强基线，保留其正常的分页、缓存、消歧、重试边界及异常分支。

新计划先补“正确证据是否被检索到、生成回答是否受支持”的证据。当前药典v3的8665片段与旧8654片段向量缓存不匹配，不能将开启旧向量视为RAG升级；也不能用Goal十二题代替检索/回答评测。R1先建原始锚点参考，R2隔离比较检索，R3在固定证据下比较回答，R4再测动态行动。精确字段直接查询仍保留。

## 2. 黄芪贮藏：已定位的事实

诊断时的旧索引`var/mineru_retrieval_v2/research.sqlite3`中，字段`mineru-herb-4d2e9a34d40176dfd7d25676:field:014`同时包含贮藏正文和两段试剂配制注释，作用域为`prepared_slices`。旧索引和原资料保留不变；修复输出至新视图/索引v3。

本地查看`high`来源PDF第344页（印刷页325）：贮藏正文后确有“注：PBS…”及后续配制段落，之后才是炙黄芪条目。因此：**能确认字段边界串入后续注释，不能直接断言这些注释来自无关附录，也没有证据说明OCR把原文识错。**

| 块ID | 归属判断 | 原页范围（归一化坐标） |
|---|---|---|
| `part-301-400:840` | 贮藏正文 | `[102,394,352,407]` |
| `part-301-400:841` | 后续PBS配制注释 | `[73,412,487,463]` |
| `part-301-400:842` | 后续聚山梨酯配制注释 | `[73,468,485,500]` |

调用链核对：

- `tcm/mineru_pharmacopoeia.py::segment_blocks`：识别`【字段】`，没有识别为新字段/辅助标题的后续段落继续追加到当前字段。`auxiliary_heading`目前只覆盖饮片和特定质量标准附录，不能分离这种条目后注释。
- `scripts/build_mineru_retrieval.py::build`：把研究视图中的整个字段写入索引；不是在D2运行时重新OCR。
- `tcm/dataops/data_access.py::Sources.inspect`：按条目/字段直接取索引的`raw_text`，没有语义归属检查。
- `tcm/dataops/baseline.py::validate_result`和XLSX回读：验证值与引用/文件一致，不能证明引用片段都属于请求字段。

`candidate_scope_value / scope_requires_review`只说明“饮片段范围待核验”，**并不说明系统检测到了PBS污染**。

诊断时只读扫描614个贮藏字段，有11个命中“换行注释/试液配制”等启发式模式；当时只有黄芪查看原页，不能把11个候选当11处确认错误。后续质量批次已逐页查看这11处，并分别记录试剂、栽培变种、检测注释的块归属参考，见质量验收。该结果仍不是全库质量错误率，不采用“遇到注字就截断”的规则。

## 3. 优先修数据质量，不把已知规则问题包装成模型收益

质量批次按以下要求实现并验收，后续扩展继续遵循：

1. 保留黄芪失败样本、原块、页码及源hash；以原页建立独立参考：贮藏保留840，841/842归入条目注释，原文不删除。
2. 用可撤销的块归属修订或通用边界规则生成新研究视图和**新索引版本**，不原地修改现用SQLite。保留饮片作用域和未人工审核状态。
3. 对其余10个启发式候选进行小样本复核，同时加入“注释确实属于贮藏、应保留”的反例。没有把握时隔离字段、保留证据并报待审核，不伪造干净值。
4. 增加字段归属参考，独立于被测索引/研究视图。现有`SourceOracle`虽不调用被测适配器，但参考仍读取预索引视图；它不能独立发现共享上游边界错误。
5. 把“任务按契约完成”“字段值正确”“文件与数据一致”分开报告。审计任务允许报告缺失后完成，但不能把被污染字段当成正确字段。

这项确定性修复应同时给F/P/A使用。不能故意让固定流程继续使用污染索引来证明模型更好。生产索引切换还需校验来源版本/候选映射，旧工作区不静默复用新索引，旧文件继续可回看。

## 4. 当前工具确实限制了模型能做什么

`dataops/model.py`现有动作可以读取字段、回读已存在证据、询问、构建和验证；`read_evidence`不能自动补出相邻原始版面。现有字段验证又要求单元格等于整个索引字段，模型没有合法方式只保留其中正确的原块。

`planning.py`的一次规划P也强制包含基本固定阶段及依赖顺序，后续异常由宿主处理；它目前适合做协议及开销对照，尚不足以测试开放的任务规划收益。

兼容复测已在V4以2/3结束，尚未稳定通过；暂停扩展A的自动字段归属修订工具。目标理解适配器`goal_model.py`已完成G V1开发对照，`goal_proposal.py`仍是现有HTTP有界本地语法。下表是此前提出的能力：前两项仍未实现，第三项是未接入网页的实验接口；不再将它们作为R1–R3前置任务。新受限检索/证据读取按数据RAG方案实施，不能自动改写源字段。

| 拟议能力 | 最小输入/输出 | 宿主必须约束 |
|---|---|---|
| 字段上下文查看 | 已授权字段证据ID → 当前块和有限相邻块、标题/字段边界及位置 | 只读本地；绑定条目、源hash与证据归属；无任意文件路径；限制块数和字数 |
| 字段归属提案 | 从已读块中选取原始片段及拟归属 → 新候选字段和注释引用 | 不接受自由生成的药学值；原文字节/偏移可验证；不覆盖原索引；保留未核验状态和修订记录 |
| 类型化目标提案（G V1已实现） | 当前问句、允许字段与最多128别名合成目录 → Goal/澄清 | 代码校验对象、字段、范围、父对象继承；需求完整性仍需独立参考，不能仅凭类型；禁止直接执行SQL |

字段归属提案只是允许验证模型的证据选择，不等于程序能机械证明语义正确；业务评分仍须对独立参考。合法指令与源内容分开，源注释不能作为工具指令。

## 5. 两个实验分开测

本节保留此前G/A设计。新排期先完成R2检索与R3回答的分层对照，不继续单独刷G2或V4题；G字段语义及真正的观察驱动收益在R4结合真实任务验收。

### 实验G：自然语言目标理解是否有增益

对照本地有界解析与单次LLM结构化提案。二者拿到相同问句和允许的目录/字段，后续使用同一个固定执行流程。不得给模型直接提供标准Goal而给规则原始问句。

已完成的G V1单独冻结12题，见[题集](../eval/dataops_goal_understanding_v1.json)；与下方原12题压力草案分开。R/G各8/12，模型补3道自然表达同时错3道规范题，暂不替代规则。下一轮先修完整语义契约与路由，不能只用本轮题调提示后声称泛化提升。

指标：完整Goal匹配、对象/字段遗漏、应澄清而擅自执行、范围外误接受、需要用户改问的次数、真实请求数/耗时。多种合理解释事先标为应澄清，不因模型“猜对作者想法”得分。

### 实验A：观察循环是否有增益

向F固定流程、P一次计划、A真实观察循环提供同一个已核对Goal、数据快照、工具、宿主校验和完成标准，隔离自然语言理解的影响。P有正常异常处理，F可以检查候选和资料异常；不能把它们削弱成遇错即死。

以下12题是此前的作者压力集**草案，不是已冻结参考或独立用户集，当前不单独排为新题集**；可作为R阶段覆盖类型的参考，不能与新拟30题或G V1十二题混算：

| 组别 | 4种场景 | 要验证的结果 |
|---|---|---|
| C 确定性对照 | 单药标准字段、两药标准表格、结构化条件批量选择、明确追加一列 | F应有竞争力；模型不应无故增加动作或降低正确率 |
| G 目标表达 | 未预设同义表达、多要求同句、前序结果的限定修订、会改变结果的含糊要求 | 用于实验G；正确Goal或一次有效澄清，不丢要求 |
| O 执行观察 | 后续注释混入字段、合法字段内注释必须保留、候选/炮制形式歧义、证据不足无法完成字段 | 用于实验A；合理补查、受限修订、必要澄清或保留未知 |

已知黄芪样本是开发回归题，不能算模型泛化成绩。正式取舍前再由独立出题者提供少量未见样本，在执行前固定参考；不等待用户手动审核全库或提供几十个科研问题。

## 6. 如何拿到“依据观察调整”的证据

对同一Goal构造正常资料与异常资料两个分支，两者起始输入相同，不把答案写在题目或工具名里。记录真实模型在收到不同观察后的动作：正常分支直接交付，异常分支是否查看字段上下文、提交受限修订或询问；最后用参考核对结果。

仅轨迹变化不够。必须同时报告最终字段正确率、无关内容混入、合理保留率、遗漏/错对象及交付有效性。若A只是多调用工具但结果无改善，不算收益。

主指标至少包括：

- 完整任务达成率、正确部分交付率、应澄清时的正确处理率，分别报告；不把partial自动算全成功。
- 正确字段覆盖率及字段内容归属正确率；引用可回溯率另算，避免“有来源所以正确”。
- 未支持的值、跨对象引用、越权写源资料为0容忍；出现即停止发布候选。
- 实际提供方请求、返回响应、token、宿主决策步、工具调用、逻辑来源读取、等待和活跃耗时分别计量。
- 小样本逐题列结果，开发/未见题分开；预算允许后再独立重复，不用单次结果宣称统计显著。

规则控制题没有净收益时保持0模型调用。只有在复杂组中出现可重复的安全交付/改问次数改善，且成本/延迟在事前预算内，才把对应入口交给模型；否则保留固定执行或单次提案。

## 7. 失败处理也是实验结果

| 失败 | 预期动作 | 留存证据 |
|---|---|---|
| 已收到零/多工具动作或参数不合法 | 执行前拒绝；仅显式允许时最多一次格式纠正，计入原预算 | 拒绝类别、动作数量、工具注册名和数值usage；不留无效正文或隐藏推理 |
| 超时/断连，是否执行未知 | 停止，不静默重发；保留已完成产物/状态 | 派发预留、已收到响应与否、未知状态、停止位置 |
| 源/代码/父版本改变 | 拒绝旧状态重放，另建明确的新运行 | 旧/新版本摘要、缓存未复用证明、父子关系 |
| 字段归属不确定、候选冲突 | 限定补查；必要澄清或输出未知；不能自行补造 | 证据块、候选、未完成要求和对最终交付的影响 |
| 索引原文包含工具指令 | 只作为数据处理，拒绝越权行动 | 实际动作与宿主拒绝结果，不用模型自述证明安全 |

格式错误、未知派发、版本变化和注入作为故障套件单独报告，不能混进普通业务成功率。离线注入与真实提供方响应分别标识，不能拿MockTransport结果当真实模型行为。

当前raw run中的`model_calls`有时是驱动决策计数；普通声明式路径对外已有`execution.driver_steps`。后续应增加明确的`driver_steps`和由传输收据计算的`provider_requests`，保留旧字段兼容，不重写旧日志。缺失的usage/成本用null；不能把本地决策步当提供方请求数，或把缺usage当0成本。
