## 五分钟操作

| 步骤 | 操作 | 核对结果 |
| --- | --- | --- |
| 1 | 输入`查找疾病 Dermatosis Papulosa Nigra` | 当前快照返回一条来源；确认疾病原名 |
| 2 | 点击该行“候选排序” | 按选定来源计算Jaccard，显示药材候选；不是自由生成药物推荐 |
| 3 | 可输入下方指令改为前5项，展开“查看规模对照” | 实测交集、同规模期望及差值；默认折叠 |
| 4 | 展开候选行“查看”，再展开“双方原始记录” | 查看来源文件、SHA、JSON位置和原始行；此处是样本见证，非全量展示 |
| 5 | 点击“改按共同靶点数排序”，刷新页面 | 保留当前来源、数量和排序参数，重新读取结果；规模对照恢复折叠 |

```text
/analysis disease-rank Dermatosis Papulosa Nigra --top-k 5
```

可继续用`查找疾病 diabetes`展示多候选选择。中文疾病别名未核验，不能假设“糖尿病”会自动对应正确英文疾病实体。输入不存在的来源时应说明未找到，不用模型补造。

## 项目讲解要点

当前链路：浏览器聊天 → FastAPI → 现有聊天路由/LangGraph本地执行路径 → 严格参数分析工具 → SQLite只读来源目录 → 类型化结果 → 前端表格及出处。疾病名称查找、集合运算及规模期望都在本地计算；本次演示模型调用为0。Qdrant不是本条结构化查询的检索引擎，DeepSeek意图兜底在这个预览中关闭，MCP和模型自主分析循环未实现。

能说明的工程工作：模型和规则共享固定分析能力定义；来源身份、数据指纹、分母及返回结构校验；会话保存查询参数并按当前目录恢复；缺失和旧版本停止复用；来源见证可以回到原JSON核对。

可讲清楚的负面实验：128组疾病中，Jaccard前10项与只按药材靶点规模排序平均重合62.58%，共同数量排序重合82.03%；每组256次规模随机对照后，没有一组最大交集超过对应随机最大交集的第95百分位。因此保留候选检索的定位，增加实测与规模期望解释，尚未把它包装为已验证的疾病预测。随机模型只控制规模，不控制疾病靶点频率等因素，不能据此否定个别真实关联。
