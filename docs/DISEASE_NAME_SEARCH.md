# 疾病名称查找

更新：2026-10-23。7877源码预览新增 `search_disease_sources`，在已有疾病索引上浏览和检索来源名称，不需要记住完整英文名。中文别名、自动翻译和疾病同义词映射尚未实现。

## 使用

当前服务入口：http://127.0.0.1:7877/ 。可输入：

```text
浏览疾病目录
查找疾病 diabetes
查找疾病 diabetes mellitus
搜索疾病 alzheimer
```

每页20条，显示来源名称、靶点数量，以及“查看靶点”“候选排序”按钮。表格上方可直接修改关键词；来源信息默认折叠。选择后按固定来源ID进入已有分析，不按列表第一项自动选择。刷新或“回看分析结果”会恢复最近一次搜索的关键词与页码，重新读取当前索引。

也支持明确指令：

```text
/analysis diseases
/analysis diseases diabetes --page 2
```

如尚不知道完整名称，也可以先提出原分析需求：

```text
疾病 diabetes 的候选药材，按共同靶点数排序，前5个
```

当原名不能唯一匹配时，会先展示最多20条候选来源，尚不执行排序；选择按钮保留原请求的工具、数量、排序或页码。需要查看更多候选时，使用名称搜索缩小范围；普通来源搜索页的“候选排序”采用默认前10项/Jaccard，不继承另一条未选择请求。

## 查找范围

检索基于已入库的7593条来源原名，不包含此前隔离的112条文件名差异记录。当前快照中，`diabetes`匹配51条、`diabetes mellitus`匹配24条、`alzheimer`匹配9条；这些数字是名称匹配来源数，不是疾病种数或有效疾病基因集数量。

大小写不敏感，多个空格分隔的关键词需同时出现。排序依次为完整名称相同、名称前缀匹配、其他关键词匹配，然后按规范名称和来源ID稳定排列。没有同义词扩展、拼写纠错或语义相似度；名称包含某词不代表这些疾病可以合并。单独的 `%` 或 `_` 不会被解释为查询全部记录的通配符。

“查找疾病 糖尿病”目前会显示未匹配，不自动换成某条英文疾病。只有经核验、绑定具体来源的中文映射才适合加入后续版本。本轮没有为补中文名称而外发资料或调用翻译模型。

## 实现与验证

- `tcm/disease_search.py`：参数化只读SQL、字面多关键词查找、每页20条、5秒数据库查询预算；不重建1.8GB疾病索引，不改原JSON。
- `tcm/analysis_tools.py`：加入第五个固定注册工具，严格输入/分页输出Schema；能力名称与模型工具说明共用注册信息。
- `analysis_chat.py`和`intent_planner.py`：新增明确指令/自然入口和模型可选动作。模型必须逐字保留搜索关键词；不能把具名请求改成空词全库浏览。模型选择路径使用合成SDK验证，未做新增Schema的真实提供方调用。
- `disease_analysis.py`：原名未匹配时提供来源候选，并保留原分析参数；来源ID查询失效时不退回模糊匹配，不替换成另一条疾病。
- 页面支持搜索框、翻页和来源选择；会话只保存搜索工具、关键词、页码和目录修订指纹。目录变更会使旧搜索焦点失效，要求重新搜索。

专项8项覆盖字面搜索、顺序/分页、浏览空词、未知中文、通配字符、同名不同来源、原请求参数保留、目录变化、来源删除、缺库、输出校验及一次合成模型意图。浏览器11组通过，搜索数量和顺序与直接读取来源名的独立计算对照；包含手机/桌面宽度、来源选择、排序、刷新与旧功能回归。开发时修复了空词分页命令解析和下划线误扩大查询的问题，最终测试覆盖这两项。初次专项重复发现了导入的旧测试类，已改为模块引用，最终只计8项新增测试。

完整离线 **94模块859项通过**，跳过和网络尝试0；最终字面匹配保护专项8项复验通过。完整结果见[验收记录](../audits/disease_search_v1/summary.json)。上述是工程回归，不是疾病身份、检索语义召回率或生物学有效性评估。

## 启动与回滚

本机已验证的Python环境启动命令：

```bash
/tmp/tcm-ci-mail-env/bin/python -m scripts.preview_local_tasks \
  --port 7877 \
  --diseases var/disease_catalog_v1/build/diseases.sqlite3
```

服务已运行时直接打开页面，避免重复占用端口。该解释器位于临时目录，长期环境准备见[启动说明](PROJECT_DEMO.md#启动与复现)。本轮保持外部模型关闭。

不传 `--diseases` 则疾病工具不可用；回退本轮代码不需要数据迁移或删除会话。上一阶段疾病分析和启动修复已提交 `f02ba1a`；本轮名称搜索仍在工作区，未push、未更新Docker。

下一步转向候选排序的基线评估：检查大靶点集合偏差、相同疾病集合的等价排名与跨疾病Top-K重叠程度。没有独立标签时只报告这些诊断指标，不生成虚构预测准确率；中文别名和外部疾病ID仍需有依据的对应资料。
