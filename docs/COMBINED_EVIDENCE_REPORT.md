# 药典与现代文献证据清单

M4-04a提供按用户选择并列的Markdown清单：一部分为当前会话选定的PubMed批次书目/核查标记，另一部分复用药典本轮单药清单的原文、研究视图与原页定位。它不推断中拉药名对应、炮制品等价、复方归因或临床结论，不生成模型综述。

## 页面使用

主应用同时启用 `ENABLE_PUBMED=1` 和 `ENABLE_PHARMACOPOEIA_RESEARCH=1`，且本地药典索引/PDF可用后：

1. 在聊天中检索明确的文献式，例如 `/pubmed Astragalus membranaceus[Title/Abstract] AND randomized controlled trial[Publication Type]`。
2. 展开文献卡的“导出药典＋文献证据清单”。填写明确药名与字段，例如“黄芪的功效”。
3. 点击“下载证据清单”，得到 `tcm-research-evidence.md`。分别核对文献记录与药典物理页码/坐标，不能仅因被选入同一文件就认为两者研究对象相同。

表单不自动把PubMed名称或标题填成中文药材查询。药典查询不另发聊天轮次，因此不会先切换任务清掉文献焦点；查询由服务器从当前只读索引重新执行。未知药名、多药混问或范围外问题拒绝导出，缺项/引用未展开/炮制范围未解析等已知状态按原单药清单明确保留。

刷新或重启后可恢复本会话的文献批次卡；药典查询表单不持久化，需重新填写。切换文献批次、清除文献焦点、切换聊天任务或删除会话后，旧卡片不能继续导出。没有提供任意历史批次ID下载接口。

## 包含内容与边界

- 清单格式版本、UTC生成时间、用户选择的药典查询、药典索引SHA256、当前文献批次ID/SHA256与生成代码指纹。
- 文献原检索式、检索时间、解释式、总命中记录数、接口状态及响应SHA256；最多5篇书目。零结果、工具失败、部分获取及缺失PMID分别保留，不能包装成“没有相关研究”。
- 标题、期刊、日期、PMID链接、原DOI、来源出版类型、摘要/元数据范围、来源关系、DOI/版本提示及旧批次缺少核查状态。文献部分不导出摘要正文，查看来源摘要仍使用文献卡；未获取任何全文。
- 同DOI候选不合并，不直接计算独立研究数量。撤稿和通知方向保留，来源类型不代替质量评议，规则未命中不保证没有问题，见[文献关系契约](PUBMED_EVIDENCE.md)。
- 附带完整的既有本轮[药典单药清单](RESEARCH_EVIDENCE_EXPORT.md)：最多5个字段片段，保留OCR/研究视图、修订、审核状态、来源文档哈希、物理页码与坐标。原PDF与图片不打包。

生成时没有调用模型或外部文献接口，不自动补缺、不替换炮制品。下载文件包含用户选择的检索式与药典来源文字，应按本地研究资料管理；生成不会公开上传文件。

## 端点与会话约束

`POST /api/evidence/report`只接受以下JSON字段，无附加URL参数：

```json
{
  "question": "黄芪的功效",
  "index_sha256": "当前药典索引的64位小写十六进制SHA256",
  "run_id": "当前文献卡的32位十六进制批次ID"
}
```

页面先从 `/ready/research` 获取已验证的索引哈希。服务器要求有效签名Cookie，读取该会话焦点并比较批次ID，再从私有台账读取、核对批次哈希；客户端不能提交文献正文、聊天消息、来源路径或任意内容。最后再次检查会话修订号，期间有更新则拒绝返回“当前”报告。

返回Markdown附件，设置 `Cache-Control: private, no-store` 和 `X-Content-Type-Options: nosniff`。没有Cookie为401，批次/来源失效或修订变化为409，已过期/删除的旧凭证按原会话策略处理；未启用/存储故障为503，非法问题400、结构非法422。原 `/api/research/report` 保持原用途。

导出不保存新消息、报告或检索批次，不改变任何工具焦点；只将文件交给请求方。文献库若仍为v1，读取会按既有文献工具契约先备份迁移，见[迁移说明](PUBMED_EVIDENCE.md)。外部标题、检索式、关系备注按Markdown字面量转义，原药典引用继续使用原格式的安全文本围栏，不执行来源指令。
