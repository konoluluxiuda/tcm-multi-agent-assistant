# 有界计划与持久澄清（合成验证，2026-10-21）

后续模型验证已完成，见[合成问句规划结果](TASK_PLANNER_SYNTHETIC.md)；以下保留本轮结构化计划交付记录。

任务先明确本次查询范围和两个对象，再使用工具。缺项不是空结果，也不应通过模型猜来源。本轮提供结构化TaskPlan及待确认状态，复用现有来源/靶点确认、SQLite任务库、所有者和revision机制；不新增框架或数据库。

## 实际实现与操作

打开 http://127.0.0.1:7877/research-tasks ，在“计划与澄清验证（合成资料）”选择范围后点击“创建计划任务”。范围留空时保存`waiting_plan`，在详情中确认后才查来源。页面固定示例甲草、示例乙草，测试场景沿用上方选择。原“创建任务”和真实ETCM表单保持原流程。

`TaskPlan`版本1只允许`synthetic_only`、两个不同的合成药材，以及两种目标：

| 范围 | 所需工作 | 完成边界 |
|---|---|---|
| source_relations | 确认来源 → 共同靶点 → 用户选1–2个靶点 → 双方原始记录 | 不要求研究记录；有效空交集完成，不替用户猜靶点 |
| evidence_review | 原有来源/靶点确认 → 既有合成研究记录检索/核查 | 保留成分、对象不符、撤稿和工具不可用等缺口 |

没有自由问句解析器，不宣称本轮实现自然语言意图识别或模型规划。计划由页面或API显式提供；任意工具列表、真实药名、数据路径、外部URL等不属于计划字段。合成研究核查复用已有流程，不扩展真实文献能力。

## 状态与调用链

POST `/api/research/tasks`，`mode=synthetic_plan`，`plan={}`可创建缺项草稿。也可提交`intent`、`herb_one`、`herb_two`的部分或完整结构。服务端严格校验后保存；缺项时生成`pending.kind=plan`并停在`waiting_plan`，工具动作与调度调用均为0。

确认复用`POST /api/research/tasks/{id}/choose`：携带当前revision及恰好对应已保存缺项的selection。不能同时修改已确认字段，不能填成相同药材；非法确认不覆盖任务。确认后更新计划和names、恢复running，再进入已有引擎，分别暂停等待用户来源/靶点选择。完整计划可直接进入来源候选查询。

执行器再次按计划允许的动作校验，source_relations不能调用search_literature或inspect_study。报告显示选定靶点的双方合成原始行、确认计划、完成结果及结论边界。只保存动作/观察和用户确认，不展示或保存模型自由思维链。

GET、列表和导出不自动执行任务；`resume`不能绕过waiting_plan。使用现有匿名浏览器所有者隔离、SQLite乐观锁与查询预算。页面及本轮任务不调用外部模型、真实资料工具或联网文献。

## 文件与兼容

`tcm/task_plan.py`定义严格计划、缺项选项和确认规则；`tcm/research_task.py`接入计划暂停、工具范围和完成标准；API添加可选synthetic_plan模式，页面和Markdown展示计划与来源见证；专项测试在`tests/test_task_plan.py`。

原合成任务不补写plan，继续原研究核查完成口径；真实ETCM保持上轮v2完成语义及注册表，无真实ETCM计划或模型调用。没有任务库结构迁移。当前是Python状态机持久化，不是通用LangGraph checkpointer或多Agent规划。

## 验收、回滚与下一项

离线测试覆盖零工具暂停、缺项确认、存储重开、禁止修改已确认范围、越权和409冲突、禁止真实数据/任意工具、关系任务跳过研究检索、空交集、成分证据不足及旧任务兼容。完整回归命令：`python -m scripts.run_offline_ci --out var/task_plan_v1/ci_final`。浏览器验收包含实际预览进程重启后继续待确认计划。最终83模块735项完整离线测试通过，跳过和网络尝试均为0；15项实际浏览器检查通过，包含真实预览进程重启、计划恢复、两次显式选择、导出和旧流程回归。详细成绩见`audits/task_plan_v1/summary.json`；都是已知合成流程验收，不能计为独立真实任务准确率。

回滚需整体恢复引擎、API、页面脚本和报告formatter，保留任务库备份。旧版本不认识waiting_plan和plan确认表单；回退时须先停用新建计划入口并隔离尚未完成的计划任务，或恢复升级前任务库，不能把其状态强改为running。不要删除真实ETCM和旧合成任务。

下一项是仅用合成资料验证自由问句到严格计划的有界规划器，与明确结构化输入基线比较；缺项/歧义继续交给用户确认，不自动合并对象，不向外部模型发送真实资料。若没有可验证收益，保留确定性方案。真实ETCM接入计划仍待后续明确验收。
