# 开发变更记录

## 2026-10-12：药材查询 API 与结构化页面

在既有药材导入和查询模块上，完成独立查询页面的可用性改进。支持拼音、拉丁名、英文名查询、多个属性条件筛选、分页、同名来源选择、字段比较和出处展开。

### 本轮变更

- 修复查询按钮与浏览器 `window.name` 冲突；页面改为显式获取输入元素。
- 拒绝未知、空白及重复筛选参数，避免静默忽略条件。
- 筛选和比较保留字段原值、缺失状态、来源文件、JSON Pointer、SHA-256 与未核验警告。
- 新增按来源 ID 查询接口 `/herb-records/{source_record_id}`，候选选择不自动合并实体。
- 筛选新增 `limit/offset`，默认 20、最多 100 条，返回总数、本页数量与下一页偏移，排序固定为来源路径与 ID。
- 用结构化表格替代整段 JSON 展示；支持动态条件、分页、候选详情、字段证据展开及空结果/错误提示。
- 翻页与详情携带返回的数据版本；请求取消及序号检查避免过期响应覆盖新查询。
- 使用文本节点展示源内容，补充中文字体回退与移动端布局。
- 同步使用说明、路线图和验收报告；排除轻量虚拟环境，不提交数据库、密钥、完整原始数据或临时浏览器/字体。

### 验证

- 14 项数据层测试、11 项 API 测试通过。
- 16 项 Chromium 页面检查通过；真实 127 条筛选记录逐页访问，无重复或遗漏。
- 验证同名候选定位、来源展开、多条件 AND、中文未映射提示、空结果和页面错误状态。
- 使用模拟响应验证 HTML 不执行和服务失败提示；真实浏览器检查移动端无页面级横向溢出。
- Python 语法、文档链接及 Git 差异格式检查通过。

### 接口变化与边界

`filter_herbs()` 与 HTTP 筛选默认只返回一页；`count` 是总匹配数，调用方应按 `next_offset` 遍历。分页仍扫描整份版本数据，尚未提供跨请求的固定导入批次游标。同名比较项保持未选定，查看候选不会自动替换比较列。

中文名称映射继续暂缓，未接入原医疗聊天入口，未常驻部署或发布 Docker 镜像。下一步建立人工核对的固定查询验收集，再集成聊天入口。
