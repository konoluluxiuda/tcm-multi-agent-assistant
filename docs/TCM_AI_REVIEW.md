## 分歧如何处理

现有生产查询已经对名称查询做空白归一化，但展示值保留 NBSP；独立审核采用另一种 HTML 展示规则。先保留双方原值和理由，人工决定是否需要统一展示规范；如果改变数据或查询语义，另建候选版本，不为得到绿色结果覆盖 v1。尾空白可解释差异也保留在报告，不静默删除。

共享源数据和产品规范可能导致审核与系统犯同样的错误。源字段一致性不证明科学结论；药材实体、传统术语解释、PMID 对具体结论的支持、临床效果与安全性均未由本轮验证。

## 可重复运行

```bash
python -m scripts.review_tcm_golden \
  --source /home/zry/workspace/HDCTI/dataset/ETCM2.0 \
  --phase blind --out /tmp/tcm-independent-review

python -m scripts.review_tcm_golden \
  --source /home/zry/workspace/HDCTI/dataset/ETCM2.0 \
  --phase compare --out /tmp/tcm-independent-review
```

`blind` 只访问套件的 id/operation/input，推导并保存来源事实；`compare` 才访问 expected/records，检查套件 SHA 和源指纹绑定。默认 `all` 顺序执行两阶段。标准 JSON 解码会加载整份文件，这属于访问流程隔离，不是严格答案屏蔽；重复运行后的自动对照不能重新宣称模型从未见过答案。

退出码：0 无字面差异；1 已生成报告但有差异；2 输入漂移、绑定失败或无法完成审计。输出不得位于源目录或包含输入套件。仓库保存每题预测、全量文件哈希清单及预测路径选出的 66 条来源事实，不提交 2,076 条完整资料。

## 审计器验证与下一步

新增 9 项合成小套件测试，覆盖正确样例、错误字段、错误定位、错误结果、源漂移、盲推绑定、显式当前版本、只读边界，以及“字段存在但值为空”的来源保留。新增空值测试暴露审计器把空字段记成 present 的问题，已修复；没有修改生产系统或冻结答案。故障测试必须检出对应差异，不能仅凭命令退出异常视为成功。

该测试模块自动进入默认离线 CI；完整审计需要本地源快照，不在 CI 下载原数据。9 项测试通过意味着审计器的选定故障分支通过，不意味着本轮 8 个字面分歧被解决。
