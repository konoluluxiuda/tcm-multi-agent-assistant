# A循环：统一药典、ETCM属性与两药报告工具

2026-10-29。P0-2在原A核心上完成，不新增框架、依赖或来源库Schema。原始结果、失败与复现入口见[本轮审计](../audits/research_report_tools_v1/README.md)；后续任务只在[统一大纲](TCM_PROJECT_ROADMAP.md)维护。最新源码尚未构建镜像。

## 业务入口与实际调用链

可在聊天中直接输入：

> 比较当归与川芎的药典功效和用量，核对全部共同靶点，保留双方原始记录的位置

也支持明确的字段组合，例如“查询药典当归的功效，查询川芎的ETCM药用部位”。需要双方ETCM属性时，可在两药问题中加入“列出双方的ETCM药用部位”。

`/chat → 本地有限语法/既有单次问句提案 → 完整分句、对象及字段校验 → 来源选择 → RunScope → 原research_run循环 → 既有报告子图/本地只读worker → 缺项与双方见证校验 → 私有证据 → 摘要和对照表`。

唯一候选自动查，多候选才逐一选择。两味药分别保存选择槽位；选择时保留整条问题，不能把一侧来源套到另一侧。药典与ETCM仍按来源分别展示，没有宣布完成实体对齐。

## 统一工具契约与完成语义

`tcm/research_business_tools.py`登记八个业务工具：原五个结构化分析工具，加以下三个。证据回读、结束动作不计入这八个业务工具。旧分析API继续使用原五工具契约。

| 新工具 | 输入与复用机制 | 计入预算的读取 |
|---|---|---:|
| `pharmacopoeia_lookup` | 明确药名、1–4个药典字段，复用原文本检索 | 1 |
| `herb_attributes` | 宿主已选择的ETCM来源ID、1–12个属性，保留原值和出处 | 1 |
| `pair_evidence_report` | 两味药、双方来源ID、药典字段、可选ETCM属性及是否全量共同靶点；复用两药/单药LangGraph子图 | 默认首页最多5；全量最多14 |

两药子图先完成双方药典/ETCM四次读取，再核对来源并按页查询共同靶点；全量最多10页，每页最多20项。`action_calls`记外层动作，`tool_calls`记内部已派发读取；调用前先扣预算并保存pending。一次两药动作不伪装成一次工具读取。宿主先按最大成本准入，再按实际读取计量；例如全量需预留14次，资料只有23项时实际6次。正式本地入口总预算16，底层循环默认8未改变，直接调用者需显式配置足够预算。

成功返回工具数据不等于任务完整。宿主重算请求字段、原页锚点、选中来源、共同标识的双方见证及末页状态；字段缺失、来源不可用或分页未结束保持partial。无法完整识别的额外要求不被悄悄丢弃，也不退回只查交集。

本轮报告工具采用明确的本地词面检索和直接子进程调用，关闭该路径的向量、重排与MCP。原独立报告入口的可选检索/MCP能力保留，不能据此声称统一工具已使用这些后端。药典工具由既有`ENABLE_PHARMACOPOEIA_RESEARCH`开关控制。

## 页面、证据与中断

页面先展示请求的字段表与共同靶点总数，默认仅预览5项共同标识；原始行、哈希、执行信息折叠。完整报告沿用[私有证据外置](RESEARCH_EVIDENCE_OFFLOAD.md)，按字段读取或完整下载。读取页同时受20项与6000字节约束，必须遵循`next_offset`；大单项使用下载核对。

已保存报告可在同一会话刷新回看，不重复查库。药典索引及manifest纳入来源契约，变化时旧成功不可继续冒用。内部读取前的journal写入失败直接阻断，不会被子报告的容错逻辑吞掉。

两次真实SIGKILL边界：内部派发pending时恢复停在`uncertain_tool_dispatch`，不重发；报告已保存时恢复复用同一完整结果。当前复合动作不逐个恢复内部读取。后续P0-3已接入[新聊天网页恢复、队列、SSE和取消](RESEARCH_PLAN_LIFECYCLE.md)，有独立的队列强杀与浏览器验收；不套用旧独立报告的checkpoint成绩。
