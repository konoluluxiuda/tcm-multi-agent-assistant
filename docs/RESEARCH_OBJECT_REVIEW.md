# 研究对象线索与来源绑定的用户标注

M4-04b1先提供按需核对入口，不批准药典与文献实体一致，不生成疗效归因。仍未完成M4-04b整体的对象映射、跨药材比较或综合解释。

## 如何使用

1. 在现代文献页签检索，展开每篇“研究对象原文线索（待核对）”，查看标题或摘要提到的相关词，再自行读摘要/原文确认语境。
2. 在“导出药典＋文献证据清单”填写明确药名和字段，例如“黄芪的功效”。
3. 按需展开“逐篇核对研究对象”，勾选需要标注的PMID，选择文献对象类型与关系。可以保持未确认，不要求逐篇处理全部候选。
4. 从该篇标题或指定摘要段复制12–300个精确字符；也可点击引用按钮，再自行核对。下载清单时服务器再次确认当前会话、批次、药典查询和摘录。

对象类型为未确认、单味原药材、炮制品/饮片、复方/组合、提取物、成分；关系为尚未确认、用户认为可能相关、用户认为范围不同、用户主张一致。最后一种仍明确标记“系统未验证”，不赋予对象一致或直接归因权限。

标注只随本次Markdown文件保存，不写入服务器、会话消息、文献库或全局映射。刷新后需重新标注；修改药典查询会取消旧标注选择。现有不带标注的导出保持可用，未标注论文继续未知。

## 自动线索与限制

规则版本 `research_object_scope_v1` 在返回的标题及摘要中标出single-herb、processed、formula、extract、compound等有限词及对应中文表达，保留原词、字段、摘要段索引、字符区间和UTF-8来源文本SHA256。

线索只说明原文提到相关词，不判断该词是否为实际干预对象，也不处理否定、对照组、讨论背景和多义词的语义归属。没有线索不表示单药或对象一致；提到extract也不代表标题对象就是提取物。最多扫描标题及前20个摘要段，每段前8,000字符，每篇最多12条线索；截断会明示。原始XML字节定位不等于解析后文字区间。

该分析在读取文献卡/导出时按当前规则生成，位于tool_result之外，不修改历史批次哈希或旧书目。新旧批次均可在不重新联网的情况下得到当前线索；规则版本与原批次检索时间区分。研究类型、撤稿/更正标记仍沿用原批次来源契约。

## 服务端验证

可选 `object_reviews` 最多5条且PMID不得重复，只能标注当前会话批次前5篇。每条包含pmid、kind、relation、source_field、abstract_index和quote，不允许客户端提交批准标志、全文、来源路径或任意source对象。

`object_review_target`必须与本次question完全一致。标题不得有摘要索引；摘要索引须为0–99整数且该段真实存在；摘录必须精确包含在所选冻结标题/摘要里，不做模糊匹配或跨段拼接。导出由服务器计算来源及摘录SHA和字符区间，不相信浏览器自报的来源。

导出还重查冻结药典索引，加入药名、entry_id、原始scope和索引SHA锚点。若无本地字段锚点，则拒绝带标注的导出。炮制品/复方/提取物/成分标注明确附加不等价提示；所有标注仍是用户主张，不是经过认证的专家签核。原有Cookie、批次哈希、索引快照、会话修订和no-store附件检查保持有效。

清单格式升级为2。不导出完整文献摘要；主动添加的用户标注可带每篇最多300字符的来源摘录，其来源及哈希单列。导出不调用模型或外部网络，本地检索用于独立药典清单与对象锚点。标注不会影响真实文献库的迁移或数据结构。
