# 核心任务控制：是否需要模型

参考文献扩展冻结，原JSON、药典定位与数据版本继续作为核心资料查询依据。本次不改聊天、检索、任务页或工具，只比较已有合成任务在来源/靶点明确后，如何执行剩余核查步骤。

## 对照方法

| 方法 | 控制方式 |
|---|---|
| 确定性工具 | 既有自适应规则驱动，包含初次为空后的单次补检及所有返回记录核查；不故意削弱基线 |
| 一次模型策略规划 | 模型一次选择“空结果是否补检、是否核查返回记录”两项策略；固定解释器按实际观察执行，不猜返回ID |
| 有限工具循环 | 原生bind_tools/tool_calls/ToolMessage，模型逐步观察后决定工具动作；每题最多6次模型调用 |

三组共用 `ResearchTaskEngine`、合成工具、来源/靶点选择、身份约束和程序化报告。来源SYN-A1/SYN-B1及靶点SYN-T1由测试脚本模拟用户明确选择。前两阶段的确定性工具动作不计入比较耗时和新增动作数，但保留在任务轨迹中；每个方法整任务仍最多12个工具动作。

固定4个已知开发场景：正常记录、初次空结果、返回对象不符、工具不可用。预期前两项完成合成流程，后两项如实partial；正确保留partial属于执行契约通过，不冒充完整证据任务完成。

运行前固定题目、预期、代码副本与哈希、提示词、模型参数和调用预算。方法顺序按题轮换；总真实模型调用上限28次，无SDK重试，超时15秒。失败留在首轮，不重跑抬分。只发送虚构状态、工具参数与观察，不访问或外发真实药典、ETCM、论文、聊天历史。

一次规划只有两项布尔策略，能与规则基线相同不代表具备开放研究规划能力。有限循环的范围也是已知工具执行，不涉及自由综述、自然意图泛化或临床判断。

## 评判与复现

逐项检查预期状态、返回记录是否核查完整、来源/靶点是否保持、双方来源锚点、非法动作以及partial缺口。对象不符必须排除，成分不能记为药材本体；初次为空的题要实际补检。所有报告由同一程序生成，因此本次不能测量自由文本幻觉或引用语义支持。

记录模型调用、成功回复token用量、失败、阶段耗时及工具动作；单价未知费用为null，失败调用token可能未知。不用单次总耗时声称生产加速比、P95或统计显著性，也不与此前题集合并成准确率。

```bash
# 验证评测器，调用的是显式mock，不代表模型效果
python -m scripts.benchmark_task_controllers --out var/controller_benchmark_v1/offline_new

# 只有合成内容，经已配置HTTPS api.deepseek.com运行；输出目录必须不存在
python -m scripts.benchmark_task_controllers --live-synthetic --out var/controller_benchmark_v1/live_new
```

原始首轮保存在 `var/controller_benchmark_v1/live_01/`，离线mock在 `offline/`，二者不得混报。脚本不会读取真实任务或语料库，也不支持任意外部端点。

## 结论范围

本次是选择简单任务默认控制方式的小型开发对照，不是独立用户评测。即使三者全部通过，也只能说明在本套已知受控任务上未观察到模型的完成收益。不能由此推断复杂开放任务不需要模型。

后续应优先用现有真实本地资料验证新用户能否顺利完成明确任务，再决定何处需要模型理解或动态决策；不继续扩充文献审核体系或为增加术语添加Agent。

## 首轮真实模型结果（2026-10-21）

配置及回复模型均为 `deepseek-flash`，HTTPS `api.deepseek.com`。实际19次调用，低于28次上限；没有失败、没有修复重跑。此处只报告live_01，离线mock另存。

| 方法 | 执行契约通过 | 合成流程完成 / 预期partial | 模型调用 | 工具动作（确认后阶段） | 四题总耗时 |
|---|---:|---:|---:|---:|---:|
| 确定性工具 | 4/4 | 2 / 2 | 0 | 15 | 0.231秒 |
| 一次模型策略规划 | 4/4 | 2 / 2 | 4 | 15 | 6.318秒 |
| 有限工具循环 | 4/4 | 2 / 2 | 15 | 16 | 14.304秒 |

工具不可用C04中，有限循环在initial返回unavailable后又调用expanded，仍返回unavailable才结束。其他两组直接保留缺口；该额外步骤未提高完成情况。保留此结果，不为修好同题再运行或重新定义成绩。循环组正常题也可以批量核查两条记录，因此调用次数不简单等于工具动作数。

三组均由相同服务器约束身份并生成报告，两个partial也都符合预期，表格不是“业务准确率100%”。尤其一次规划只有两项策略选择，不能代表通用Plan-and-Execute架构的能力；有限循环没有被迫解决规则基线不知道的新分支。本次没有理由把当前默认流程改成逐步模型调用。

**决定：当前明确资料任务继续默认确定性工具；原生工具循环保留为受控实验能力，不接管现有本地ETCM/药典查询。文献获取、全文、对象审核平台、CoT展示和增加Agent均不继续扩展。** 模型的下一次价值验证应来自未见用户表达或固定流程处理不了的真实任务，而不是再造一组有利于模型的故障题。
