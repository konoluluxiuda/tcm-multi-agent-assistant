# 疾病候选排序：基线诊断（P2d）

2026-10-23，本地快照开发评测。当前排序能够复现来源集合交集，但候选重复度较高，**尚无证据证明其疾病预测有效性**。本轮未修改聊天默认算法、数据库或模型配置。

## 固定方法

先从7582条有靶点的疾病来源得到6331组不同集合，再按集合SHA-256升序取前128组，每组选择来源ID最小的一条；在计算排名前写入`protocol.json`。这是可复现的确定性抽样，不是独立临床测试集，也未按病种分层。381组相同集合涉及1632条来源，抽样时每组只占一票；药材侧保留来源记录，不把同名或炮制品自动合并。

候选池为1849条有靶点的药材来源，其他227条不参与排序。比较：

- **Jaccard**：交集除以完整并集，保留疾病集合中不在药材背景内的标识。
- **共同靶点数**：按交集大小排序。两种算法的并列顺序与生产代码一致。
- **规模基线**：不读取疾病靶点，直接按药材靶点总数降序、来源ID升序取前10条。该基线不要求与当前疾病有交集。

重合指标统一为`前10项交集数 / 10`，只比较成员，不比较名次，不命名为召回率。短列表和空列表也保留分母10；本次128组均返回10条。跨疾病指标使用128组之间全部8128对，每对一票；这些对不独立，不据此报告置信区间或显著性。

## 实际结果

| 指标 | Jaccard | 共同靶点数 |
| --- | ---: | ---: |
| 与规模基线Top10的平均重合 | 62.58% | 82.03% |
| 不同疾病集合间Top10的平均重合 | 58.54% | 80.97% |
| 所选候选靶点数中位数（1280个排名位置） | 299 | 317 |
| 128组中的不同首位来源数 | 20 | 12 |
| 最常见首位来源出现次数 | 64 / 128 | 76 / 128 |
| Top10累计不同药材来源数 | 121 | 49 |

候选池靶点数中位数为43，规模基线前10项中位数317。两种排序彼此Top10平均重合74.69%。最常见首位来源的拼音标签为`FuPenZi`；标签按原记录保留，不等于已完成中文药材身份审核。

本次疾病集合大小中位数299，范围10–379；每组背景外标识平均5.62个，每组有交集的药材来源平均1738.55条。这些数据说明许多集合覆盖较广。Jaccard相对共同靶点数降低了结果集中程度，但仍明显偏向大集合。**这些观察尚不能分离集合大小、共有高频靶点、疾病本身相关性和来源重复的影响**，更不能以候选更分散证明预测更准确。

相同输入集合必然产生相同排名，改换排序公式也无法让完全相同的输入具有不同疾病含义。来源的物种、关联证据等级和上游预测质量尚未独立核验。当前能力应描述为“基于来源靶点集合的候选检索”，疗效、作用方向、剂量和临床适用性均未评估。

## 实现、验收与复现

实现为`tcm/ranking_diagnostics.py`与`scripts/eval_disease_ranking.py`，只依赖标准库及现有只读目录模块。读取基础库/增强库来源映射、疾病绑定的背景版本与指纹；样本靶点集合重新计算SHA；运行前后核对DB/WAL状态。结果写入全新目录，拒绝覆盖旧实验。发生版本不一致或输入变化时不写完成报告。

前8个固定样本的两种排序分别与生产`rank_sets`对照，16份Top10顺序全部一致。专项测试覆盖分母、空集、并列、固定抽样、背景外标识、只读性、复现、拒绝覆盖、背景错配和快照变化。专项8项、完整离线95模块867项通过，跳过与网络尝试均为0。结果见[验收摘要](../audits/disease_ranking_v1/summary.json)。本轮未更改页面，未新增浏览器验收或模型调用。

运行命令（需当前项目环境；`--out`必须尚不存在）：

```bash
python -m scripts.eval_disease_ranking \
  --database var/tcm/herbs.sqlite3 \
  --enrichment var/research_update_20261020/runtime_catalogs/catalogs/enrichment.sqlite3 \
  --diseases var/disease_catalog_v1/build/diseases.sqlite3 \
  --out var/disease_ranking_v1/run \
  --sample-size 128 --top-k 10
```

本次使用`/tmp/tcm-ci-mail-env/bin/python`运行，耗时11.024秒。这里是单次离线批评测时间，包含16份生产排序对照；不是聊天延迟或服务容量测试。输出为：

- `protocol.json`：计算排名前冻结的抽样规则、样本来源、集合指纹与数据版本。
- `rankings.json`：逐样本两种排名及覆盖计数，保留在本地`var/`。
- `summary.json`：聚合诊断及源指纹；可提交副本位于`audits/disease_ranking_v1/`。

## 下一步与回滚

后续进展：P2e已完成，128组×256次随机对照未见最大共同靶点数超过各自随机第95百分位，见[完整结果](DISEASE_SIZE_NULL_EVALUATION.md)。下段保留P2d时的实验计划；当前下一项为聊天候选结果解释。

P2e优先做**按集合大小匹配的随机对照**：固定背景、随机种子、样本和计算预算，判断观察交集超出随机规模预期多少，并单独保留药材背景外标识。先作为离线对照，不自动加入聊天，不把随机富集分数解释为疗效概率。若仍显示共有高频靶点主导，再比较逆频率加权。

128组现已成为开发集；后续公式如用其调优，验证需另冻未参与调优的集合。来自同一上游的留出集合仍不是独立生物学真值，预测有效性最终需要独立证据标签和清晰任务定义。

本轮无线上行为改变，无数据库迁移。回滚只需移除新评测脚本、纯函数和文档引用；已生成实验目录可保留用于对照，原库和聊天数据不受影响。
