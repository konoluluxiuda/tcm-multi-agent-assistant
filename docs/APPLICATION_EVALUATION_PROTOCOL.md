## 下一项实现要解决什么

本地dense对照已暴露两个目标：把“使用风险”识别为当前资料的注意字段，把“今天卖多少钱”识别为当前知识库范围之外。它们现在都是已知开发题，修复后只能算回归。

源码已增加显式任务类型和规范字段输出，并继续复用工具的实体/炮制品守卫；有歧义先澄清，不靠向量兜底强行返回药材正文。现有字符串计划只约束查询条数，无法核对任务/字段选择；新格式使这一判断可以逐题检查，但任务选错或字段漏选仍可能发生。合成模型替身与真实本地检索器的工程检查，以及8条真实模型合成规划烟测已通过。没有旧提示同题模型对照或新格式真实药典任务成绩，尚未证明业务收益；下一步比较未见题上的规则与模型结果，避免预先假定模型一定更好。这8条合成题也已成为开发题，不能并入未来独立验收成绩。

## 新题如何准备与冻结

建议一次准备24题，每类4题：用途改述、存储/用量/属性等字段改述、多字段且其中一项缺失、无对象或歧义、价格/诊断等超范围任务、炮制品和多来源区分。它是小样本业务筛查，不用于估计总体医疗准确率。

1. 在下一轮调参前写原始问题、题目来源（设计或真实记录）、期望任务/字段、允许状态、验收条件和来源定位。期望值从固定来源核对，不能拿被测程序输出当答案；资料缺失时记录缺失，不补造功效。
2. 与上表逐条对照，去掉相同问题及仅替换药名的近重复；按问法模板、任务和炮制品组隔离。已有药名可以复用，但不得把实体已见解释成实体泛化。记录人工检查范围，文本去重不能证明语义独立。
3. 写入一个新版本JSON，保存题集/参考/索引指纹、模型及参数、提示词/源码版本、调用预算和评分规则；通过Git或独立存档固定。工作区未提交时，额外保存实际源码副本或差异，不能只记录HEAD。
4. 未参与调参的人提供并保管问题，才能进一步说明作者独立性；由本人另行设计的未运行题只能称前瞻保留集。当前没有收集到这样的新题，本文件不假称已创建或通过独立验收。
5. 固定版本一次运行并保留所有原始结果；看到失败后可以修复，但这批题随后进入回归，新版本效果验证另取未见题。无需另建审核平台或强制全量专家签核；临床正确性不属于本轮工程评分。

## 同题比较与评分

先比较当前确定性入口与模型工作流。使用相同问题、数据快照和可用来源；独立检索实验与完整回答的结果分别报告。外部模型测试继续受已有数据发送授权约束，本协议不会授权额外调用；无法运行的项目记为not_run。

| 指标 | 判定方式 |
|---|---|
| 任务/字段选择 | 对照事先固定的任务类型和允许字段集合；计划选对与工具最终取对分开记 |
| 任务完成 | 全部满足该题验收条件才算完成；partial、合理澄清/拒答、错误和not_run分别列出；缺字段但诚实说明不等于完整回答 |
| 来源支持 | 引用定位、短句存在、短句相关与陈述支持分开核对；ID存在和原文子串检查不替代语义判断 |
| 范围与身份 | 是否错误回答超范围任务，是否混入别的药材/炮制品；逐题保留失败 |
| 代价 | 端到端与阶段耗时、模型调用数、输入/输出token；未知单价费用记null，不把离线回放时间当推理时间 |

分别报告每个方法的完成数/已运行数及已运行数/计划数，避免跳过失败题提高成绩；报告分组计数而非合并成一个“准确率”。单次运行只描述本轮延迟，不声称稳定P95。评判人及其是否参与调参须注明；AI自查只能作为开发判断，不能冒充独立人工审核。

停止条件：能用逐题结果解释模型在哪些任务有收益、在哪些任务增加成本或失败，并据此选择默认行为；随后录制已有5分钟演示并用于投递，不再默认扩充题库或技术栈。
