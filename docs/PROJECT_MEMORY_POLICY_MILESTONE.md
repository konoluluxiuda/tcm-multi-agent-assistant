2026-10-27。本轮完成上一轮诊断中的三项修复：自然语言找回项目、明确药材约束、完整项目列表。技术路线不变，没有外部模型调用。

## 用户可见行为

- “以前那份白术配茯苓的资料在哪里”“当归、川芎的资料还没整理完”等问法进入本地项目记忆。
- “找之前黄芪的研究项目”：已知目录识别到黄芪，但当前用户没有保存该药材项目时，返回无匹配，不用其他药材项目凑候选。
- “列出所有研究项目”：直接读取当前用户的完整列表（项目存储现有上限20个），不走向量阈值或Top-K；不配置嵌入模型也可使用。
- “继续当归项目，这次看白术的贮藏”：先用历史部分找当归项目；选择后按本次白术与贮藏要求填写报告。不会把新对象当成旧项目筛选条件。
- 选择列表中的项目使用保存的研究问题，不把“列出所有项目”写进报告。
- 普通药材问答、短期追问保持原有入口；找回项目仍需选择候选，选择本身不创建执行任务。

## 实现与边界

`tcm/project_semantic.py`负责意图边界、历史/当前要求分离、目录名称约束及列表分支；SQLite仍是所有权和版本的权威来源。本地BGE/Qdrant/RRF只处理剩余的语义检索，阈值与权重未调整。`app.py`与`tcm/research_runs.js`显示列表数量和无匹配提示。目录缺失时只能约束已保存项目内的名称；目录外别名、任意复杂否定和指代仍不保证识别。

列表是读取时的快照，应用时继续检查owner和revision，已删除或已改版本不自动应用。没有实现真实账号或跨设备身份共享。
