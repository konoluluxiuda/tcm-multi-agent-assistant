## 调用与失败处理

`tcm/task_planner.py`的NativeTaskPlanner通过当前LangChain SDK bind_tools提交一个submit_task_plan工具；最多一次invoke，期望恰好一个合法工具调用。TaskPlan仅允许两味合成药材、两种意图和synthetic_only模式，输入长度1–400字符。不允许源ID、靶点、任意工具或路径；不执行模型自由文本，不保存自由思维链。

超时或服务错误返回unavailable；缺少调用、多调用、非法字段/真实药名/重复药材等返回invalid_output。两种失败均保留问句中明确出现的合成对象、将目标留空，进入用户审核；不自动重试、猜范围或执行工具。异常正文不进入记录，避免泄露URL或凭据。

有效输出若补出未提及药材，移除该字段并要求用户确认；原始计划与处理后计划分开记录。评分分别统计原始与约束后的匹配，防止把程序修正当模型正确。对象按集合评分，因为本任务两侧对称；不把顺序差异误算语义错误。

## 提案到持久任务

create_proposal复用现有任务引擎，保存proposed_plan、plan_origin和plan_review_required。所有提案都进入waiting_plan，三个字段均展示建议值供用户显式提交；用户可以修改提议范围和对象，原提案保留。确认后仍分别选择来源和靶点。执行器拒绝在review_required为真时调用工具。

列表/GET不触发规划，确认、刷新、工具执行不会再次调用模型；API及页面显示已发生的provider_calls，不把SDK替身计为真实外部调用。Markdown同时保留原提案和最终确认的计划；历史结构化计划、原合成任务与ETCM任务不改写。

这是单次模型生成结构化草案＋确定性解释器＋显式用户确认，不是通用多Agent自主规划、CoT展示或LangGraph通用checkpoint。网页没有自由问题输入，也没有新增模型调用API。

### 尚未解决的两个模型失败

- A11要求比较甲、乙、丙三味。模型仍选择source_relations，但两个对象字段都为空，没有按预设保留已支持的甲乙并表达第三对象不支持。当前两个固定对象槽不能完整描述三对象请求。
- A12同时要求共同靶点和药用部位并排表。模型返回甲乙的source_relations，遗漏额外交付要求。药用部位在其他聊天工具中可查，但当前TaskPlan不能表达该复合任务；仅完成来源查询不能算完整满足原请求。

两项都停在提案审核，没有自动调用资料工具；这是确认机制的约束，不代表模型已经正确识别全部范围。当前schema没有未支持对象/子任务的显式字段，也没有“原请求全部覆盖”的完成门槛。

下一项P0应补请求覆盖契约：记录原请求的对象和交付项、未支持/未覆盖项；不能覆盖时明确澄清或由用户确认缩小范围，避免以一个合法枚举静默替换整个请求。先在合成资料上验证，不能只追加A11/A12关键词修补提示词，也不能把本轮失败改成同题修复后再称独立效果。是否需要扩展更多对象/工具另按实际需求判断。本轮不实施修复，保留当前核心冻结。
