# 大结果外置＋结构化回读：隔离原型

> 后续进度（2026-10-29）：本原型机制现已接入[正式A循环](RESEARCH_EVIDENCE_OFFLOAD.md)。下文“尚未接入”、旧配额/工具范围及下一项描述保留原实验阶段含义，原始成绩不改写。

2026-10-28。完成最小机制验证，未修改聊天入口、正式执行层、大纲或项目依赖。

## 结果

合成画像含14000个标识，格式化JSON为406597字节。完整JSON结构存入独立SQLite，上下文仅使用614字节的证据索引；含当前问题和消息包装后987字节，最新观察也能落入实验16000字节预算，不必等待其变成历史观察再压缩。

这不是token或费用下降结论。原始格式化空白不保留，JSON结构、字段和值保持一致；哈希基于规范化JSON。来源ID、数据版本、目录版本、原始证据ID和内容哈希随索引/回读返回。单条payload限制4MB。

13项测试通过；写入子进程正常退出后，由另一个子进程读取并校验完整结构，准确找回第7000项合成标记。外部模型调用0次。这里是正常退出重启，不是SIGKILL验收。

## 实现

- [EvidenceStore](../experiments/architecture_candidates/evidence_store.py)：宿主绑定owner/run，opaque句柄查询，不接受文件路径；同一运行的同一证据ID不可覆盖，重复写入相同内容返回原句柄。
- payload和索引元数据同一SQLite事务保存，只有提交成功后才返回句柄。
- 回读先验证归属、内容哈希和来源版本，再复用现有 `read_run_evidence` 字段、offset和limit规则；输出额外携带句柄与内容哈希。
- 搜索/画像Schema继续使用现有Pydantic模型，错误观察不生成外置引用。

测试覆盖跨owner/run、未知/路径句柄、版本变化、内容损坏、不可变ID、回读边界、存储上限、错误数据库、符号链接、实例重建、写入前失败与SQLite实际INSERT失败回滚。测试文件见[13项测试](../tests/test_evidence_offload_candidate.py)。写入失败未返回句柄且记录数为0；未模拟磁盘断电或SQLite提交I/O故障。

## 尚未完成的边界

该存储是独立组件：调用者显式put，尚未按阈值自动接入 `research_run`。因此正式循环目前仍会拒绝原有上限之外的观察，不能说聊天已支持400KB结果。

未接入journal与备份：若证据提交后、执行状态提交前进程退出，可能留下未引用记录；还需设计引用发布/恢复、清理和总存储配额。不能把此前模型循环强杀结果套用到本存储。此次没有运行并发写入压力或跨进程锁竞争测试。

owner来自可信宿主，不是独立HTTP身份认证；数据库是私有可信状态，不防管理员同时改正文与哈希。索引只保留来源声明，不证明医学对象映射正确。当前每次回读会载入并校验整条payload，4MB以内可做原型，后续需按实际规模评估开销。

## 下一项应验证什么

在隔离执行适配器中加入入上下文前的大小判定，超限保存证据并返回索引；将回读接入同一工具协议。冻结来源及存储版本并关联journal，验证“证据已提交/运行状态未提交”和“引用已提交/恢复回读”两个强杀边界，确认不会出现悬空引用或重复工具派发。

这一原型支持借鉴B的大结果外置机制，同时保留A的结构化出处；尚不支持最终选型或修改大纲。
