## 当前行为

直接输入以下问题，不需要进入任务页核对清单：

> 查找Synthetic disease的来源，读取全部靶点原始记录，再按Jaccard列出前五个药材候选，保留出处

实际疾病原名应以本地目录为准，`Synthetic disease`是本轮合成验收名称。

也支持药材的多项结构化查询，例如：

> Alpha的靶点画像，查找与Beta靶点最相似的药材，前5个

将示例名换成本地记录中的药材名称。唯一中文候选沿用现有来源解析，不能视作药材身份已核验；炮制范围不被自动缩短。

- 完整命中的本地多步骤语法直接生成计划，0次外部模型调用。
- 未完整命中的复合分析问句，在已启用`ENABLE_INTENT_PLANNER`时，复用现有单次`submit_query_intent`，增加`analysis_plan`提案类型。仅发送当前问句与静态协议/Schema，不发送ETCM内容、会话历史或工具观察，不自动重试。
- 提案包含固定工具、原句对象和分句编号；宿主检查分句覆盖、完整对象、排序指标、数量和“全部原始记录”，然后解析真实来源ID并生成`RunScope`。明显漏项或缩成单任务会停下澄清。
- 来源唯一时直接查询；多来源或非精确疾病匹配才展示选择按钮。选择命令仅能使用本会话当前选项，选择后按完整原问题创建新执行，不称为断点续跑。
- 结果默认展示简洁摘要和候选表格；原始记录、JSON位置、来源和执行详情折叠。没有每行重复免责声明或默认展开哈希。
- 会话只保存计划、来源选择和run引用，不保存靶点数组或原始行。完整结果进入现有owner隔离的RunStore，刷新/“出处呢”读取保存结果，不重新调用工具或模型；数据版本变化时提示重新查询。
- 药材单独分析不再依赖配置疾病库。worker同时固定宿主的`TCM_DATASET_VERSION`，避免选中的数据版本在子进程内变成最新批次。

## 调用链

`/chat → 现有路由 → 本地解析或单次意图提案 → 分句/对象校验 → 本地来源解析 → RunScope → 既有A循环 → 五个工具 → 要求完成检查 → RunStore → 页面摘要/表格/折叠出处`。

这属于**模型辅助意图解析＋受控本地执行**。当前执行使用声明式驱动按已验证观察解锁依赖；没有开启把真实工具结果回传外部模型的自主循环，不能描述成完整自主科研Agent。分句覆盖检查也不能证明模型对任意语义都理解正确，仍需独立业务集评测。

旧单项分析、共同靶点查询和已有任务/报告入口保留。共同靶点交集不属于本轮五个工具，继续走已有关系查询；没有将复杂交集任务错误当作药材画像执行。
