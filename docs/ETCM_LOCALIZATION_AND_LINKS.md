## 现在如何使用

2026-10-20当前增量：关系结果已具备会话焦点。选择来源后可以追问“这些成分对应哪些靶点”或“出处呢”；刷新及重启会按来源和页码重读结果。后文“仅保存摘要、需重发原问”的说明属于此前阶段，当前以[关系焦点说明](#关系焦点与重启恢复2026-10-20)为准。

本机入口为 http://127.0.0.1:7875/ 。保持“AI整理回答”未勾选：

1. 输入`/herb 白术`，查看来自药典拼音标题的中文名称候选；点击“选择此来源”。候选不自动合并为药典中的白术。
2. 查看中文字段及括号中的英文原值。白术的`Root`显示“根”，不擅自改为药典中的“根茎”。未知术语的机器译文默认折叠，并标注未审核。
3. 展开“来源中的关联记录”，按类别每页查看20条。白术来源有307条成分记录，可查看原始关联行、JSON Pointer及抓取状态。
4. 点击“同标识或名称分组的其他药材来源”中的按钮，跳转到另一条ETCM原始药材记录。每行最多展示5个其他来源，不表示全部相关药材。

中文候选以显式ETCM查询为入口；普通“白术的功效”仍可走药典工具。没有候选的药材继续用原拼音或来源ID查询。

在项目根目录、已安装研究聊天依赖并配置模型的环境中启动：

```bash
python -m scripts.preview_evidence --port 7875 --with-local-research --with-local-herbs --etcm-enrichment var/etcm_enrichment_v1/data/enrichment.sqlite3 --etcm-source /home/zry/workspace/HDCTI/dataset/ETCM2.0 --etcm-targets var/etcm_target_links_v1/targets-paths.sqlite3
```

本机已验证的临时Python为`/tmp/tcm-ci-mail-env/bin/python`。`--etcm-enrichment`要求同时启用`--with-local-herbs`，启动时核对版本及基础数据库SHA。省略此选项只查询原基础数据。其他服务可显式配置`ETCM_ENRICHMENT_DB`，其资料记录仍逐条核对来源SHA。

`--etcm-source`可选，要求同时指定`--etcm-enrichment`，用于按需读取原始成分文件。省略它仍可查询已有关系，但不显示成分详情按钮；启动器会清空继承的`ETCM_SOURCE_ROOT`。不要使用药材来源指纹不同的另一份快照。

`--etcm-targets`同样可选并要求`--etcm-enrichment`，启用已核对的靶点→成分索引；省略会关闭该方向，其他查询不变。启动时核对派生目录的版本和药材来源指纹，不把旧目录用于不同快照。

上述查询、翻译结果展示及关联查询不调用模型。AI整理仍固定使用合成资料，没有扩大真实资料外发授权。旧7873容器不变。

## 翻译范围与限制

| 处理方式 | 实际数量 | 含义 |
|---|---:|---|
| 词表中文对照 | 9904个字段实例 | 药性、药味、归经及部分部位、科属、产地、分类等；未知组合不作部分翻译 |
| 本地机器译文 | 3514个字段实例，2264个不同待译值 | CPU离线翻译，全部未人工审核；仅供对照，不用于实体合并或临床判断 |
| 保留原始标识 | 7914个字段实例 | 拼音、科学名称及引用标识等，不编造中文药名 |
| 中文药名候选 | 520条药材来源记录 | 基于已有药典OCR标题的规范化拼音匹配，有条目、标题块和原页出处，身份未核验 |

以上字段计数不是药材数量。其余1556条来源记录没有中文药名候选，继续保留拼音；不能宣称2076个药名均已可靠汉化。候选来自词面对应，不能跨过基原、部位、炮制品差异自动合并。

机器翻译使用[Argos公开英中1.9模型](https://argos-net.com/v1/translate-en_zh-1_9.argosmodel)，推理由CTranslate2和SentencePiece在本机完成，技术来源见[Argos项目](https://github.com/argosopentech/argos-translate)。模型包SHA256固定为`433e7c4f034d87fbe2353161e05f18646d7999452f801a4e1f0378522b9850ab`。实际试译出现过中药术语误译，因此不作为默认主答案，也没有人工质量通过率。

所有关系保留药材来源ID、原始行、JSON Pointer及抓取状态；`skipped`或部分抓取不会被改成完整。疾病富集不是适应证，靶点关联不证明结合或作用机制，中成药/方剂收录不证明疗效。此实现是可追溯的SQLite关联目录，没有引入Neo4j或MCP。

## 成分文件标识与直接靶点记录

当前7875已启用原始ETCM目录的按需只读访问。保持AI未勾选，发送“白术有哪些成分”，选择来源后，在某条成分记录中展开“查看成分标识与直接靶点记录”。它会读取已有文件候选，核对内部名称、分子式和分子量，展示来源声明的CAS、PubChem CID及原始字段位置。

文件名只用于定位候选，不足以确认身份。名称比较保留`(+)/(-)`等符号，分子式区分大小写，分子量使用十进制数值比较；任一字段冲突、缺失或重复时不展示为可对应的化学标识。三项一致也仅标记“来源字段一致，化学身份未验证”，不确认结构、立体异构、外部数据库身份或临床作用。多个PubChem CID全部保留，不任选一个，也不据此合并实体。界面的PubChem链接仅在用户点击后打开，工具不联网查询或加载外部结构图。

真实样本：白术关联的`(-)-alloaromadendrene`成分文件与药材行的三项字段一致；文件声明CAS `25246-27-9`和5个PubChem CID。界面保留这5个值及文件SHA、双方JSON位置，不把它们解释为5个已核验的等价实体。

抽查的`(-)-alloaromadendrene`、`(-)-aromadendrene`和`Atractylenolide_I`文件只列出药材/方剂关联，没有直接靶点表，因此目前不能据此建立完整的“药材→成分→靶点”链。页面明确显示“未记录直接靶点表”，不会把药材的靶点复制给每个成分。若其他文件确有`related_table/type=target`，只展示该文件直接收录的表、抓取状态及最多10条原始行；网络图图例不作为靶点关系依据。

读取接口为`GET /api/etcm/ingredient?source_record_id=…&edge_id=…`，不接受任意文件路径。服务先核对药材原始文件SHA、派生库版本及关联行归属，再从目录中的已知候选读取；每次最多3份候选，每份最大32 MiB。越界路径、目录外符号链接、超限文件和来源变更均停止或标记不可用；缺少候选不推断不存在该成分。原始文件、本地基础库及派生关联表均不被修改，也没有全量导入大型成分目录。

普通服务默认关闭此功能，需显式配置`ETCM_SOURCE_ROOT`和`ETCM_ENRICHMENT_DB`；源码预览使用上方完整命令。身份依据和化学标识只显示在当前详情卡片，不写入会话记忆。Docker未更新，换机需另行配置资料挂载。
