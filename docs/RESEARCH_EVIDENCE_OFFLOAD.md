# A循环的大结果外置与按需回读

更新：2026-10-29。本轮将隔离实验机制接入同一个`tcm/research_run.py`，没有增加生产框架、第二套循环或模型请求。完整原始验收见[本轮审计](../audits/research_offload_production_v1/README.md)。本地代码接入不代表Docker镜像已经构建发布。

后续P0-2已将同一外置机制用于药典/ETCM属性/两药报告，当前八个业务工具及新验收见[报告工具统一](RESEARCH_REPORT_TOOLS.md)。下文1173项是外置阶段历史成绩。

## 现在的调用链

`聊天/本地研究API → 宿主绑定owner与run → 本地工具worker → 完整Schema/来源/分页校验 → 小结果内联或大结果提交私有SQLite → 发布摘要与引用 → 原A循环完成校验/受限回读 → 页面结果与运行记录`。

新多步骤聊天仍由声明计划驱动；可选模型只提出一次问句计划，不收到真实资料。本轮模型动作—观察—回读链路使用合成SDK验证，不宣称真实DeepSeek已端到端完成该业务。

## 限制与出处

| 对象 | 当前策略 |
|---|---|
| 内联阈值 | 规范化JSON超过16000字节即外置；这是本地字节策略，不是token计量 |
| 完整单条返回 | 最多4000000字节；源工具仍有业务分页/查询预算，不保存未查询的数据库内容 |
| 已外置payload配额 | 每run 16000000、每owner 64000000、每证据库256000000字节；事务内核对，含未发布记录；不是磁盘预留或SQLite文件大小保证 |
| 模型回读 | 原`read_run_evidence`动作，计入原工具预算；每次1–20项，offset为0–100000，数据页最多6000字节 |
| 浏览器回读 | 同会话鉴权，零模型请求；每次1–20项，遵循`next_offset`，不是重新查询来源库 |
| 完整下载 | 每份已接受观察的JSON，最大4MB；不把全文放回聊天上下文 |
| 证据内容 | 完整JSON结构、字段和值；不保留原序列化缩进/键顺序。SHA256基于规范化JSON |
| 保留政策 | 不按时间自动清理；删除本会话已终结的研究运行时清理对应外置内容。未发布记录保留并计入配额，不能从孤立记录推断任务已经完成 |

这里只保存**完整工具返回**。例如疾病资料返回完整靶点标识集合和当页最多20条原始行，下载并不意味着数据库全部原始行已被读取。要求全部原始行时仍逐页执行，预算不足保持partial。单项记录超过回读页预算时明确提示，使用完整下载核对，不静默截断。

模型不能指定文件路径、owner或run。回读只选择当前运行已有观察ID；服务器解析opaque句柄并核对归属、观察ID、内容SHA、数据版本和来源绑定。`rows`、`target_ids`、`items`是允许的字段；候选集合的`shared_ids`、`query_only_ids`、`candidate_only_ids`和`evidence`还需明确`item_index`。这些是读取已接受结果，不是自由执行JSON路径、SQL或代码。

## 页面和API

大结果卡片先显示摘要/预览，完整内容默认折叠。在“完整证据（按需查看）”选择字段，使用上一页/下一页；也可下载该观察的完整JSON。刷新同一会话时恢复同一run，不重新查询。来源文件或证据缺失、损坏、版本改变时拒绝旧成功结果，不自动拿新来源替换。

```text
GET /api/research/runs/{run_id}/evidence/{obs_id}?field=target_ids&offset=0&limit=20
GET /api/research/runs/{run_id}/evidence/{obs_id}/download
```

使用服务签名Cookie鉴权；跨会话/未知观察返回404，无效参数422，来源/证据变化409。页面展示的数组可能是预览，不能据其长度判断完整集合规模。完整证据位于运行库同目录的`evidence.sqlite3`；不是源资料库，也不能作为可删除缓存。

无宿主owner/run绑定的底层`run()`仍保留48000字节护栏。正式聊天/API会传入私有证据上下文；显式业务scope的`run_durable`自动绑定。较早的无scope合成循环保持原内联行为与迁移恢复契约，不因这个功能额外绑定证据路径。

## 发布与恢复

运行先记录pending和已消耗预算，再查工具。证据提交后才发布引用；引用与工具消息保存完成才进入ready。证据库与运行journal是两个SQLite文件，没有联合原子事务。

| 故障位置 | 恢复行为 |
|---|---|
| 证据已提交，引用未保存 | uncertain_tool_dispatch，停止；记录保留，不重新查询或推断发布 |
| 引用已保存，等待后续回读 | 验证引用后继续，不重复资料查询 |
| 下一动作已保存，尚未执行 | 复用保存动作，预算不重置 |
| 已发布内容丢失或损坏 | partial/evidence_unavailable；聊天回看与API拒绝旧成功，不用预览伪装完整证据 |

每次执行/回读持有证据库共享活动锁；清理要求独占锁，活跃时拒绝删除。没有自动删除未发布证据的后台任务。后续P0-3已交付[新聊天队列、取消和受控恢复](RESEARCH_PLAN_LIFECYCLE.md)，并另做真实队列强杀与浏览器验收；本阶段执行层成绩不代替后续入口成绩。

## 备份与回滚

已有`backup_runtime`增加`--runs`和`--evidence`，需与原memory/projects及一种job后端一起使用。停止并排空写入后，例如：

```bash
.venv/bin/python -m scripts.backup_runtime backup \
  --memory /path/to/memory.sqlite3 --projects /path/to/projects.sqlite3 \
  --jobs /path/to/jobs.sqlite3 --runs /path/to/research_runs.sqlite3 \
  --evidence /path/to/evidence.sqlite3 \
  --out /path/to/new-backup --cookie-name your_cookie_name --workers-stopped
```

若还包含业务循环journal，另加`--loops`。备份及检查会验证已发布引用；缺证据文件、错误归属、内容损坏或悬空引用直接失败，不输出表面成功的备份。恢复到新目录后，已完成研究记录可回读；必须保留签名Cookie及来源配置。显式业务journal将证据路径/策略纳入执行绑定，换路径、框架或代码后不能强改绑定继续运行；此处不承诺任意路径迁移续跑。

无来源库Schema迁移、无新增依赖。回滚应先停止新运行，保留运行库和`evidence.sqlite3`；旧版程序不认识外置引用，应使用对应版本回看已有外置结果，不能只删证据库或将预览冒充原返回。

## 验收范围与剩余问题

新增19项开发测试覆盖存储、配额、只读worker、五工具大结果执行、原生tool_calls回读、归属/伪造引用、落盘/损坏/版本失败、HTTP、删除和配套备份。另用真正SIGKILL测试三个发布边界，用真实Chromium验证折叠、分页、下载与刷新。全量离线回归为138模块1173项，0跳过、0联网尝试；原始失败见审计目录。另在7896既有本地ETCM上运行当归画像与川芎前5相似来源，2次工具调用完成，21189字节相似度结果成功外置、回读、下载SHA核对及同run刷新恢复。离线/浏览器/强杀用临时合成资料，实际数据烟测仅在本地，所有环节外部模型调用0。

尚未验证真实模型对长资料的语义选择、独立业务收益、实际token/计费下降、并发压力、整机断电、多机共享存储或公网服务负载。完整payload的回读每次仍会加载并核验该条JSON，4MB上限内有界，后续应按实际压力评估流式/字段索引方案。
