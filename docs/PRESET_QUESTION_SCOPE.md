## 五类问题

| 类别 | 首批支持内容 | 固定输出 |
|---|---|---|
| 1. 单药字段查询 | 指定一味药的ETCM字段或药典字段 | 药名、请求字段、资料值、出处；缺值明确标注 |
| 2. 多药同字段查询 | 两三味药查询同一组字段 | 按药材分别回答，字段齐全，不擅自生成文件 |
| 3. 跨来源查询 | 明确ETCM与药典各要哪些字段 | 分来源列出值和出处，不把来源差异合并成一个结论 |
| 4. 关系查询 | 指定药材的成分或靶点记录 | 沿用已有分页展示，说明范围，不声称穷尽 |
| 5. 固定模板表格 | 明确药名、来源和字段，要求生成表格 | 使用现有XLSX模板，列出请求字段与出处，保留缺项 |

“当前能做什么”“介绍两个数据库”“数据概览”沿用已有固定入口，不新增理解流程。表格追加保留已有功能与修复记录，暂不作为本轮必须完成的主流程。两三味药是首批走查规模，不是新增的运行时数量限制。

## 业务背景与一次完整交付

业务定位：面向中草药资料整理人员的本地资料核对与研究数据准备。收到药材清单后，从ETCM与药典查找指定字段，保留来源差异、缺失和歧义，交付可以回查出处的固定模板表格。这是项目定位与使用验收方案，尚未经过独立真实用户研究，不声称已有商业客户或测得效率提升。

人工基线通常需要逐条查资料、复制字段、补记出处并检查是否遗漏；本项目将这些步骤组织为有来源和状态的交付。候选药名匹配不等于身份审核，资料整理结果不用于替代诊疗决策。

| 使用步骤 | 本轮已有问题 | 交付检查 |
|---|---|---|
| 收到白术、黄芪清单，先核对资料字段 | Q01、Q02单药查询；Q03多药同字段 | 每个对象和请求字段都出现；缺项明确说明 |
| 核对数据库与药典各自的记录 | Q05、Q06跨来源 | 值和出处按来源区分，不将差异自动裁决为对错 |
| 查阅关联记录 | Q07、Q08关系查询 | 显示当前页和范围，不把第一页称为全部 |
| 整理给下一位资料核对人员 | Q09、Q10固定表格 | 下载真实XLSX；对象、字段、状态、出处与请求一致 |
| 回查与复核 | 已保存会话、任务及产物 | 刷新后能找到结果；缺失、身份候选及来源限制可见 |

复用下方原问句与现有结果，不另造一套更容易通过的题目。以上步骤可以分次执行，不承诺将它们合并成一个开放自主任务；Q09、Q10分别交付对应来源的表格，不假装已生成统一跨来源总表。

后续真实试用只需记录同一范围内的人工耗时、系统操作耗时、遗漏字段、错误对象/来源、必要与不必要澄清、最终文件能否使用。没有测量的值写“未测量”。工程测试数、预设走查通过率、真实用户任务完成率分别报告，不互相替代；当前13条仍是已见开发例子。

## 直接用于走查的例子

每类两条，共10条。使用同一数据版本与入口检查；问句和资料内容都不因失败而临时修改。以下是开发验收例子，不是独立泛化评测集。

| 编号 | 问题 | 必须检查的结果 |
|---|---|---|
| Q01 | 查看白术的ETCM药用部位和科名。 | 两个字段及出处，不能只给其中一个 |
| Q02 | 查看黄芪的药典功能与主治和用法与用量。 | 两个药典字段，保留来源范围与缺失 |
| Q03 | 分别告诉我白术和黄芪的ETCM药用部位。 | 两个对象各自的值和出处 |
| Q04 | 分别查询丹参和连翘的ETCM科名、性味、归经。 | 两个对象；性味包括药性和药味 |
| Q05 | 查询白术的ETCM科名和药典功能与主治。 | 两个来源均回答并注明出处 |
| Q06 | 查询黄芪的ETCM药用部位和药典用法与用量。 | 不漏字段，不混淆来源 |
| Q07 | 查看白术的成分记录，先显示一页。 | 成分记录及来源，分页范围明确 |
| Q08 | 查看黄芪的靶点记录，先显示一页。 | 靶点记录及来源，不误称全部 |
| Q09 | 把白术和黄芪的ETCM科名、药用部位生成表格。 | 可下载XLSX，只包含请求的资料字段，不补药典默认列 |
| Q10 | 把白术和黄芪的药典功能与主治生成表格。 | 可下载XLSX，不补ETCM默认字段，缺失如实保留 |

另查3条边界：

- B01“帮我查一下”：询问药名和需要的资料，不猜对象。
- B02“查询不存在的药材名XYZ的药用部位”：说明没有匹配来源，不编造记录。
- B03“替我诊断症状并开处方”：说明超出资料查询范围，不提供诊疗方案。

名字有多个候选时允许要求选择，资料缺失时允许明确报告缺失；不能把错误绑定、漏字段或无文件的HTTP成功记为通过。确实缺少该药材来源时记录为资料覆盖不足，不偷换成别的药名。表格的来源ID、状态和出处列属于固定模板说明列，不算擅自新增的资料字段。

## 开发规则与暂缓项

- 沿用本地解析和已有可选单次模型理解，模型只识别类别、药名、来源和字段，执行使用既有工具与固定流程。当前默认仍是 `local_then_one_model_v1`，不提升W为默认。
- 类别内信息不足时只问缺失信息；用户可用页面字段选择或明确模板补齐，不通过增加模型轮数解决所有问法。
- 超出范围明确告知；若有适合的固定模板，可以说明模板选项，不能默默缩小用户要求。
- 暂缓任意列顺序、任意格式、开放多工具组合、自动多轮规划、全量关系导出、扩大策略对照及未见题泛化研究。
- “药名第一列”暂不扩展为通用契约；展示现有固定模板说明。不把历史HV2-32改判通过。
- 已有额外功能和实验代码保留，不为缩小范围进行大规模删除或重构。

## 实际连续追问补充（2026-11-05）

13条固定问法不能代表实际连续对话已完整覆盖。按用户原例补充以下顺序：

1. “分别告诉我白术和黄芪的属性”：记录两个对象，询问具体字段。
2. “分别告诉我白术和黄芪的性味”：使用ETCM药性、药味字段，逐药返回出处。
3. “给出白术和黄芪的相关信息”：保留对象并询问需要哪些资料。
4. “这两个草药的性味是什么”：从本会话最近一轮恢复两个对象，查询药性和药味。

对象提及不代表身份核验或工具执行成功。无上下文、指代数量不匹配、对象来源不唯一时保留澄清；明确新对象优先。现有W工具反馈流程可接收此上下文，默认部署仍关闭模型。见[连续对话修复](../audits/conversation_scope_v1/README.md)。
