# 项目记忆第一阶段：显式背景复用

2026-10-26。参考用户提供的《虚构 Agent 项目的架构设计与面试追问》后，后续计划改为围绕真实任务完成记忆、证据核对和对照实验，再复用工具接入MCP。保留Python、LangGraph、FastAPI、Qdrant、DeepSeek路线；不引入文档中未经核验的插件框架，不采用虚构规模或提升数字。

## 本轮功能

聊天页 → 本地研究 → 研究项目记忆。保存项目名、一到两味药、关注问题；列表显示全部已保存字段，可编辑、删除或点击“用于报告”。选择项目后填入单药/两药报告表单，用户可修改本次问题，再手动提交现有后台报告。没有自动发起模型或资料查询。

示例：项目名“当归资料整理”、药材“当归”、关注问题“功效及贮藏”。之后刷新页面，选择项目即可再次填入，不需要重新输入。报告仍从本地资料读取出处，项目文字不作为药学证据。

## 实现与边界

- `tcm/project_memory.py`：独立SQLite项目库；类型及长度校验；最多20个项目/owner；事务内revision比较，防止并发编辑覆盖。删除后旧版本无法重建记录。库标识与schema版本校验，拒绝误用其他数据库。
- `tcm/project_memory_api.py`：CRUD与按ID显式召回；沿用签名Cookie身份，owner哈希隔离、同源写入检查、响应no-store。未启用后台研究入口时返回404。
- `app.py`：挂载路由并将精确项目API路径纳入资料查询模式允许范围。
- `templates/index.html`、`tcm/research_runs.js`：列表、编辑表单、显式选择、报告预填；提交前重新检查已选择项目是否存在及revision。修改本次报告不会隐式修改项目。
- 默认库在会话库同目录`research_projects.sqlite3`；可配置`RESEARCH_PROJECT_DB`。不迁移已有会话库，不向PostgreSQL来源表写入项目偏好。

这是**显式项目背景持久化与精确选择**，不是语义召回、自动长期事实抽取或自主规划。可跨刷新、浏览器重新打开和服务重启，但需要保留原Cookie及服务器会话签名库；清除会话/Cookie或换设备不保证找回，不是账号体系。项目资料不自动外发。

删除项目不删除已经生成的报告、已复制的问题或备份；研究历史需单独删除。提交前的浏览器检查用于提示过期背景，不是跨项目库/任务库的原子事务。用户明确填写的报告参数仍是执行依据。

## 验收口径

单元/API验证：重开数据库、owner隔离、四连接并发编辑仅一方成功、过期版本拒绝、删除后无法召回或旧写入复活、数量上限、Schema/字段校验、跨站写入拦截。主应用验证资料查询模式允许项目操作且仍禁止其他写入。

真实浏览器验证：创建→刷新→选择→生成当归贮藏报告并核对来源字段→其他浏览器隔离→编辑→过期选择拒绝→重新选择→删除→刷新后不再召回。首轮发现主应用中间件遗漏项目写入白名单，已修复；不能仅用独立路由测试代替主应用验收。

固定流程对照：不使用项目时填写模式、药材、问题共3项；保存后点击一次项目选择可预填3项。这里只证明一个已知场景减少重复输入，不报告业务准确率、时间节省百分比或语义召回收益；项目创建及维护也有成本。
