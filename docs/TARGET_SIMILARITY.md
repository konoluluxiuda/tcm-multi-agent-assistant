# 药材靶点画像与来源集合相似度

更新：2026-10-23。P1 已实现，运行入口为本地源码预览 http://127.0.0.1:7877/ 。本轮未提交 Git、未更新 Docker。疾病候选排序与新靶点预测仍未实现。

## 使用

```text
白术的靶点画像
哪些药材与白术的靶点集合最相似？列前10个，并显示共同靶点和依据。
与白术靶点最相似的药材，按共同靶点数排序，前5个
回看分析结果
```

默认前10项、最多20项。唯一药材候选直接查询，多来源时才选择；炮制品与未找到的名字不自动替换成普通药材。表格展示来源、Jaccard、共同靶点和候选集合大小。共享/独有标识和来源说明默认折叠，可点击“核对双方原始行”。也支持 `/analysis profile BaiZhu` 和 `/analysis similarity BaiZhu --top-k 5 --metric common_count`。

## 实际调用链

```text
POST /chat → 已有安全与明确指令检查 → 本地完整问法匹配
  → 未识别时可选的一次模型意图提取 → QueryIntent 校验
  → LangGraph assistant 节点 → analysis_tools.execute_turn
  → 本地药材来源解析 → 注册工具参数校验
  → target_similarity.query 只读事务 → 输出Schema校验
  → 页面结果表格 + 会话参数持久化
```

模型仅收到当前问句和静态工具定义，不收到资料或历史；不执行模型生成的 SQL/Python，也不将分析结果发回模型。两个工具共用固定注册表，能力名称与模型工具说明由此生成。沿用 Python、LangGraph、FastAPI、Qdrant、DeepSeek 技术路线；本功能计算结构化关联，不依赖向量检索或新的框架。原研究任务工具保持原接口，尚未完成全工具统一、MCP 或模型循环自主规划。

主要文件：`tcm/target_similarity.py`（只读集合算法）、`tcm/analysis_tools.py`（严格参数/输出与调度）、`tcm/analysis_chat.py`（自然问法与明确指令）、`tcm/intent_planner.py`（模型意图）。接入已有路由、LangGraph 节点、关系焦点恢复及 `templates/index.html`。

## 数据与计算

- 来源为现有 `TCM_DB` 与 `ETCM_ENRICHMENT_DB`，不新增索引，不改原始 JSON。先核对两个目录的整个来源ID/哈希映射、数据版本与所选来源。
- 使用来源明确提供的 UniProt 标识集合，同一来源去重。画像同时保留原始行数、重复标识行数、无可用标识行数和抓取状态。
- Jaccard 为 `共同标识数 / 双方标识并集数`。另一排序方式为共同标识数量；并列按另一指标和来源ID稳定排序，使用精确分数比较。
- 排除自身、空集合及无交集来源；空记录列为未覆盖。不同来源即使名称相同也不合并，不能将来源条数当去重药材数。
- 当前快照共2076条来源，1849条有明确标识，227条未覆盖，962个不同标识。白术来源为253个去重标识、269条原始行，其中15条重复标识行、1条无可用标识行。
- 来源靶点相似度不等于药效、作用方向或疗效相似，也没有生成新靶点预测。来源证据层级、中文实体身份与抓取完整性仍有限制。

数据库有10秒查询进度预算；这不是整个HTTP请求的严格超时承诺。当前同步读取、没有结果缓存或批处理队列；大规模数据和多用户并发性能尚未评估。

## 记忆与版本

复用已有SQLite会话检查点，只保存分析工具、来源ID、排序/数量参数及目录修订指纹，不存整批靶点结果。刷新或“回看分析结果”按当前目录重新计算。数据、目录文件或算法版本变化会使旧焦点失效，要求重新查询；另一个会话不能继承该焦点。本轮已验证页面刷新与重新打开记忆存储对象，不将其宣称为已做真实进程重启专项或账号长期记忆。

只读事务和查询前后文件指纹用于检测并发资料变化。原始JSON哈希在验收时抽查，运行时不每次重读全部原文件；输入资料应由现有构建流程生成、核验并整体切换。无新数据库迁移。

## 验证与已知失败

完整离线回归 **91模块、831项通过**，跳过和网络尝试均为0。完整结果见[脱敏记录](../audits/target_similarity_v1/summary.json)。本地私有原始结果在 `var/target_similarity_v1/`。

- 数学/工具/聊天测试覆盖去重、空集、同集/不相交、并列、排序切换、输出计数、同名多来源、炮制范围、未知输入、数据缺失、旧版本、记忆隔离及无模型执行。
- 最终浏览器11组检查通过，包括桌面/手机宽度、折叠来源、查看双方原行、参数恢复与数据库介绍回归。Top10 Jaccard 和 Top5 共同靶点数与独立SQL对照；查询来源及前三名共4份原始JSON核对哈希和完整集合。
- 首轮浏览器完成9组后在真实模型改述断言失败，未保存该条完整响应。经用户追加授权诊断1次，捕获模型选对工具和前5项，但同时在 `analysis.arguments.name` 与 `entities` 填入“白术”，被互斥格式校验拒绝。
- 修复仅接受这两处完全相同的单一对象并归一化；不同对象、额外字段/任务及缩短炮制名仍拒绝。捕获参数通过离线回放，合成图调用验证归一化后可执行本地工具。修复后没有新增真实模型调用，故不宣称真实提供方端到端重测通过。
- 本功能开发累计2次真实模型意图调用（首次浏览器1次、授权诊断1次），未发送药典/ETCM资料或历史。中间单独测试命令漏设离线环境导致初始化失败，使用正式隔离运行器重跑；失败记录保留。测试和开发修复不能替代独立用户问句准确率或生物学有效性评估。

## 回滚与下一步

本轮没有数据迁移或原始资料写入；回滚时恢复本轮模块及路由/页面接入，并保留会话数据库，不能用整个工作区重置来丢弃此前未提交修改。`ENABLE_INTENT_PLANNER=0` 可只关闭模型兜底，规则入口仍可用；如需回滚整个分析功能，应回退相应代码，当前没有独立分析功能开关。旧代码无法解释新焦点时重新查询；旧聊天与研究收藏不需要清空。
