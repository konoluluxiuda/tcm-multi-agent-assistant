# 药典自动切分与可续跑提取试验

本轮完成 M2-01 的批量处理前置：9 页 OCR、10 个自动识别的条目候选、跨栏跨页接续、饮片/附属标准分节、逐页缓存与中断续跑。这里只验证工程行为；没有完成全书提取、人工批准或正式聊天 RAG 接入。

## 本轮范围与结果

固定计划见 [页面计划](../eval/pharmacopoeia_batch_pilot_v1.json)：434 页扫描件 PDF 24–29，加 2058 页扫描件 PDF 76–78。两组来源分别处理，不能把两份扫描件的内容直接拼成一条记录。印刷页码经本轮读图登记，仍待人工签核；不按固定偏移推算全书页码。

| 项目 | 实际结果 |
|---|---|
| 页数 | 9：复用 5 页旧 RapidOCR，新增识别 4 页 |
| 条目候选 | 10；8 个止于下一标题，2 个仍缺后续边界 |
| 未闭合候选 | 人工牛黄、山茱萸；保留内容并标记待补页 |
| 子节 | 饮片单独保留；人工牛黄的 5 个附属质量标准分节 |
| 续跑 | 首轮新增 2 页后停止；第二轮命中 7 页缓存、补 2 页；最终重跑命中 9 页缓存、新增 OCR 为 0 |
| 稳定性 | 同一最终解析代码连续两次重跑，entries.json SHA 完全相同 |
| 审核状态 | 全部为机器候选，人工批准 0；全文准确率、边界准确率不填数值 |

10 个候选名：一枝黄花、丁公藤、丁香、八角茴香、人工牛黄、大蓟炭、大腹皮、山麦冬、山豆根、山茱萸。名称来自 OCR，不是 ETCM 名称映射或实体合并结果。

“找到下一标题”仅表示本规则找到了结束位置，不能证明字段完整或识别正确。最终两个未闭合项即使含有贮藏段也不自动判定完成。

## 自动边界规则与一次真实失败

按左栏后右栏、栏内纵向排序。条目起点要求同栏邻近的中文名、含小写的拼音、1–3 行大写拉丁名，以及“本品为”或“本品由”来源开头。保留原始文字、置信分数、坐标、物理页码、印刷页码和原始页面结果 SHA。

新页面识别前读图登记了 [AI 视觉观察](../eval/pharmacopoeia_batch_visual_v1.json)：PDF 26 有八角茴香、人工牛黄两个起点；27–29 没有新的独立条目。初版只支持“本品为”，漏掉“本品由……”开头的人工牛黄，将它接入前条目。修复后两个起点均检出，附属标准未被拆为药材。**这些新页面已参与修正规则，不能再称独立留出集，也不能据此声称 100% 边界准确率。** 下一批必须使用未参与调规则的页面。

页首边栏文字与底部页码候选另存排除记录；裸数字仅在更低的外侧页脚位置才排除，不按底部高度统一截掉正文。疑似剂量、页码或标题仍可追溯到未改写的 OCR 行。大蓟炭在 PDF 76 有完整标题组合，应保留为条目候选，并非无标题续文。

“饮片”不作为新药材；其用量、注意、贮藏等字段与正文分开。附属质量标准也另设范围。子节不继承或臆造独立来源/拼音/拉丁名；重复字段仍保留并标记，未实现炮制品的规范实体映射。

## 使用方法

在仓库根目录使用已有 RapidOCR 环境（依赖见 requirements-ocr-pilot.txt）：

```bash
/tmp/tcm-ocr-sample-20261016/bin/python -m scripts.batch_pharmacopoeia_pdf \
  --reuse-ocr-dir var/pharmacopoeia_pdf_benchmark/rapidocr \
  --reuse-prepared var/pharmacopoeia_pdf_benchmark/pages \
  --max-new-pages 2

# 继续处理剩余页；已经导入/识别成功的页面不必再次提供旧结果目录。
/tmp/tcm-ocr-sample-20261016/bin/python -m scripts.batch_pharmacopoeia_pdf

# 只使用现有缓存；没有缓存的页面记为 pending，不算已完成。
/tmp/tcm-ocr-sample-20261016/bin/python -m scripts.batch_pharmacopoeia_pdf --max-new-pages 0
```

也可不传复用选项，直接对计划中的页面执行新 OCR。首次无缓存时须保证模型已经在本地；本命令不下载模型，Python socket 网络调用在推理期间被阻断（不等于操作系统级网络隔离）。本轮未调用付费接口。

输出默认在忽略目录 `var/pharmacopoeia_batch_pilot/`：

- `ocr_cache/`：逐页原始 OCR 与来源指纹、推理配置、内容校验和、复用/新识别来源说明；不随字段规则改动而重新 OCR。
- `pages/`：新识别页的本地证据图；旧页面图仍保留在原基准目录。
- `state.json`：已成功缓存页面的文件 SHA；原子写入，进程中断后复用已落盘的成功页面。
- `entries.json`：自动切分内容、字段候选、子节、未闭合状态和排除行。
- `recipe.json`：包版本、模型 SHA、分栏/BGR/线程/检测尺寸/渲染设置。
- `summary.json` 和 `runs/`：最新运行摘要与每次成功返回的运行记录；校验失败会抛错退出，不能用旧摘要证明新运行成功。

原子替换按单机单文件写入设计，不承诺断电恢复或事务式整批发布。每个输出目录使用 OS 文件锁，避免两个进程同时写入。原生 OCR 单页异常会记录失败，后续重试不重跑成功页；失败页、物理页不连续、已知印刷跳页、来源变化都会中断条目接续。开头无标题的续文另存，不能强塞给后面的新药材。

来源 PDF、缓存文件、计划或推理配置校验失败时拒绝续跑。修改页面计划或推理配方应换新 `--out` 目录，保留原试验；本版没有跨输出目录的共享缓存管理。**只修改切分/字段代码**可以在相同计划和 OCR 配方下重建条目，输出记录两份解析源码 SHA。若改变渲染实现，必须升级 renderer_recipe 并使用新输出目录。

复用的五页通过计划中预先固定的原始结果 SHA、旧报告/预处理元数据和图片 SHA 校验。旧实验没有保存模型指纹，因此明确记录 `models_at_original_run: not_recorded`，不会用本次模型指纹倒推旧结果的模型身份。

## 验证与下一任务

新增 12 项测试覆盖跨页接续、跨来源/跳页阻断、无标题续文隔离、双行拉丁名、饮片与附属标准范围、人工牛黄来源、页脚/剂量保护、坐标异常、缓存损坏、计划变更、部分处理、失败重试及无操作续跑。另有实际九页的分两批处理和最终缓存重跑记录，见 [脱敏审计](../audits/pharmacopoeia_batch/)。

本轮完整离线回归 **182/182** 通过（21 个模块、0 跳过），结果见该目录 offline_ci.json。第一次沙箱内回归在既有 Starlette TestClient 事件循环挂起，已中止；随后使用相同的阻网离线脚本在沙箱外重新检查，保留环境限制记录。

下一步选取未参与开发的章节前/中/后页面，覆盖长条目、更多炮制品、表格、异常标题、空白和印刷缺页，扩大到约 30–50 页并登记漏切、误切、跨药串接和源缺页。先冻结规则，再独立核对起止位置；不要求人工逐字段校对全书。对明确异常和抽样条目保留复核，之后再分批跑完整“药材和饮片”。

目前字段部位词表仍是早期有限词表；标题跨栏/跨页断开、识别错误、特殊版式可能漏切。相同 OCR 或相同机器结果不是正确性的证明。本轮候选未接入四药研究索引、正式聊天或 ETCM；其机器质检仍需单独适配和验证。原 PDF、ETCM 数据库未修改。
