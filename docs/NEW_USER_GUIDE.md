# 新用户使用说明与示例问题

新增[资料任务页](RESEARCH_SELECTION_AGENT.md)：7912与Docker7914的 `/dataops/research` 可输入任务问句，或用表单指定候选、字段和数量。可直接试：

- “整理白术和黄芪的功效、注意事项，保留出处并生成表格”：两味均保留，缺失注意项如实显示。
- “增加贮藏，保留旧字段”：接续当前结果生成v2，原文件保留。
- “从白术、黄芪、川芎、甘草、大黄中挑两条功效和注意字段齐全的”：按字段完整性挑选，当前为甘草、大黄。

默认先做完整的本地解析并确定性执行。当前7912已配置统一模型兜底：聊天与资料任务页在未完整识别时最多补一次理解；页面的允许模型选项默认勾选，可取消，规范问句仍可零调用。7896/7914未启用目标模型，保持本地解析。模型只接收当前问句、名称候选、字段/工具定义及父表结构，不发送资料正文或聊天历史；查询直接回到原查询链，表格进入工作区。歧义、越界或模型提案不合格时说明原因，保留原句，不静默执行半个任务。见[统一理解与Harness验收](../audits/unified_harness_v1/README.md)。

API的 `use_model` 省略或为 `null` 时沿用部署开关；`false` 强制仅本地解析，`true` 允许本地未识别时的一次模型补充，不强制每题调用。该限制仅指目标理解；另行启用的RAG生成和native执行有独立预算。多轮Agent仍为显式实验，不保证所有任务都能执行；旧评测失败保留。

执行统计中，`decision_steps` 是本地策略或模型的决策步数，`provider_requests` 才是执行阶段的外部模型请求数；一次问句理解另计于 `goal_provider_requests`。未知请求数显示为 `null`，不算作0。工作区 `mode` 区分 `research_fixed`（确定性）、`research_synthetic`（本地模拟）与 `research_native`（多轮模型）；队列尚未记录驱动时显示 `execution_pending_or_unknown`。历史检查点的内部字段保持兼容，API展示采用上述名称。

聊天返回的顶层`model_calls`及`assistant.understanding_requests_this_submission`表示本次提交新增的理解请求，重放为0；`assistant.llm_calls`按`counts_scope`表示原工作区或理解结果累计值，两者不混为重复付费。

以上字段层级适用于聊天的资料任务响应，例如首次理解后的重放：

```json
{"model_calls":0,"assistant":{"understanding_requests_this_submission":0,"llm_calls":1,"counts_scope":"workspace_total","replayed":true}}
```

`understanding_requests_this_submission`不在聊天顶层；普通查询的理解回执在`routing`内。队列忙碌返回429及`Retry-After`，工作区标为`queue_busy`，表示已保留目标但尚未入队。使用同一Cookie、同一`request_key`和原始请求重试，会复用目标与理解回执；队列仍忙时继续429，不再调用模型。字段、对象、来源版本改变时返回409，需要核对后新建。旧版的`queue_not_enqueued`失败记录未证明属于忙碌，不自动恢复或重发。

`/api/runtime`的`source_revision_scope=research-application-v3`表示共享服务源码摘要，可跨本地进程和镜像比较；预览启动脚本由`entrypoint_revision`另行记录，未打包进研究镜像的旧影像/RAG/文献子模块由`optional_modules_revision`记录。`restart_required`检查三部分是否漂移。相同服务源码摘要不代表模型开关、数据版本或部署参数相同。

“挑选齐全记录”没有合格项时会直接说明“0条满足”及已保存的排除原因；`partial` 和空表如实保留。指定对象核对仍保留缺失行。引用资料页若模型结果与原文逐字一致，会明确提示本次没有改变展示内容；可选“查看原文”避免生成调用。此提示不是模型效果评分。

## 直接调用资料工作台 API

API按会话隔离任务。先访问页面取得Cookie，再用同一Cookie调用；没有初始化会话时返回401是预期行为。以下命令只列出当前会话的任务，不创建任务、不调用模型；端口按部署调整：

```bash
umask 077
curl --fail --silent --show-error --cookie-jar /tmp/tcm-session.cookies \
  http://127.0.0.1:7896/dataops/research --output /dev/null
curl --fail --silent --show-error --cookie /tmp/tcm-session.cookies \
  http://127.0.0.1:7896/api/dataops/workspaces
```

`POST /api/dataops/research-questions` 和 `/api/dataops/research-tasks` 同样需要该Cookie。若发送 `Origin`，必须与访问地址的协议、主机、端口一致，例如 `Origin: http://127.0.0.1:7896`。Cookie文件应仅供自己读取；丢失Cookie后新会话不能读取旧会话的任务，勿向他人分享。

新增可选[引用资料页](RAG_CITED_ANSWER.md)：7912/rag可查看原文，或点击整理进行一次有界引用生成；7896/rag只看原文。普通聊天与表格模式保持原配置；完整范围、外发与失败回退见该说明。

同日后续复核已修复7896旧进程问题，并统一单药多字段直接查询、普通关系查询的唯一候选读取；页面资源支持离线加载，API正文含有界原文与出处。7896沿用原疾病目录及手动工作台配置，7912保留模拟动态模式；两个端口的配置不同，详见[新用户走查与修复](NEW_USER_QA_20261030.md)。

2026-10-30能力核验：聊天支持“当前能做什么”“目前能做什么”“现在支持哪些任务”，菜单按当前开关及本地文件配置显示。它是入口说明，不是所有任务已运行成功的证明。已更新的7912实例使用本地模拟模型，可整理表格并追加字段；真实LLM自主整理仍未验收。疾病目录默认未加载，自由问法仍有漏识别，详见[本轮实际结果与限制](../audits/capability_verification_v1/README.md)。

## 先试这几类问题

每行作为一条消息发送。示例用于上手，部分已参与开发测试，不是独立评测集。

| 需求 | 可复制的问题 | 预期结果 |
|---|---|---|
| 了解能力 | `当前能做什么`、`你能做什么` | 按当前开关和资料配置展示可用入口及限制 |
| 介绍资料 | `介绍两个数据库` | ETCM与药典各自内容和用途，不要求药名 |
| 数据数量 | `数据概览` | 当前索引计数；来源记录数不等于药材种数 |
| 药材属性 | `我需要查看白术的相关属性` | ETCM属性及来源 |
| 指定多项属性 | `查看白术的药用部位和科名` | 按ETCM分别展示字段与出处，缺字段时保留缺项 |
| 资料能力 | `药典的数据能查到哪些字段` | 介绍药典字段与用途，不要求药材名称 |
| 药典字段 | `黄芪有什么作用` | 功能与主治原文候选及出处 |
| 连续追问 | 接上一题发送`用量呢`、`出处呢` | 沿用已识别对象；新会话需先明确对象 |
| 成分记录 | `白术有哪些成分` | 来源收录的成分行，可分页核对 |
| 共同靶点 | `我在整理当归与川芎，想核对共同靶点，并保留双方原始记录的位置` | 共同UniProt及双方原始行；普通查询无需核对请求清单 |
| 靶点画像 | `白术的靶点画像` | 当前来源的去重靶点及缺失情况 |
| 相似来源 | `哪些药材与白术的靶点集合最相似？列前10个，并显示共同靶点和依据` | 集合相似度、共享标识及依据 |
| 疾病目录 | `浏览疾病目录`、`查找疾病 diabetes` | 来源名称、ID和后续查询入口；需启用疾病索引 |
| 多步骤查询 | `当归的靶点画像，川芎的靶点画像` | 同一计划执行两个画像，返回各自结果和出处 |
| 多工具查询 | `当归的靶点画像，查找与川芎靶点最相似的药材，前5个` | 画像与相似来源分别展示，不丢弃一项要求 |
| 药典对比 | `比较白术和黄芪的功效与用量` | 分药材、分字段原文对照及证据导出 |
| 跨来源研究 | `比较当归与川芎的药典功效和用量，核对全部共同靶点，保留双方原始记录的位置` | 同一任务返回属性对照、全部交集及双方记录 |
| 多种资料字段 | `查询药典当归的功效，查询川芎的ETCM药用部位` | 按资料分别返回字段原文与出处 |

有多个ETCM候选来源时，核对名称、部位和来源后选择；普通关系查询的完整目录只有一个候选时可直接读取，中文身份仍标待核验。显式`/relations`指令保留手动指定来源的用法。查询结果缺字段或没有记录时会保留缺项，不自动补造。不要把示例中的结果数量当作所有数据版本的固定答案。

## 如何阅读和保留结果

多步骤研究先返回“研究任务已排队”，随后更新进度和结果；关页不会取消。结果先显示摘要或表格。“查看”“来源与说明”等折叠区保留原始行、JSON位置、文件摘要或药典原页。需要引用时展开核对，不必逐项阅读内部执行信息。大结果显示预览；两药共同标识默认预览5项。打开“完整证据（按需查看）”分页读取，或下载完整JSON。每页最多20项，同时受6KB上限约束，实际项数可能更少。刷新保留原运行；证据丢失或来源改变会提示重新核对，不自动查询替换。见[证据保存与读取](RESEARCH_EVIDENCE_OFFLOAD.md)。

普通共同靶点查询默认展示首页。两药报告明确要求“全部共同靶点”时支持受控分页，当前上限10页、每页20项；预算不足保留已读结果并标记未完成，不把部分结果说成全量。该报告现已作为受控工具接入新多步骤聊天。全量任务先按最高14次读取检查剩余预算，实际按派发次数扣减；无法容纳时不开始该动作。见[报告工具统一](RESEARCH_REPORT_TOOLS.md)。

新多步骤聊天覆盖八个业务工具：原五个结构化分析，加药典字段、ETCM属性、两药证据报告。文献检索、任意下载任务、治疗或预测等要求仍未纳入统一计划；证据下载只是读取已完成的工具结果。规则未识别时，默认本地预览会说明限制；只有显式启用意图模型时，才可能发送当前问句进行一次提案，不发送资料或会话历史。

“本地研究”面板可生成单药/两药报告；`/research-tasks`保留较早的任务清单流程，用于明确计划和来源核对，不是普通聊天查询的必经步骤。

## 会话、收藏与项目记忆

- 同一浏览器、同一状态目录可恢复已完成消息和来源焦点；清理Cookie或换浏览器不会自动同步账号。
- 研究收藏需手动保存。笔记是个人记录，不是新的药学证据；清空聊天与删除收藏是不同操作。迁移前先导出收藏备份。
- 项目记忆保存明确填写的研究背景；语义候选检索需另外配置本地模型，不是默认自动记住全部历史。
- 新多步骤查询在后台执行，同一会话刷新可查看进度和结果。点击“取消任务”才结束任务；中断后可点击“恢复已保存步骤”。若上次调用是否执行不确定，会保留部分结果并停止，不自动重查；数据、代码版本变化也会拒绝恢复。见[后台执行与恢复](RESEARCH_PLAN_LIFECYCLE.md)。

## 遇到问题

| 现象 | 操作 |
|---|---|
| 页面打不开 | 核对启动输出和端口；本地预览7896与Compose默认7872是两种配置 |
| 提示未启用 | 联系管理员检查功能开关、索引和挂载；改问法不会自动开启功能 |
| 问法不识别 | 写全对象和字段，或使用下方明确指令；保存原句供排查 |
| 来源多于一个 | 选择本次查询要使用的来源，不直接默认同名资料属于同一对象 |
| 刷新后结果失效 | 核对资料版本、会话Cookie和状态目录，重新查询 |
| 已有研究任务运行 | 查看原任务进度或取消；重复提交不创建第二个活动任务，原任务焦点保留 |
| 中断后不能恢复 | 核对来源/代码版本和执行预算；已取消任务不能继续，未知派发不会自动重试 |
| 两窗口修改冲突 | 刷新后核对最新记录，不直接覆盖另一窗口的修改 |
| 系统报错 | 保留原始问句、请求编号、时间和操作步骤交给管理员 |

```text
/research 黄芪的功效
/herb BaiZhu
/relations 靶点药材 Q07973
/relations 靶点成分 Q07973
```

当前服务用于资料研究。来源靶点、相似度和疾病候选排序不能证明新靶点、作用机制或个体治疗效果。更完整的限制见[统一大纲](TCM_PROJECT_ROADMAP.md)；管理员演示与故障验证见[演示指南](PROJECT_DEMO.md)。
