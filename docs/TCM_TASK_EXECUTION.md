## 运行

使用 [离线CI环境](OFFLINE_CI.md) 的依赖：

```bash
python -m scripts.eval_tcm_tasks \
  --source /home/zry/workspace/HDCTI/dataset/ETCM2.0 \
  --out /tmp/tcm-task-execution.json
```

默认采用真实 API 的 ASGI 传输。若需检查已运行的药材服务：

```bash
python -m scripts.eval_tcm_tasks \
  --base-url http://127.0.0.1:7863 \
  --out /tmp/tcm-task-execution-http.json
```

HTTP模式仍需要本地数据库校验快照绑定；服务readiness版本/记录数和返回来源也必须符合预期。它不等于证明远程整个数据库与本地逐字相同。可用 `--db` 和 `--suite` 指定路径。

退出码0：自动检查运行完成且没有失败，仍可包含partial、人工未运行和未支持项；1：自动检查失败；2：数据/来源/版本等前置条件不满足，或运行中输入变化。输出路径不能覆盖候选、数据库或进入源目录。

## 真实性与边界

- 检查真实HTTP 400/422、字段值/缺失、歧义、来源指针/哈希/原值、分页和完整筛选ID集合。
- 未知expected键明确记为unverified，不能直接复制expected充当actual；科学结论、界面可见性和完整任务目标仍由人工判断。
- 从段落锚点核对字段时，解析候选保存的原始段落值，再核对字段原值与来源键；不改写预期。
- 默认CI使用临时JSON与SQLite测试执行器及故障分支，不执行私有快照上的60题。
- 单轮顺序API检查的均值/p50/p95仅供排查，包含分页等额外请求，不代表用户响应时延或容量。报告中模型调用为0、模型API费用为0，总系统成本未知；不把机器与人工成本填为0。
- 报告保存候选SHA、执行代码提交与源代码SHA、工作区是否有改动。运行时执行器尚未提交，报告如实标为dirty，不冒充已发布镜像结果。

## 失败记录与下一步

独立复核另发现：COMPARE-05 的文字提到缺失格，但所选预期字段均存在，因此不能用该题证明“比较表缺失格展示”能力。该事项记录为候选质量待审，不为增加通过数改题；其他缺失题继续单独检查。

下一步人工执行3条页面任务，复核9条partial与候选目标是否充分，收集真实使用题；之后再冻结正式任务基准和评测口径。本轮工程结果不替代M1-06人工签核或真实业务成功率。
