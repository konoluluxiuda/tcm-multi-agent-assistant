# 普通聊天复用字段请求解析

2026-10-25。本轮把上一阶段报告入口的有限字段解释接入普通聊天，不需要 `/research` 前缀，也不需要打开报告面板。本轮没有新增外部模型调用，仍为本地确定性资料查询；不是开放问题规划器或自主Agent升级。

## 调用链与改动

`/chat` → `assistant_router.resolve` → 共享 `bounded_field_request` 识别完整问法 → 既有LangGraph药典工具节点 → `ResearchTool.execute` → `ResearchService.search` → 只读索引 → 字段组织 → 原文与出处展示。

- `report_request.py` 新增完整句式中的实体提取，复用上一阶段的保存/用途语法及字段词表。提取的是用户写出的完整名称，不把酒制、胶囊或其他复合名截成母药材。识别只负责路由，实际名称、炮制范围、多药问题仍由检索工具校验。
- `assistant_router.py` 在自然药典字段入口补共享解析，传递原句。显式ETCM、文献、比较和既有命令入口保持原路由优先级。
- `mineru_chat.py` 将解析后的检索问句交给原有service；基于检索器确认的字段检查输出覆盖，最多展示5项。唯一明确的优先字段稳定排在前面；未知或有歧义的优先要求不强行排序。
- 会话保存原句对应的已解析对象问法，“出处呢”重新执行同一句解释与查询，不回填虚构正文。解析模块指纹加入会话绑定，版本变化会使旧焦点失效，需明确药材重新查询。
- `research_bookmarks.py` 保存该指纹；`bookmark_backup.py` 验证可选指纹格式。旧备份仍可导入，但没有新指纹的旧焦点属于过期状态，不能冒充当前可直接回放的来源。无需数据库迁移；用户笔记不作为资料发送给检索器。

原规则的局限仍存在：仅支持有限句式，任意长句、隐含任务、否定多字段等不保证完整理解。本轮没有启用仅问句模型fallback。完整句式附带未知额外指令时不会被截掉后强行改写，但其他既有路由的开放语义覆盖仍需继续验证。

## 实际验收

当前预览：http://127.0.0.1:7883/ 。直接在普通聊天输入：

1. `当归买回来放在哪里保存？`
2. `整理当归的资料，想知道它主要用来做什么。`
3. `当归的功效和贮藏都需要，不过请先列保存要求。`
4. 刷新页面后输入 `出处呢`。

浏览器实际提交前三句，检查字段顺序、出处及刷新后的来源ID一致性。随后通过同一浏览器会话的真实 `/chat` 接口执行原30题开发集：24条资料问题返回预期字段，6条价格问题由入口明确403拒绝。这里的403是声明不支持此请求，不是服务器500/超时；评测严格区分。**30/30是已知开发用例的约定行为通过数，不是30条回答成功或独立业务准确率。**

首次页面检查24/30，是因为评测原本只接受检索器的空结果状态，没有接受聊天入口明确拒绝。原始结果保留在 `audits/chat_field_request_v1/browser_initial.json`，最终记录另存。查询实现没有为价格问题添加错误的回答或绕过入口限制。

首次全仓回归发现收藏白名单遗漏新版本指纹，导致收藏来源被误判过期；已同步保存和备份校验。另一个合成比较fixture没有检索器的标准字段标记，修复覆盖计算改为使用检索器确认的 `fields`，不把每个原句关键词当作已解析查询要求。原始失败回归记录保留，最终回归另存。
