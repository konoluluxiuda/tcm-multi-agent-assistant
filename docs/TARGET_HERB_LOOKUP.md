# 靶点反查药材来源

当前本地交付：本功能已进入7876的`tcm-research-chat:c4de8bc`镜像，见[版本、启动及容器验收](releases/RESEARCH_LOCAL_C4DE8BC.md)。下方源码阶段记录保留其当时的验收边界；7875源码预览需按命令另行启动，不视为当前运行状态。

2026-10-20源码增量，对应ENG-04/05。用于从明确靶点出发，找到当前药材资料中直接列出该靶点的来源，再进入该药材的靶点表或成分候选路径。不引入新数据库或模型调用。

## 使用与结果

支持以下聊天问法：

- `CYP24A1关联哪些药材`
- `靶点Q07973对应哪些药材`
- `查询TNF关联的药材有哪些`
- `/relations 靶点药材 P04278 第2页`

基因符号或UniProt必须是当前已核对靶点目录的精确标识，不猜蛋白中文别名。多个UniProt先选择，选择后翻页固定UniProt；未知标识提示未覆盖，不等于没有关联。带“推荐用药/治疗”等附加要求的问句不纳入本功能语法，不会被截掉后自动执行反查。

结果每页20条药材**来源记录**。相同来源有多条靶点行只计一条药材记录；同名不同来源分别保留，数量不是去重药材种数。默认按来源ID稳定排序，不按功效、证据强度或药材优劣排序。

每条展示药材来源拼音、药用部位、该来源的关联行数，最多3条原始靶点行及JSON位置、文件SHA、抓取状态。超过3条见证有截断标记；未提供抓取状态时保留空列表，不补成complete。靶点原始名称不一致的情况仍可从原始行核对，仅凭共同标识不能批准对象身份。

点击“查看此来源的靶点”或“查看此来源的候选路径”时使用固定来源ID，不重新按药名匹配，也不自动映射到药典中文名。当前结果可刷新恢复、追问“出处呢”、手动收藏、备份、预览及导出Markdown；收藏只保留已选靶点、页码和版本指纹，不把整页药材/原始行写入聊天记忆。不能从一个靶点结果自动替用户挑一味药继续查路径，须点击具体来源。

## 来源与工程边界

使用已有只读资料：

- 基础药材库：`var/tcm/herbs.sqlite3`，当前2076条来源记录。
- 关联目录：`var/etcm_enrichment_v1/data/enrichment.sqlite3`的target节点及药材来源边。
- 已核对靶点目录：`var/etcm_target_links_v1/targets-paths.sqlite3`，当前211个靶点；它用于基因符号/UniProt消歧，不将其中成分关联推算成药材关系。

新查询只使用药材原始靶点表中明确、单一的UniProt分组。仅有相同蛋白名称或一行有多个标识的记录不参与连接。目录未覆盖的其他靶点暂不开放反查；不是全量UniProt或全量药材数据库服务。

先检查靶点/药材目录版本和来源指纹；再对照当前基础库全部有效来源ID与文件SHA，保护包括当前页以外的计数分母。任何错配均停止，不返回过期计数或切换模型。先定位靶点节点，再走已有`edges_by_node`索引，避免为单个靶点扫描全部关系边。没有修改原JSON、基础库、关联库或权限，也无需重建索引。

来源关联不证明实验结合、因果机制或临床疗效，不是药效排名、治疗推荐或药物筛选结论。零结果只表示当前资料没有可返回的来源；未抓取、排除记录和目录覆盖不全仍会影响结果。没有增加中文疾病翻译、靶点机制推断或图数据库。
