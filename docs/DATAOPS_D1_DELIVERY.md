# D1：批量资料核对与表格交付

2026-10-29。D1使用固定本地流程F，模型调用0次。动态Agent、人工消歧后续跑和增量v2属于D2；现有资料中的身份与OCR审核状态继续保留。

## 用户如何使用

在项目已安装依赖的虚拟环境中启动：

```bash
.venv/bin/python -m pip install -r requirements-research-chat.txt
.venv/bin/python -m scripts.preview_local_tasks \
  --port 7908 --state var/dataops_d1_preview
```

打开`http://127.0.0.1:7908/dataops`。该预览使用既有本地ETCM、关系目录和药典索引；模型、联网和追踪关闭。复用同一状态目录与浏览器Cookie可回看任务。

1. 选择目录字段筛选，例如药用部位`Root`，点击“查看记录”；显示匹配总数和本次稳定排序选择的前N条，N最多50。
2. 也可展开“按名称或来源ID指定记录”，每行输入一个名称，例如`白术`、`黄芪`。支持已收录拼音/拉丁/英文名与已有中文名称候选；未知名称会列在问题表，多个来源分别保留，不猜别名或身份。
3. 勾选功能与主治、注意、贮藏、炮制中的1–4项，生成核对表。ETCM默认同时输出药用部位和拉丁名。
4. 页面显示记录数、缺项、对应状态和原文预览；展开可看问题及完整来源。下载XLSX包含结果、问题、来源、运行说明四张表。
5. 刷新或重启后，从“已保存的任务”回看。网络响应丢失时点“重试同一请求”，相同请求不重复生成；重新点“生成”创建一项新的v1任务。

“全部字段补齐”选项严格评分，存在缺项或身份差异就标部分完成；普通核对任务允许以明确的缺失说明完成审查。不会静默丢记录或把缺失补成推断。

药典正文和饮片段的原文分别保留范围。饮片段字段显示“范围待核对”；重复字段不合并，保留歧义及各自引用。

中文名称对应仍是候选。即使字段字面一致，也显示身份待核验。药典取值保留候选状态和原文，与ETCM并列；药用部位不同会保留双方原值及差异，不覆盖原始资料。

## 当前实现与接口

新增`tcm/dataops/`：严格Goal/Query契约、参数化只读查询、复用身份比较的批量核对、字段证据检查、SQLite工作区、不可变XLSX及API/页面。主应用增加入口，独立开关`ENABLE_DATAOPS`默认关闭；预览脚本自动开启。

数据环境：`TCM_DB`、`ETCM_ENRICHMENT_DB`、`PHARMACOPOEIA_INDEX`；可选`TCM_DATASET_VERSION`。`DATAOPS_ROOT`是独立派生状态目录，默认在会话数据库旁。轻量依赖增加openpyxl 3.1.5和et-xmlfile 2.0.0。

| 接口 | 行为 |
|---|---|
| GET `/dataops` | 页面及会话Cookie初始化 |
| POST `/api/dataops/query` | 筛选、精确名称候选、缺失检查、稳定分页与分组统计 |
| POST `/api/dataops/workspaces` | 以Goal和request_key创建固定流程任务；同key同输入返回原任务，变更参数/来源版本返回409 |
| GET `/api/dataops/workspaces` | 当前会话归属的历史摘要 |
| GET `/api/dataops/workspaces/{id}` | 结果、证据、问题和目标版本 |
| GET `/api/dataops/workspaces/{id}/artifact` | 检查文件hash后下载当前归属的不可变v1 |

API延续现有匿名会话Cookie隔离，不是新增账户系统。非本站写请求拒绝，猜测他人ID不能读取。下载、JSON和页面使用no-store。请求不接受SQL、文件路径或任意字段名。源目录版本绑定，检测到变更则拒绝发布。

每个非空字段验证其对应证据的来源ID、字段类型和原始值；药典字段按引用原文拼接精确核对。XLSX生成后重新读取，逐单元格比较全部四张表；字符串强制以文本写入，不能作为公式执行。超出单元格容量报错，不截断。文件验证成功后才发布并写入工作区元数据；失败任务不暴露下载。

工作区版本为1，历史结果发布后不可覆盖；D2实现目标子版本及增量diff。D1是有界同步任务，生成期间状态为building；进程强杀时不自动恢复半成品。正常重启可读取已完成任务，未知的未完成请求需要另建任务。不能把这一边界说成D2持久图已经完成。
