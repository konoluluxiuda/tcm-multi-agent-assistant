# 从资料查询到靶点关联分析

更新：2026-10-23。针对用户提出的“介绍两个数据库”、药材靶点画像和疾病候选筛选，调整下一阶段主线。P0 数据库介绍已完成；P1 已实现药材靶点画像与来源集合相似度。P2a疾病来源审计和独立索引已完成；P2b疾病靶点聊天与来源候选排序已完成；新靶点预测仍待实现。

## 本轮已修复

新增`dataset_info`意图，同时接入本地规则和模型可选Schema。数据概览后可直接问“分别介绍两个数据”“我想问的是介绍两个数据库”，也支持分别介绍ETCM或药典。回复介绍内容、用途和查询示例，计数从当前索引读取；索引不可用时仍可介绍资料类型，但不沿用旧数量。模型只识别当前问句，描述及统计在本地产生。

旧问题的根因是能力定义缺项：模型此前只能选单药查询、关系、统计、功能介绍等动作，没有数据库介绍动作；通用澄清又一律要求药材名。仅增加模型调用不能补齐缺失的工具能力。新意图不要求药材对象，保留原有属性、药典、共同靶点路由和会话焦点。

实现文件：`tcm/dataset_info.py`、`assistant_info.py`、`assistant_router.py`、`intent_planner.py`和`app.py`。验证见[本轮记录](../audits/dataset_info_v1/summary.json)。

验收：专项48项、完整离线89模块815项通过，跳过与网络尝试0；8个本地浏览器场景及1个真实模型改述通过，后者仅1次当前问句意图调用。初轮测试对异步历史加载的过早断言已修正，原日志保留。上述是开发回归，不代表自由问句的总体准确率。

## 算法与评估

P1已通过来源—UniProt去重集合计算相似度，未新增矩阵存储或训练模型。同一来源的重复行只计一个靶点，原始见证另外保留；没有记录的药材标记未覆盖，不能当作“确认没有靶点”。按明确UniProt分组，不通过名称猜同义靶点。

第一版比较共同标识数量与Jaccard：`|A∩B| / |A∪B|`，显示交集、并集及双方规模。空集合不输出可比较分数，排除自身，使用稳定的并列排序。若热门靶点主导排序，再做逆频率加权对照，不先堆多种模型。集合相似度不是作用方向、剂量、生物利用度或药效相似度。

P2a已完成7705份疾病文件扫描、来源一致性与字段审计，并构建可追溯索引；见[结果与复现](DISEASE_GENE_CATALOG.md)。7593条入库来源均缺少明确物种字段，1632条来源共享381组完全相同的非空靶点集合。后续需在排序中保留未核验状态与无法区分相同集合的限制，不以来源自报ok证明抓取完整。优先使用已有疾病基因集，不把药材的疾病富集标签反过来当独立疾病基因真值。比较共同靶点数、疾病基因覆盖率和Jaccard；分母同时报告原疾病集合及当前背景可覆盖部分。若加入超几何检验，须固定背景全集并做多重检验校正，不能把p值转换为疗效概率。

测试分三层：数学性质和手算样本；实际数据独立SQL/原行对照；冻结疾病/来源的独立候选排序评估。至少覆盖重复行、无ID、空/完全相同/不相交集合、未知疾病、同名多来源、缺失库、版本变化、并列排名和高频靶点偏差。报告覆盖率、Top-K命中/排序指标、耗时和失败类型；没有独立标签时仅报告计算与溯源正确性。

ETCM论文说明其靶点信息含已有与潜在靶点，使用配体相似性方法。当前下载行未必保留每条边的证据级别，所以读取现有列表不能称为本项目完成了新靶点预测。[ETCM v2.0原始论文](https://doi.org/10.1016/j.apsb.2023.03.012)

P3需要先区分原有边与待预测边，再评估结构数据、可靠活性标签或独立网络是否足够。预测用的成分/靶点/疾病关联不能同时充当测试答案；按来源、化合物结构簇或时间划分，避免重复药材、共享成分和上游预测结果泄漏。网络接近度还需要额外PPI背景及大小/节点度匹配的随机基线，不能仅凭交集给出验证过的疾病治疗结论。[网络接近度原始研究](https://www.nature.com/articles/ncomms10331)
