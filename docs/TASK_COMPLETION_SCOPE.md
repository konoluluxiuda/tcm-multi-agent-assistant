# 本地关系任务的完成范围（2026-10-21）

后续工具注册增量见[工具返回契约](TASK_TOOL_REGISTRY.md)；下文保留本轮完成口径的交付记录。

本轮修正“完成本地查询”与“研究证据核验完成”混用的问题。适用于研究任务页的新建ETCM任务，不改变聊天模型、检索方案或合成工具任务。

## 使用与结果

打开 http://127.0.0.1:7877/research-tasks ，输入两味药，确认对应ETCM来源，分页查看来源声明的共同UniProt，选择本页1至2个靶点核对双方原始行。

| 结果 | 状态 | 含义 |
|---|---|---|
| 双方原始行已核对 | complete / matched | 已完成所选靶点的本地来源查询；不是所有靶点都经过人工核验 |
| 已确认两份来源，交集为零 | complete / empty | 数据中未记录共同明确标识；不代表现实中不存在共同作用 |
| 来源候选缺失 | partial / source_unresolved | 无法确定查询对象，不能当作空结果 |
| 查询或所选靶点双方见证未齐 | partial / incomplete | 本次要求尚未完成 |

未检索文献、身份与UniProt映射未外部核验、抓取完整性不足等放入`limitations`，不再作为已完成本地查询的`gaps`。`research_evidence_verified`始终为false，不产生药效、结合或机制结论。可选“读取来源文献ID”仅保留原PMID线索，不获取文章，也不提升研究证据等级。

## 实现与兼容

- `tcm/task_contracts.py`提供严格的Pydantic `TaskCompletion`，验证所需步骤、已完成步骤与结果的一致性；由选定来源、查询事件、所选靶点和双方JSON见证生成，不能仅凭状态字符串宣布完成。
- `tcm/research_task_local.py`在创建时写入`result_version=2`和`task_scope=local_relation`，在生成报告时应用完成规则。
- `tcm/research_task_api.py`透传版本和范围；页面与Markdown展示本地完成、缺口和结论边界。
- 无版本字段的任务按v1处理，包括尚待用户确认的旧任务；旧partial报告不自动升级，GET和导出不重写SQLite记录。用户需新建任务才能使用新口径。
- 本次只引入本地任务的完成契约。统一TaskPlan、ToolResult、工具注册表、ETCM模型规划和通用LangGraph暂停恢复尚未实现。

## 验收与回滚

离线测试覆盖空结果、来源缺失、双方见证不足、预算、分页、快照变化、所有者隔离、乐观锁及旧任务继续执行/反复读取导出。浏览器使用已知白术与黄芪来源验证实际页面、原JSON锚点和下载；不是独立业务评测，测试程序选择来源不等于药材身份获人工批准。81模块715项离线回归通过，跳过与网络尝试均为0；16项实际浏览器检查通过（已知来源对共151个标识，选1个靶点、核对双方2条原始见证及2处PMID锚点）。首轮因预览旧后端未重启而等待新标签超时，保留失败后重启复测通过。详细结果见`audits/task_completion_scope_v1/summary.json`。

原JSON与派生目录只读，不迁移历史任务。回滚应保留任务库备份、使用本轮前的源码和静态资源整体回退；旧代码可能把v2的complete显示为合成完成或沿用旧缺口含义，不能混用新旧页面和接口。v2已存报告不应由旧引擎重算；需要恢复写操作时先隔离v2任务或恢复升级前任务库，不能靠删版本字段改写历史含义。

7877是独立源码预览，专用会话与任务数据库复用原预览路径。Docker此前因Desktop WSL集成不可用未更新；本轮不构建、不上传镜像，不提交Git或push。没有调用外部模型或联网文献服务。
