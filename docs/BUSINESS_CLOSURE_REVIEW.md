## 十个未完成任务：根因与优先级

| 首轮题号 | 失败点 | 下一项修复方向 |
|---|---|---|
| BC01、BC18 | 概览及数据库能力追问未识别 | 将资料介绍/能力意图与药材资料意图区分，支持对话对象引用；避免要求每题带固定短语 |
| BC03 | ETCM药用部位/科名被送去药典，最后name_not_resolved | 先确定对象、资料类型及字段，明确药典/ETCM归属后再选工具 |

| BC07 | 相似度问题被当作未识别的复合计划 | 将排序数量/指标作为任务参数，避免因问号分句而升级成另一类任务 |
| BC08 | 已有共同靶点能力却回到旧“核对清单” | 单项查询加出处要求直接执行；来源歧义才选择，展示要求不变成审批步骤 |

BC06与BC15已经用纯规则静态诊断定位，不再次发问题给模型。BC03从实际结果核对到错误资料路由；其他项按首轮路径和现有校验器分析，具体改造后仍需验证。

## 下一大步的架构范围

优先把“用户任务表达→可执行计划”做实，不再添加一套队列、审核台或新Agent框架：

1. 用统一任务表达保存药材/疾病对象、原句跨度、资料类型、字段、排序、分页和出处要求。规则与可选一次问句模型提案都生成同一契约，宿主绑定真实来源ID。
2. 将契约降低到既有八工具和A循环，沿用预算、来源、完成、原始见证及恢复校验。已有能力不因一句自然改述就跳回旧审核清单。
3. 修改模型提案的验收边界：当前报告提案仍必须与有限本地语法解析一致，仅打开模型开关不足以解决BC10/BC12。保留对象/字段落地和覆盖约束，取消“模型必须复述规则已经能理解的句式”这一耦合；不能同时放松来源ID、SQL或真实资料外发限制。
4. 原24题用于回归，保留8/18首轮。另收集未参与开发者提供的新题，先冻结成功条件再比较规则与问句模型；拒答、partial、工具不可用、not_run分开。当前独立题目标40，实际收到0，可先完成10–20题的首批收集，不建大规模标注平台。

本轮没有执行真实模型对照。当前持久授权仅覆盖未识别的当前问句做单次意图识别，不意味着可把药典/ETCM观察送入自主模型循环；新增批量模型实验必须先固定范围、预算和数据内容。模型决定工具后是否更有效，要用同题完整率、漏项、引用和代价验证，不预设“接LLM一定改善”。

## 仍未完成、但不应挤占上述主线的工作

- **独立业务与检索收益**：题源/人工预期、引用支持审核、消融对照、描述性延迟和真实计费；现有工程通过数不替代这些结果。
- **数据可信度**：药典OCR抽查、药典/ETCM实体对齐、字段缺失/词表和抓取完整性；不默认全量人工逐行审核，先覆盖演示与真实任务的关键证据。
- **模型自主工作流**：真实资料的多轮tool calling/观察决策尚未验收，不需要展示隐藏CoT来补这个缺口。
- **可部署性**：新镜像、来源只读挂载、运行状态卷、源码/镜像绑定、容器浏览器与重启恢复，再准备3–5分钟可复现演示。
- **运行规模**：新聊天PostgreSQL/多机、负载、容量/保留政策、索引原子发布和统一trace；目前单机研究项目先不把这些全做成生产平台。

面试可以讲清的现阶段成果是资料与执行链的可追溯工程、失败恢复和真实发现的入口缺陷。业务效果仍需以上结果支撑；本次保留负结果比增加框架名称更能说明工作。

## 复现

本地源资料与索引就绪后，先用独立状态启动无模型服务，保留用户7896实例：

```bash
.venv/bin/python -m scripts.preview_local_tasks --port 7905 \
  --state var/business_closure_v1/runtime \
  --diseases var/disease_catalog_v1/build/diseases.sqlite3
.venv/bin/python -m scripts.eval_business_closure freeze --out var/business_closure_v1/frozen
.venv/bin/python -m scripts.eval_business_closure run \
  --frozen var/business_closure_v1/frozen --url http://127.0.0.1:7905 \
  --out var/business_closure_v1/first_run
```

输出目录要求不存在，不能覆盖首轮；复现应更换整个输出根目录，保留旧冻结与报告。脚本拒绝外部URL、代理和重定向，检查本机预览进程未启用意图模型，运行前后核对代码与资料SHA。完整响应、药典摘录和参考保留在权限受限的`var/`；公开审计只放问题、计数、判定和摘要。本轮不修改应用、不提交Git、不构建或发布Docker。
