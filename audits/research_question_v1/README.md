# R4有界问句：Goal、执行交付与真实模型理解验收

日期：2026-10-31。接通问句输入与已有执行链，新增指定对象核对语义；**没有将真实A原始0/2改写为成功**。当前顺序见[大纲](../../docs/TCM_PROJECT_ROADMAP.md)，运行方式见[资料任务说明](../../docs/RESEARCH_SELECTION_AGENT.md)。

## 本轮交付

`/dataops/research` 顶部直接输入任务，`POST /api/dataops/research-questions` 编译有界ResearchGoal后复用现有队列、ResearchEngine、持久图、来源校验和XLSX验证。聊天的明确表格整理与续加字段共用DataOpsService，不另建执行器。旧D1/D2入口和旧Selection默认筛选模式保留。

- `audit_named`：整理指定对象，所有记录保留；缺失标记，不要求缺失项被补齐才交付。`complete`只表示已完成核对。
- `select_complete`：从限定候选挑选满足字段条件的目标条数；不足明确partial。候选上限20和目标数量1–5不同。
- 续加字段绑定已交付父版本，保留对象、旧列和旧文件；不让模型自行重建父对象。出处不是药典基原列，未指定ETCM属性只默认药用部位。
- 默认本地解析，未知要求或歧义不创建部分任务。可选的一次模型理解与native多轮执行分别开关、分别计数。复用RAG请求回执，先落盘后派发；同请求键复用提案，未知派发不自动重发。

主要受影响模块为 `research_question.py`、ResearchGoal/ResearchEngine/ResearchSynthetic、DataOpsService/API/chat、工作台、预览CLI及能力菜单。RAG原请求回执抽成共享 `RequestJournal`，原接口保持兼容。没有新增框架、向量索引或修改原始资料。

## 真实问句理解对照：有局部帮助，也会生成错误目标

冻结[8道作者开发题](../../eval/research_question_v1.json)，输入问句，不给模型标准目标；参考及源码在运行前冻结，未执行生成的Goal。不是独立用户集或盲测，不是临床效果评估。

| 项目 | 本地规则 | 单次模型方案 |
|---|---:|---:|
| 整体符合目标/必要澄清契约 | 4/8 | 6/8 |
| 实际需要理解的5题 | 1/5 | 3/5 |
| 宿主预检处理的3道控制题 | 3/3，零调用 | 3/3，零调用，不计模型能力 |
| 错误ready目标 | 0 | 1 |
| 不必要追问或未识别表达 | 4 | 1 |

实际5次DeepSeek HTTP200，7,754 token，无重试；三道控制题均未调用模型。只发送固定问句、静态Goal定义、精确命中的名称候选和父版本字段/筛选元数据，没有资料正文、PDF/数据库或会话历史。本轮没有导出Langfuse，不能声称轨迹已回读。

Q01、Q03说明模型能理解一些规则不接受的表达。Q04把“存放环境”看成ETCM生境，又因父版本未外发药名而多余追问；Q08虽然只要求功效，模型却增加性味、归经等五个ETCM属性。**Schema合法不代表目标正确，语义覆盖提升不能抵消错误执行风险。** 原记录见[逐题结果](model-results.json)，协议/输入/原始响应与源码快照留在 `var/research_question_v1/live_ready/`，该目录禁止重复执行。

事后增加未请求ETCM属性及明确否定列的宿主拒绝，父版本增加“对象已由宿主绑定”标志，并澄清存放环境与生境。Q08原响应离线回放已被拦截，见[守卫回放](guard-replay.json)。这只是事后安全验证，**原6/8及错误ready记录不变，改后提示未做真实模型复测**。不将旧题反复调优成绩当作泛化证据；日常模型理解仍关闭。

## 后续与回滚

下一大步验证“输入理解＋观察执行”的安全组合：新问法先检查错对象/错列/遗漏要求不入队，再用新任务比较单次理解加确定性执行与真实A。原A0/2、旧G8/12、新8题失败和本次回放各自保留；尚无真实A稳定交付、自主检索收益、开放语义验证或跨库身份签核。

关闭 `--research-goal-model` 即关闭模型理解；关闭research-selection可恢复旧入口。回退保留的 `tcm-research-r4-before-question-v1` 容器前先停止当前服务，并保留原状态目录；旧执行器不能恢复新版在途checkpoint。已交付文件不重写。镜像不是含数据的搬家包，跨机器仍须登记同版本资料。
