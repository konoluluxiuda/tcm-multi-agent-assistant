# 单来源表格与澄清契约修复

日期：2026-11-04。起点是[真实回归审核](../requirements_feedback_v1/live_regression_result.md)：G业务2/6、W3/6，边界各2/2；23次请求均HTTP200，旧成绩不变。

## 修复内容

- 表格Goal允许一侧字段为空，但两侧不能同时为空；省略字段参数时的旧默认值保持兼容。需求适配器按明确字段生成表格，不再给单来源请求补入另一来源的默认列。逐对象列差异、父对象/行策略冲突仍拒绝。
- 纯ETCM表格跳过药典候选/正文检查，状态为 `not_requested`，不声称完成跨来源身份核对。完整性筛选只检查请求字段，不再要求无关的药典名称匹配。追加药典字段时重新读取对应来源，保留原表和旧字段。
- `needs_input` 的 `requirements=[]` 约束显式写入模型可见JSON Schema、字段说明与提示词。未满足的原要求保留在 `unresolved` 中；无效返回仍被拒绝，不自动删字段替模型修好。诊断新增明确的Schema拒绝阶段及 `clarification_has_executable_requirements` 修正建议。
- W关系范围提示明确：普通“列出资料中的结果”默认分页，只有明确全部/穷尽要求才用 `all`。宿主仍拒绝不支持的全量关系，不以分页冒充全量。提示词的真实效果尚未重新调用模型验证。
