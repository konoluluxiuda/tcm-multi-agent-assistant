# 模型提案误拒修复与真实资料回归（2026-11-01）

本轮修复[上一批新问法](../query_generalization_v1/README.md)暴露的宿主问题。不是重做未见题评测：原始业务成绩本地0/8、一次理解＋fixed 4/8保留；本轮新增外部模型调用0。

## 改动与范围

| 问题 | 修复 |
|---|---|
| 正确药名因“列出/重合”等词被拒绝 | 普通模型查询使用宿主目录候选＋原句字面位置校验，目录内对象不再依赖上下文动词白名单；重叠候选优先完整长名称。仍拒绝炮制/提取物/复方截取、否定对象、ASCII半词和漏掉第二个已知对象。来源选择仍由本地工具执行，不把候选关联当作人审身份 |
| “注明出处”使四步计划不完整 | 展示要求统一识别“注明/标明”；不生成额外业务动作，四个成分/靶点要求仍逐项比较。未知附加要求不能一起吞掉 |
| “选出字段都有记录的”被要求填写数量 | 齐全筛选识别与Goal验证共用同一判断；没有选N条时核对整个候选范围。两项字段不会变成两条记录；明确选两条仍保留数量约束 |
| 模型正确拒绝却被Schema拒绝 | `unsupported`可保留有界拒绝理由，仍不能携带可执行字段或关联类型；说明同步保留到结构化回复。Prompt只同步这个停止契约，没有增加题目示例 |
| 第三人诊疗与交易要求未前置拒绝 | 增加家人/患者的明确用药安排指令判断，聊天在模型与队列前403拒绝；下单/联系药店不被丢弃后只查功效。研究性提及和新增交易动作的明确否定分别测试 |
| 深层工具参数被截断/并发诊断缺记录 | 本地owner诊断使用16层脱敏上限，保留常规嵌套调用参数及SDK解析结构SHA256；原48,000字符预算与凭据/隐藏推理脱敏保留。SQLite同进程事务按路径锁串行化，减少首次建表写竞争；超时仍不改变业务执行 |

普通查询的目录证据仅由宿主传入，不是模型可填写的参数。不在目录的对象继续沿用严格字面边界；疾病及复杂计划也没有整体放宽。当前仍有有限炮制、否定和化合物规则，不宣称解决任意中文对象识别或任意任务语义验证。
