# 药材查询页面工作流验收

日期：2026-10-12。承接同日 API 修复，提交与上传状态以 Git 记录为准；未重建镜像、未接入原医疗聊天路由。

## 已完成

- 查询页由整段 JSON 输出改为名称查询、动态多条件筛选、记录表格、来源详情和字段比较。
- 新增 `/herb-records/{source_record_id}`：同名候选和筛选表格都按具体来源 ID 打开详情，避免用名称再次查询时选错记录。
- 筛选支持 `limit/offset`，默认 20、最多 100 条，返回总数、本页数量和下一页偏移；固定按相对路径/ID 排序。
- 页面翻页和来源选择保留返回的 `dataset_version`；页面显示当前版本和实际筛选条件。
- 详情和比较字段可展开原值、JSON Pointer、来源文件及 SHA-256，所有原文使用文本节点展示。
- 增加空结果、中文名未映射、字段条件错误、服务不可用和同名候选的明确提示。过期请求通过 AbortController 与请求序号隔离，避免晚返回的结果覆盖新查询。

## 验证

25 项 Python 回归通过：14 项数据层、11 项 API。新增 API 覆盖分页上下界、稳定翻页、总数/本页数量区别、重复分页参数、来源 ID 详情和指定版本不存在。

真实 Chromium 工作流共 16 项通过，见 [检查结果](page_workflow_2026-10-12.json)：

- HuangQin 查询和字段来源展开。
- Leguminosae 筛选共 127 条，每页 20 条，上一页/下一页保持稳定；逐页收集 127 个来源 ID，无重复或遗漏。
- 筛选行与 HuaShi 同名候选均按指定 ID 打开正确来源。
- 多药材比较保留同名歧义、查无记录与证据定位；未自动合并候选。
- 中文名不支持提示、空结果分页禁用、重复字段提示和多条件 AND 筛选。
- HTML 字段不执行、服务错误不保留旧详情（这两项使用模拟响应）。
- 390 px 移动端无页面级水平溢出，无 JavaScript 错误；表格自身允许横向滚动。

截图人工检查时发现测试环境无中文字库，随后在临时 fontconfig 中引用本机已有微软雅黑重跑 16 项检查，中文可读。字体文件没有复制到仓库或打包。桌面/移动截图在 `/tmp/tcm-query-desktop.png` 与 `/tmp/tcm-query-mobile.png`，属于临时预览。

测试通过临时本机 Uvicorn 服务读取现有 `var/tcm/herbs.sqlite3`，结束后自动关闭；未修改源数据或数据库。

## 运行与复现

见 [使用说明](../../docs/ETCM2_MVP_USAGE.md)。轻量环境中启动：

```bash
python -m uvicorn tcm.api:app --host 127.0.0.1 --port 7863
```

打开 `http://127.0.0.1:7863`。此为独立查询服务；本轮测试没有将其作为常驻服务部署。

```bash
python -m unittest discover -s tests -p 'test_tcm*.py' -v
python -m scripts.verify_tcm_page
```

浏览器脚本依赖 Playwright/Chromium 和示例数据库，见上一份 [API 环境说明](api_review_2026-10-12.md)。

## 边界与下一依赖

筛选接口的 `records` 不再默认包含所有匹配项；旧调用方应按 `next_offset` 遍历，`count` 仍表示总数。当前分页只限制返回数量，仍全量扫描有效记录用于匹配和计数。记录版本可固定，但同版本重导入仍能改变内容，尚无固定批次游标或并发导入时的一致性承诺。

比较中的“查看候选”只打开来源详情，不会把候选自动替换成比较列的唯一实体。中文名称映射继续暂缓；人工黄金集与原医疗聊天集成仍待完成。未把这次 UI/API 验收视为药材科学内容核验或生产容量验收。
