## 独立预期与故障发现

- 名称、候选来源和筛选集合从原始字段独立计算；固定文件不在评测时重算或覆盖。
- 每份返回记录校验字段值、缺失状态、原值、JSON Pointer、来源路径/版本/ID/校验和及未核验状态。
- 生成器拒绝覆盖已有套件。数据指纹不匹配时阻止运行，输出 blocked 和 not_run，避免悄悄改变答案。
- 故障注入证明：即使文件哈希元数据保持不变，数据库字段值或来源指针被改写也会失败；源快照或数据库哈希变更会阻断评测。
- CLI 在字段错误时返回 1，数据/套件前置条件错误返回 2；“工程通过”不会自动填写人工签核。

## 首轮 HTTP 误报与修正

首轮 HTTP 为 29/30：[初始报告](report_http_initial.json)。评测器错误地要求 HTTP 空筛选条件提示与仓库 ValueError 的文本相同。HTTP 入口提示是“provide at least one filter field”，仓库异常是“filters must be a non-empty dict”，两者同属拒绝空条件的正确行为。

修正评测器为按传输层契约校验：仓库校验异常类型与提示片段，HTTP 校验状态码与错误结构；如专门指定 HTTP 提示片段才校验它。新增回归确保 HTTP 400 却返回 status=ok 仍会失败。冻结字段、结果集合、计数和哈希均未更改，最终 HTTP 30/30：[最终报告](report_http.json)。

数据层报告：[report_repository.json](report_repository.json)。文件记录各用例耗时、失败信息、套件 SHA-256 和复核状态。当前耗时用于工程排查，非 p50/p95 性能基准。
