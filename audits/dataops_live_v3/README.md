## 已确认的V3失败原因

| A任务 | 实际动作/停止点 | 归因 |
|---|---|---|
| B01唯一候选 | 查询→核对→读取→回读证据→比较→构建→验证→结束，共8次 | 完成交付，恰好用完预算 |
| B04多候选 | 第3步询问并收到预置测试答案，第4步读取；之后比较、回读、再次比较，第8步才构建 | model_budget；文件已生成，尚未执行独立验证与结束动作 |
| R01增量 | 父目标8次完成；子目标查询复用4个旧字段，读取贮藏得到多scope值，随后回读、比较、重复核对 | 子目标第5次决策触发no_progress：比较与重复核对连续两步未改变可交付状态，无子文件 |

宿主原来给出了model_calls和字段状态，但缺少剩余预算、交付阶段预算、已读缺失/多scope与未读字段的明确处理契约，也没有把无进展计数回传模型。工具说明未清楚说明比较/重复核对不能补缺。这些是可改进的Harness反馈缺口，不能据此保证只改提示就能提升模型表现。

当前粒度要求模型逐一选择构建、验证、结束，简单任务会额外付出决策成本；构建工具自身也有文件回读检查。机械尾部是否交还宿主，应在统一工具/验收条件下另作对照，不能在本轮自动完成A以改成3/3。

**旧V2精确原因仍未知。** 当时响应动作诊断不足，不能用本轮预算/无进展问题倒推旧失败。旧V1/V2与本轮原始JSON保留不变。
