## 问题与改动

原聊天页每次发送创建新UUID。若服务端已执行而响应丢失，用户重新发送会产生新请求，无法利用后端已有的同编号回放保护。

- `assets/web/chat_requests.js`：每个标签页使用sessionStorage保存一条待确认文本请求，先保存后POST；同问题与回答模式复用编号，修改后使用新编号。浏览器存储失败时不发送并保留输入。
- `templates/index.html`：提供明确的手动重试按钮；刷新只GET会话，不自动POST；收到并展示结果后清除待确认记录。确定性拒绝403/410/422清除记录，未知执行/冲突仍交由原服务端回执处理，不自动换编号。
- `app.py`：会话返回非授权用途的`request_scope`及有界历史中的已记账请求编号。新聊天页携带scope，旧标签页遇到cookie更换或会话过期返回410；scope不是登录凭据，不能替代HttpOnly Cookie。该字段可省略，既有API调用保持兼容。已记账只表示结果或任务已保存，不表示任务成功或需求已完整交付。
- 使用说明与大纲补充“药材清单→字段查询→来源核对→分页关系→固定表格→回查”的业务流程。未增加问题类别，也未虚构客户、人工效率或模型收益。

浏览器检查需已有Playwright和Chromium，不自动下载。使用项目Python及已安装浏览器环境执行：

```bash
python -m scripts.check_chat_request_recovery_browser \
  --browser /absolute/path/to/chrome \
  --out var/chat_request_recovery_new/browser.json
```

输出须使用新文件。脚本会隔离应用环境、禁用dotenv载入、使用合成数据库，浏览器请求通过内存TestClient处理，不连接当前7934部署。

## 边界与回滚
