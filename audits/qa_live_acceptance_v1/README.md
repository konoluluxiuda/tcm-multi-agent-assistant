## U06 根因：对象保存了，但未送入后续模型上下文

原句为“我想查陈皮的资料。”→“先给我药味和药用部位。”→“再补上药典的贮藏。”。

1. 首轮保存的 HumanMessage `query_scope.object_mentions` 是 `["陈皮"]`，所以不是首轮没记住或数据库丢失。
2. [conversation_scope.py](../../tcm/dataops/conversation_scope.py) 的 `field_followup` 仅识别有限前缀；“先给我”和“再补上”返回 `None`。`prepare` 在读取上一用户轮次前提前返回，未继承陈皮。
3. 第三轮 `subject` 还会将“再补上药典”作为未经名称验证的候选片段；[service.py](../../tcm/dataops/service.py) 校对真实目录后将对象范围置空。第二、三轮保存提案均为 `object_mentions=[]`、`inherited=false`。
4. 模型接收当前问句和受限上下文，未得到可用的上一轮对象，返回 `needs_input`。在 [requirements_feedback.py](../../tcm/dataops/requirements_feedback.py) 的 `run_requirements_feedback` 中，未就绪需求直接停止，尚未进入工具预检与纠正。
5. 第二轮又保存了空对象范围，因此第三轮还受到前序失败影响。离线读取本次保存消息并调用 `prepare`，可复现上述行为，新增模型调用 0。

因此这轮不能归因为“模型不会理解药味”，也不能推断多加一轮模型就能解决。具体缺口在追问识别与上下文准备。另有展示问题：模型澄清中的 `object_mentions`、`inherited=false` 和字段命名空间直接展示给用户。

本轮仅验收与定位，不修改上述实现。若处理收尾问题，应限定于该上下文缺口及澄清展示；需保持对象切换、真实歧义与跨会话隔离规则，不能无条件沿用历史药名。任何修复的离线结果都不能替换这次真实首测分数。
