## 实现与约束

1. 提取完整的类型化需求；发送由真实能力注册表和表格Schema派生的能力/交付约束。
2. 调用共用机械规划器，检查来源唯一性、父任务、能力、覆盖和交付适配。对于可执行计划，只读探测最多2个对象、每对象4个请求标量字段；反馈仅含 present/missing/unresolved，不含字段值、PDF正文、路径或来源ID。名称与字段名仍是模型输入。
3. Schema修正与工具反馈修正共享一次额度。无法唯一绑定、父任务冲突或全量关系要求直接停止；不能删字段、删对象、缩小范围或擅自增加表格默认列来通过检查。
4. 复核模型看原问句、能力和资料可用状态，不看前一版提案；规范化需求不一致则澄清。它共享工具观察，并非统计独立验证。复核通过才进入原有fixed查询/表格执行器。

通常2次请求，有修正时最多3次；最多2轮预检，无自动重试。来源变化与本地探测错误分别报告，不伪装成未知模型派发。诊断保存阶段、工具反馈和用量。边界请求可在模型前拦截。资料状态探测仅覆盖标量字段，不能代表关系完整性，也不能证明药材身份或语义理解正确。

代码入口：[反馈策略](../../tcm/dataops/requirements_feedback.py)、[机械规划](../../tcm/dataops/requirements_pipeline.py)、[服务接入](../../tcm/dataops/service.py)。既有 V 策略与默认策略保留；评测器默认仍是 R/G/V，新增 `--policies G W` 显式选择。
