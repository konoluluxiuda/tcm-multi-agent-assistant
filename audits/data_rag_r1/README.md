## 原始参考如何建立

[种子](../../eval/rag_v1/seeds.json)为作者AI从原始OCR块与JSON编写的明确标注；[冻结参考](../../eval/rag_v1/references.json)保留源hash、PDF物理页/块/偏移、JSON指针、对象组、需求及禁止补造项，不从检索结果反推答案。PDF题核对了原页裁剪，两个结构化字段直接核对原始JSON；[核对记录](source_review.json)保留私有图片路径和hash。

缺字段题在冻结的原始阅读顺序区间扫描独立`【注意】`标签，并核对条目末尾原页；含义只是当前OCR条目未见该独立字段，不是不存在使用限制。歧义题有多个明确炮制条目作为见证，不允许擅自挑一个量。黄芪污染样本标为已知边界开发回归，不能当新模型泛化证据。

所有参考均为`ai_raw_source_checked_pending_human_signoff`，human_signoff=false。保留题仅尚未在此benchmark运行检索/生成，作者已接触参考；不声称独立盲测、全项目从未见过药材或人工批准。R1锚点校验与索引映射不消费检索/回答首测机会。全部`relevance_complete=false`，后续先报Hit/MRR，不能借34/34映射声称全库Recall=100%。

## 发现并保留的兼容性问题

旧名称侧库仍绑定同一批原块，但4条中文候选与修订视图名称不符：葫芦巴/胡芦巴、秦芫/秦艽、绵萆薤/绵萆薢、龙腺叶/龙脷叶。完整来源ID和条目ID见发布清单的`sidecars.mapping.quarantined_candidates`。**本轮只登记排除清单，没有改写侧库、自动确认身份或把新发布切给HTTP服务。** R2以发布清单访问跨源候选时必须执行该排除策略；两道JSON/药典桥接参考均不依赖这些候选。

旧向量文件hash通过，但源索引hash不兼容。R1将其标为`eligible_for_current_release=false`；R2须新建匹配当前索引和模型配方的向量代。不能只改embedding配置就复用旧缓存。
