## RAG 故障的真实执行路径

第一道知识问题：路由到 RAG → 首次重排模型加载约 38.5 秒 → 查询扩展 → 嵌入 API 200 → 检索 5 项 → 重排 → 生成回答 → confidence=0.3692405087200718 → 低于 0.4 → 转 Tavily → 缺少 TAVILY_API_KEY → HTTP 500。

来源追问也完成检索与生成，confidence=0.26399710892373046，随后同样失败。
因此问题不在于聊天/嵌入接口完全不可用，而在于分数驱动的回退路径没有处理搜索不可用的情况。
本轮来源追问未被输入 guardrail 拦截；此前代码中存在禁止来源的规则，并不意味着每次执行都会拦截。

## 附加确认的问题

1. 答案来源写成 `http://localhost:8000/data/raw/brain_tumors_ucni.pdf`。
   实际测试地址 `http://127.0.0.1:7861/data/raw/brain_tumors_ucni.pdf` 返回 200/PDF；生成的 8000 地址未返回有效 HTTP PDF（本次返回 RTSP 400）。需改为相对地址或配置公开基址，并迁移已有索引中的旧 URL。
2. 胸片响应 agent 标记包含 HUMAN_VALIDATION，但最终输出被输出过滤改写，未保留原人工确认提示。只证明路径执行，未证明审核交互完整。
3. 中文介绍声称可查指南、结合检索等，不代表这些能力已被测试或在缺少搜索密钥时可用。

## 发布判断与优先修复

镜像可以启动，中文聊天与部分接口可用；核心知识问答仍可能返回 500，当前不应标记为稳定功能版。

优先处理：

1. 将联网搜索做成可选功能，关闭时不进入该节点；保留证据不足提示，不用无来源的模型回答替代失败。
2. 修复来源链接，支持实际部署端口/域名。
3. 修复共享 thread_id、重排组件生命周期与来源追问约束，再对多用户及多轮行为验收。
4. 对证据充分性单独校准，避免仅降低 0.4 阈值掩盖问题。
5. 若目标转向中草药证据问答，优先稳定简单 RAG，再用中文领域测试集决定哪些复杂步骤值得恢复。

本轮仅测试和记录，没有修复上述业务问题，也没有重新构建或发布新镜像。
