# G V1：自然语言目标理解与固定交付对照

日期：2026-10-30。已实现单次原生目标提案、冻结12题并完成一次真实模型对照。**实验已完成，模型默认接入未验收；HTTP入口未启用本适配器。**

## 事前协议与实现

- [题集](../../eval/dataops_goal_understanding_v1.json)：4道规范控制、4道自然表达/连续修改、2道应澄清、2道范围外。作者编写、合成资料、已知开发题，不是独立用户/未见集。它与此前12题压力集草案不是同一套题。
- [预览](preview.json)、[事前源码/题集hash](pre_execution.json)均在真实调用前保存。模型不接收标准Goal、预期状态或来源评分参考。
- `tcm/dataops/goal_model.py`只提出对象、字段、筛选和修订意图；原始值、来源选择和SQL不在可生成参数中。宿主绑定父对象/版本、保留原字段、继承严格要求、解析本地名称并校验50条上限。
- 新名称目录限128个别名、上下文16KB，超限拒绝，不默默截断；这不是已解决全ETCM目录候选检索。父版本只发字段/条数摘要，不发旧单元格或会话历史。
- R使用现有有界语法；G每题恰好一次`deepseek-flash`原生tool call。两者收到相同问句、目录与字段契约。接受的目标均由同一个固定F图、工具、缓存、来源评分与文件验证执行；不掺入动态A决策。
- 总上限12次，每题最多1次、1200输出token、64KiB、30秒、显式关闭thinking，禁止并行工具、重试、格式纠正和旧运行重放。HTTP错误/未知派发停止剩余模型题。

## 逐题已确认问题

| 模型失败 | 实际输出 | 分类 |
|---|---|---|
| C01标准功效/注意＋表格 | 把“功效”及表格视作超范围，要求澄清 | 不必要拒绝；静态字段语义/可交付能力仍没对齐 |
| C02贮藏＋保留出处 | 在贮藏之外增加“来源”列 | 把证据出处误当药典“来源/基原”业务字段 |
| C03按Root筛选前2条的功效 | 筛选/数量正确；ETCM列改为indications，药典还增加注意 | 默认字段与请求字段混淆 |
| G01用途＋提醒＋出处 | 用途/提醒映射正确，但额外增加“来源”列 | 与C02相同的语义歧义 |

这些响应都通过schema和本地范围校验；错误是在事前Goal参考及实际XLSX列检查中发现的，说明**schema合法、来源真实、文件有效均不等于完整理解了用户要求**。模型没有生成实际药学值或改写源文件，问题是错误的目标列。错误产物仅留在隔离合成实验目录，没有发布到业务页面。

模型实际补回的三题是G02多对象工作簿、G03保留旧列添保存条件、G04只替换药典列；均通过固定交付和来源参考，不只是“看起来理解”。G03/G04由宿主保留ETCM列及原记录集合。

## 取舍与下一项

不让G替代已经成功的规则路径，不把8/12写成模型验收通过。保留当前HTTP的本地有界编译，真实提案只作为显式实验能力；动态A仍沿用V4未稳定验收结论。

用已收到的R/G结果做了[事后策略回放](policy_replay.json)：R ready就用R，其余选已有G结果，为11/12，选用8条G回执。**没有新增模型调用，也不是另一次在线实验**；12次实际请求不改为8次，不把该11/12当独立/前瞻成绩。

下一项为完整的G2语义契约与接入验收：明确“出处证据始终附带”与“药典来源/基原字段”的区别、默认列/明确列的边界及修改操作；形成规则优先的提案路径，未知语义或能力要求继续可见澄清。补新的事前参考后，在同一固定执行器上验证，不修改本轮题目、成绩或预算，不直接全量上线。大目录需要先做有界候选召回，不能直接把2076条来源的所有别名塞进当前128别名接口。
