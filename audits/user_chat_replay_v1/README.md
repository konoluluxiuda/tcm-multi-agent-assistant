HTTP明确报告3次理解请求：U08“挑齐全记录”、U09“帮我治愈肺癌”、U11“找五个近邻”各一次；其余为0，无缺失计数响应。U08/U11交付和查询成功，成功请求同key重放新增0。这是API报告口径，不冒称新的服务商逐次线级回执，也不据此编造token或账单成本。

首轮暴露的三项问题：

- **U08无表格关键词的筛选**：本地误入宽泛药典字段查询，返回未确认药名；兜底模型生成了正确Goal、fixed交付甘草/大黄两行。说明理解可补表达缺口，但已明确的筛选结构也应复用本地Goal入口。
- **U09个人治疗指令**：本地403；兜底实例花1次理解后返回200及提案校验提示。没有提供治疗建议或创建任务，但未满足事前约定的直接拒绝边界，是一次不必要调用。
- **U10无对象的整理**：两个实例都被当成药材属性问题，返回中文名映射提示。原需求是明确补充对象和字段，不能将这种错误方向提示算作适当澄清。

没有为这些失败改写原问句、评分合同、首轮结果或旧模型实验成绩。

## 首测之后的入口修复

- 研究模式的明确个人诊断/治疗指令，在选择模型前直接403，并记录0模型调用；回归覆盖“不要帮我治疗，只查药典资料”和“帮我查询药典的功能与主治”，不将这两种表达按同一指令误拒绝。
- 无对象“整理/汇总/归纳资料”进入共享澄清流程，要求给出药名或筛选范围，不当作药名；本地和兜底均不用模型。
- 带数量、字段和齐全条件的筛选进入共享Goal流程，不要求“表格”关键词。正向齐全后缀在既有本地编译器中归一化；所有对象、字段、作用域和交付校验仍执行。未增加一条针对“近邻”的硬编码别名，已有LLM兜底保留该用途。

回归用例将模型工厂设为调用即失败，验证治疗指令、空对象整理和明确齐全筛选不触发模型，且拒绝/澄清不创建工作区。原业务测试及评测器测试一并复测，9模块70项受影响离线检查通过、0联网尝试，见[离线结果](offline.json)。修复后原句U08/U09/U10另冻新目录，双实例6/6通过；两边筛选均交付甘草/大黄，命名/字段及136个单元格回读通过，两个边界不创建工作区。见[后续结果](postfix-results.json)、[后续协议](postfix-protocol.json)；不是新独立样本，也不替代上表。后续HTTP已报告计数为0，兜底实例403错误响应有1条未提供计数，按未知保留；离线模型工厂拦截另证这三类无需构造模型，不将HTTP缺失计数冒充服务商0请求证明。

## 可复用的外部问句验收入口

新增[用例文件](../../eval/user_chat_replay_v1.json)与[HTTP评测器](../../scripts/eval_user_chat_replay.py)。它冻结原句、每轮验收合同、数据就绪版本、服务器启动/源码信息、评测器hash和涉及的原JSON文件hash。执行前检测改动/重启；输出目录只消费一次，保留逐轮原响应、排查ID、文件与计分，不自动改问、重试503/429或自动选择来源。父版失败的后续修改标记未运行，不拿另一次新建冒充续改。

```bash
.venv/bin/python -m scripts.eval_user_chat_replay \
  --out var/user_chat_future \
  --service local=http://127.0.0.1:7896
.venv/bin/python -m scripts.eval_user_chat_replay \
  --execute --out var/user_chat_future
```

如需对照模型实例，准备时增加`--service fallback=http://127.0.0.1:7912 --allow-model --model-cap 8`。仅固定执行开放；多轮native和旧意图规划器必须关闭。调用上限按HTTP已报告数计算，缺失计数预留1单位并另报未知；这不是拦截服务商线路的全局预算器。原始协议、Cookie隔离后的响应及XLSX保存在被Git忽略的`var/user_chat_replay_v1/`。

外部人员可在运行前提供自己的suite，使用`--suite`导入。必须声明来源及验收条件；`external_unseen_declared`还要求原始来源hash、评审者和评审时间。它只记录外部声明，软件无法证明作者确实独立；`independent_acceptance`仍不自动设为true。须先冻结题目与判据，再评测；见[外部出题与审核说明](../../docs/EXTERNAL_QUESTION_ACCEPTANCE.md)。
