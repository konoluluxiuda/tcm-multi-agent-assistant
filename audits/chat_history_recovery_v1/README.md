# 历史字段答案恢复

日期：2026-11-06。修复[真实资料走查](../qa_real_data_walkthrough_v1/README.md)发现的缺口：连续完成多轮字段查询后刷新，早期答案不再仅显示“查询完成”的摘要。

## 变更与范围

- `app.py::conversation()`按当前保留消息里的交付键，使用当前会话归属读取已保存答案，附在原助手消息上；保留最后一轮的`answer_delivery`兼容字段。
- `templates/index.html`在各轮原位置渲染这些答案；最新答案不再重复追加，后续澄清或表格仍保持自己的位置和类型。
- 单轮记录不存在或损坏时，该轮显示无法读取提示，其他答案继续恢复。读取不调用模型，也不重新执行查询。
- 不扩大历史保留期限，不把已截断的消息重新插回会话，不修改模型上下文或原交付账本。范围是已有保存交付键的字段查询；其他旧版消息和候选表格仍使用原有恢复方式，不宣称所有旧功能均实现逐轮回看。

## 验证

机器可读结果见[acceptance.json](acceptance.json)。离线4个模块共47项通过，失败、跳过和网络尝试均为0。浏览器展示14组、请求恢复7组通过；覆盖原轮次字段与出处一致、最新答案无重复、缺项提示保留、表格/澄清不冒用旧查询、丢响应恢复、重复提交和会话切换。

新增HTTP回归验证了多轮保存结果逐一恢复、被历史上限截断的轮次不复活、损坏/缺失记录不遮蔽下一轮、即使持有另一会话的交付键也不能读取结果。展示检查中原先“表格后无任何旧卡片”的断言改为“旧卡片只出现在各自原轮次，表格仅一份且在其后”，不删除原来的防重复要求。

真实资料复核使用独立空状态实例，模型关闭、fixed执行：先询问茯苓信息，再问性味和剂量、归经，随后查泽泻跨来源字段和两味性味；刷新后4轮答案、5张药材卡与刷新前一致，原保存步骤逐项相同，刷新新增POST为0，较早一轮的药典原页仍可展开加载。首次浏览器启动早于服务就绪，仅连接失败，尚未发送查询；就绪后才完成上述复核。

本地日志、响应、截图与独立实例状态保存在`var/chat_history_recovery_20261106/`，不提交原资料或会话。7896更新和原状态保留情况见结果文件；未向7896发送真实聊天请求，未启用native，未运行付费模型评测。此前失败记录保留，真实W理解与自然语言泛化未在此轮重测。
