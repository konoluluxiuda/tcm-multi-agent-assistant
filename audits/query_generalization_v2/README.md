## N06：正确模型提案被误拒

排查请求号：`1b8ee99bf6f040a3a173c04517009325`。

模型明确返回三药、`filter_complete`、功效/注意、`target_count:null`，深层解析参数hash可核对。Schema、名称和字段均通过；`all_complete_request`只认“都有/有记录/齐全”等连续词，没认出“同时有……记载”。`compile_draft`把没有本地正证据当成反证，返回`completeness_mode_mismatch`，尚未执行数据查询。公开提示还错误归因为“模型改变了筛选方式”。已保存返回的无网络重放复现同一拒绝，见[首次原因记录](diagnosis.json)。

首测后修改：

- 本地解析继续保守，不为这道题增加同义词；模型提案校验新增`mode_constraints`诊断，将词表未命中与明确约束冲突分开。
- 已识别的全部齐全项要求仍不能变成audit或Top-N；明确保留全部行、查缺失项的请求不能变成正向齐全筛选；Top-N必须有显式数量且相等。
- 对象全集、字段覆盖/否定、最多5来源、父版范围、工具权限及文件验证继续执行。未知语义并未被形式校验完全证明；模型仍可能选错模式，需要结果合同评测。
- 失败提示不再直接归咎模型，固定数量冲突保留具体失败码。

保存的N06参数经过SDK替身、真实本地资料和原HTTP/队列/交付链，交付甘草/大黄两行、XLSX逐格校验128单元格，外部请求0。**这关闭已暴露宿主误拒的回归，不把首测5/6改成6/6，也未新增真实模型重测。** 修复检查、最终部署与范围见[修复回执](repair.json)。
