## 原因和修改

- 默认入口对未识别请求提前HTTP403返回，未进入会话保存。现保存用户原句及“未执行”回复，返回会话Cookie；相同请求编号不重复写入。
- 澄清和多对象回答没有可供指代使用的对象范围。现将用户提及的对象随HumanMessage持久化；仅使用同一会话最近一轮，明确新对象优先，数量不匹配或无上下文则澄清。对象提及不代表已核验身份。
- “属性／相关信息”保留对象并询问所需字段；不要求用户重新输入药名。“性味”默认查询ETCM的药性与药味，仍逐字段给出处；显式来源约束保持原样。
- 内部提交携带原问句、必要的上一问及对象范围，未新增客户端可伪造的上下文参数。解析用的问句与用户原句分开，原句仍保留在历史及回执中。
- W `requirements_feedback_v1` 在初次理解、必要纠错及语义复核中共享同一会话上下文；仍复用原机械预检、有界资料状态探测和最多3次派发。上下文与请求回执绑定，重复请求使用冻结上下文，不因后来对话变化重复调用。

链路为：任务入口 → 最近会话上下文 → 本地解析或W模型决策 → 原工具检查/反馈及必要复核 → fixed查询或表格交付 → 会话与回执持久化。无后台Cron、Task DAG或新增子Agent。
