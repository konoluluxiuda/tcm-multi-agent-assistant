## 两项失败及处置

**N06：正确的JSON不等于正确目标。** 模型给出select_complete、贮藏和monograph_only=true，却给出空names。宿主的对象覆盖校验拒绝目标，未建任务。API替身回放确认：返回具体澄清、相同请求复用失败提案、只调用替身一次、没有工作区。真实失败未重测，不把离线回放算成功。

**N03：模型说“无齐全记录”，仍提交了错误参数。** 动作链为list→inspect→read→search→deliver。三条注意均缺失，最后却提交三条source_ids（目标为两条、合格集合为空），宿主以too_many_delivery_records拒绝；前一检索也没有推进字段状态，触发连续无进展停止。保留partial检查点，**无已验证文件，判失败**；仅看partial状态会误判任务完成。

同Goal的固定执行三步交付0行表，来源读取计数4；A五步、读取计数8、额外5次模型请求仍未交付。来源读取是既有逻辑计数，不等于SQL语句或全库访问次数。N03阶段计时：G总8.728秒、A总17.642秒，均含同一次1.446秒Goal归属时间；这些是本轮Goal/执行阶段墙钟，不含冻结、页面、客户端排队，也不是生产平均延迟。

离线缩减回放确认：错误交付不会发布文件；显式创建独立的fixed任务后可交付正确0行表，原失败状态未改写。**当前没有自动重试或自动切换模型/驱动**，不能把并行基线称为线上自动降级。用户可修改目标或在表单明确范围；实验native失败后如需fixed结果，应新建独立任务，不切换驱动强行恢复旧检查点。
